## 1. 한 줄 요약

Apple 의 지금 원칙은 "콘텐츠를 앞에 두고, 컨트롤은 그 위에 떠 있는 얇은 층으로 두며, 색 · 장식 · 모달은 아껴 쓴다" 이고, JayDocs 에 가져올 것은 유리 효과 자체가 아니라 **그 규율**(계층 · 명령의 이중 노출 · 되돌리기 우선 · 접근성 설정 존중)이다.

## 2. 개요

### 2.1 HIG 가 무엇인가

HIG(Human Interface Guidelines)는 Apple 플랫폼 앱의 디자인 지침 모음이다. 구성은 Foundations(색 · 타이포 · 재질 · 모션 · 접근성 …), 패턴(툴바 · 사이드바 · 시트 · 알림 …), 플랫폼별 쪽(Designing for macOS 등)이다. 각 쪽 끝에 변경 이력이 있어 언제 바뀌었는지 확인된다. `[HIG:foundations]`

## 3. 디자인 철학

### 3.1 Apple 이 공식으로 말한 것

**① 8개 디자인 원칙** `[HIG:design-principles]` (2026-06 재도입, 원문 영어를 내가 풀었다)

| 원칙 | Apple 의 한 줄 | 쪽의 세부 항목 |
|---|---|---|
| Purpose 목적 | 의미 있는 것을 만든다 | 가치 · 초점 · 새 해법 |
| Agency 주체성 | 사람이 자기 방식대로 하게 한다 | 방해하지 않기 · 탐색의 자유 · **실수에서 복구** |
| Responsibility 책임 | 사람의 이익을 위해 행동한다 | 투명성 · 정보 보호 |
| Familiarity 친숙함 | 사람이 아는 것 위에 쌓는다 | 아는 개념 · **일관된 시각 · 상호작용** · 명확한 피드백 |
| Flexibility 유연성 | 다양한 맥락과 필요에 맞춘다 | 모두를 위한 설계 · 맥락 보존 · **여러 입력 방식** |
| Simplicity 단순함 | 명확하고 직접적으로 | 필요한 것만 · 간결 · **계층 세우기** |
| Craft 완성도 | 세부까지 신경 쓴다 | 품질 · 실험과 반복 · 유지 |
| Delight 기쁨 | 인간적으로 만든다 | 감정 정하기 · 장식과 혼동 금지 |

세션 250 은 "정해진 공식은 없고 한 원칙이 다른 원칙과 충돌할 수 있다" 고 못 박는다. `[W26-250]`

**② Liquid Glass 의 역할** — 재질 쪽의 핵심 문장 두 개(15단어 미만 인용):
- 컨트롤과 내비게이션을 위한 "distinct functional layer" 가 콘텐츠 위에 뜬다. `[HIG:materials]`
- "Don’t use Liquid Glass in the content layer." (콘텐츠 층에는 쓰지 않는다.) 콘텐츠 층의 구분은 표준 재질(blur · vibrancy)로 한다. `[HIG:materials]`

**③ 새 디자인 시스템의 세 축** — 세션 356 이 정리한 구조다. `[W25-356]`
1. **디자인 언어**: 색 · 굵고 왼쪽 정렬된 타이포 · 동심(concentric) 모서리. 하드웨어 곡률과 UI 곡률을 맞춘다.
2. **구조**: 컨트롤은 콘텐츠 위의 별도 기능 층. 장식(배경 · 테두리)으로 무게를 주지 말고 배치와 묶음으로 계층을 표현한다.
3. **연속성**: 장치 · 창 크기가 달라도 같은 해부 구조, 같은 기호, 같은 핵심 상호작용.

**④ 호환성 기준** — 사용자 시스템 설정(투명도 줄이기 · 대비 높이기 · 모션 줄이기)에 재질이 반응한다. `[HIG:materials]`

### 3.2 해석 (Apple 의 말이 아니다)

- **해석**: Apple 의 방향은 "눈에 띄는 효과를 덜어 내고 구조로 말한다" 이다. 툴바에서 배경 · 틴트를 걷고, 알림 · 시트 · 애니메이션을 아끼라는 지침이 모두 같은 방향을 가리킨다.
- **해석**: Liquid Glass 는 렌더링 기술(굴절 · 하이라이트)이라 웹에서 그대로 옮기기 어렵다. 옮길 수 있는 것은 그 밑의 **층 분리 규칙**이다 — 같은 면에 컨트롤과 콘텐츠를 섞지 않는다.
- **해석**: 2026 의 투명도 슬라이더와 "가독성 개선" 은 유리 효과의 비용이 가독성이라는 것을 Apple 도 인정했다는 뜻으로 읽힌다(Apple 의 macOS 페이지는 "뛰어난 가독성" 을 보장한다고만 쓴다). 문서 편집기에서 가독성은 본업이므로 유리보다 **대비**가 먼저다.

## 4. 원칙 · 패턴별 정리

각 항목은 무엇 / Apple 앱에서의 예 / 왜. 단축키 목록은 다루지 않고 "보여 주는 방식" 만 본다.

### 4.1 층 구조: 콘텐츠 위에 뜨는 컨트롤
- **무엇**: 툴바 · 사이드바 · 탭 바는 Liquid Glass 층, 문서 본문은 콘텐츠 층. 콘텐츠 층에는 유리를 쓰지 않는다. 유리 위에 유리를 겹치지 않는다. 사용자 정의 컨트롤에 효과를 줄 때도 가장 중요한 기능 요소에만 쓴다. `[HIG:materials]`, `[W25-219]`
- **예**: Safari 는 컨트롤이 콘텐츠가 아닌 시스템 재질 위에 놓인다. `[W25-356]` 표를 유리로 만들면 다른 요소와 경쟁해 계층이 흐려진다는 예가 세션 219 에 나온다.
- **왜**: 컨트롤과 콘텐츠를 눈으로 갈라 줘야 어디가 편집 대상인지 안다.

### 4.2 툴바
- **무엇**: 내용은 ① 현재 보기의 제목 ② 내비게이션 · 검색 ③ 동작 항목. 항목은 신중히 고르고 넘치면 더보기 메뉴로. 그룹은 **세 개 이하**. 글자 버튼과 기호 버튼을 붙여 두지 않는다. 주 동작(완료 등)은 하나, 오른쪽 끝. `[HIG:toolbars]`
- **맞춤**: 중앙 영역은 사용자가 항목을 추가 · 제거 · 정렬하게 할 수 있다. 왼쪽 끝(사이드바 토글 · 제목 · 문서 메뉴: 복제 · 이름 변경 · 이동 · 내보내기)과 오른쪽 끝은 고정. `[HIG:toolbars]`
- **macOS 규칙**: "모든 툴바 항목은 메뉴 막대에도 명령으로 있어야 한다" — 툴바는 숨기거나 바꿀 수 있기 때문. `[HIG:toolbars]`
- **창 제목**: 창마다 쓸모 있는 제목, 15자 이내, 앱 이름을 제목으로 쓰지 않는다. 메모 앱은 창 하나일 때 제목을 비운다(본문 첫 줄이 맥락이라서). `[HIG:toolbars]`
- **색 · 배경**: 커스텀 툴바 배경과 틴트 컨트롤을 줄이고, 콘텐츠가 화려하면 툴바는 단색을 유지한다. `[HIG:toolbars]` 세션 356 은 "기존에 버튼 무게를 주려 넣은 배경 · 테두리를 걷어 내라" 고 한다.
- **방해 없는 보기**: 툴바를 일시로 숨기는 몰입 모드를 줄 수 있되, 복구 방법을 확실히 둔다. `[HIG:toolbars]`

### 4.3 사이드바
- **무엇**: 앱의 주요 영역으로 이동하는 목록. 계층은 **두 단계까지**, 그보다 깊으면 분할 보기(사이드바 → 목록 → 상세)로. 숨기기를 허용하고 View 메뉴에 Show / Hide Sidebar 를 둔다. 창이 작아지면 자동으로 접기를 고려. 사이드바 **맨 아래에 핵심 정보 · 동작을 두지 않는다**(창이 화면 밖으로 밀리면 가려짐). `[HIG:sidebars]`
- **아이콘 색**: 기본은 앱 강조색을 따른다(사용자가 시스템 강조색을 바꾸면 모든 앱 사이드바가 따르길 기대한다). 고정 색은 의미가 있을 때 드물게(Mail 의 VIP 노랑). 2026-06 에 이 항목이 갱신됐다. `[HIG:sidebars]`
- **macOS 27**: 사이드바가 창 가장자리까지 가고, 선택 항목은 세미볼드 글자, 콘텐츠는 계속 그 뒤로 흐른다. 제목처럼 떠 있는 글자 아래의 스크롤 가장자리 효과는 단단한(hard) 쪽으로 정해진다. `[W26-289]`

### 4.4 분할 보기와 패널
- **무엇**: 각 창에서 현재 선택을 계속 강조해 어디서 상세로 이어지는지 보여 준다. 창 크기 최소 · 최대를 정해 구분선이 사라지지 않게. 숨길 수 있게 하고(Keynote 는 내비게이터와 발표자 노트를 숨긴다) **숨긴 창을 되살리는 방법을 여러 개**(툴바 버튼 · 메뉴 명령 · 단축키) 둔다. 구분선은 1pt 얇은 것. `[HIG:split-views]`
- **인스펙터 · 패널**: 인스펙터는 선택한 항목의 세부를 보이고 선택이 바뀌면 자동으로 갱신된다. 패널은 비모달이고 창 위에 떠서 반복 입력 · 결과 관찰에 쓴다. 단순 조정 컨트롤(슬라이더 · 스테퍼)을 우선. `[HIG:panels]`
- **왜**: 큰 화면은 중첩 단계를 줄이고 모달을 덜 쓰게 해 준다. `[HIG:designing-for-macos]`

### 4.5 창 · 레이아웃 · 동심 모서리
- 큰 화면의 장점을 살려 "더 적은 중첩 단계와 더 적은 모달" 로 정보를 보이되 밀도를 적당히. 창은 크기 변경 · 숨김 · 이동이 자유로워야 한다. `[HIG:designing-for-macos]`
- 중요한 것은 위 · 앞쪽(읽는 순서)에. 정렬과 들여쓰기로 계층을 보이고, 점진적 공개(disclosure)로 복잡도를 줄인다. 창 아래쪽에 컨트롤을 두지 않는다. `[HIG:layout]`
- 동심: 모서리 반경 = 바깥 반경 − 안쪽 여백. 안쪽 요소가 바깥 모서리와 어긋나면 "찡그리거나 벌어진" 느낌이 난다. macOS 의 중 · 소 · 미니 컨트롤은 둥근 사각형, 큰 컨트롤만 캡슐. `[W25-356]`
- **해석**: 반경 규칙은 CSS 변수 한 줄로 흉내 낼 수 있다(`calc(var(--r-outer) - var(--pad))`). 우선순위는 낮다.

### 4.6 문서 기반 앱: 파일 · 저장 · 열기
- **저장**: "사용자가 저장 동작을 하지 않아도 작업이 보존된다고 믿게" 하라 — 편집 중 주기적 자동 저장 + 파일을 닫거나 다른 앱으로 갈 때 저장. 파일 확장자는 기본 숨김, 보고 싶으면 보게. `[HIG:file-management]`
- **열기 · 새로 만들기**: 앱 메뉴와 단축키로 새로 만들기 / 열기를 줄 것. 커스텀 파일 브라우저는 Finder · 파일 앱의 이해를 돕는 방식으로. `[HIG:file-management]`
- **Quick Look**: 앱이 못 여는 파일도 미리 볼 수 있게 하고, 자체 파일 형식은 Finder 용 미리보기 생성기를 고려. `[HIG:file-management]`
- **상태 복원**: 앱을 다시 켜면 이전 위치(스크롤 · 창 상태)까지 돌려 놓는다. `[HIG:launching]` WWDC26 세션 289 도 재시작 뒤 이어서 쓰기를 강조한다.
- **버전(Versions)**: HIG 의 file-management · undo-and-redo 쪽에서 버전 기록에 관한 별도 지침은 **확인 못 함**. (document-based-apps 쪽 주소는 열리지 않았다.)

### 4.7 메뉴 막대 · 발견 가능성
- **전부 보이게**: 메뉴 항목은 상황에 안 맞아도 숨기지 말고 **흐리게(disabled)** 둔다 — 보이는 것이 "이 앱이 할 수 있는 일" 의 학습이므로. 모든 메뉴가 흐리면 메뉴 자체는 열 수 있게. `[HIG:the-menu-bar]`, `[HIG:menus]`
- **앱 고유 명령은 메뉴 막대에**: 다른 곳(툴바 · 문맥 메뉴)에 있어도 메뉴에 꼭 나열. 처음 쓰는 사람이 메뉴 막대부터 찾기 때문. `[HIG:the-menu-bar]`
- **표준 단축키 존중**: 표준 항목의 알려진 단축키를 쓰고, 맞춤 단축키는 **가장 자주 쓰는 앱 고유 명령에만**. 수정키 표기 순서는 Control · Option · Shift · Command. 관련 없는 명령에 표준 단축키 + 수정키를 붙여 새 단축키를 만들지 않는다(Cmd+Shift+Z 를 undo 와 무관한 명령에). `[HIG:keyboards]`
- **단축키를 보여 주는 곳**: 단축키는 **메인 메뉴에 표시**하고 문맥 메뉴에는 표시하지 않는다(문맥 메뉴가 이미 지름길이라 중복). `[HIG:context-menus]` 메뉴 항목의 단축키 글리프 표시 형식 자체를 명시한 문장은 읽은 쪽에서 **확인 못 함**.
- **메뉴 문구**: 동사로 시작, 제목식 대문자, 관사(a, the) 제거, 추가 입력이 필요하면 말줄임표(…), 토글은 현재 상태를 나타내는 라벨(Show/Hide). `[HIG:menus]`
- **메뉴 아이콘**: 가장 흔한 동작 · 핵심 기능에만 쓰고, 같은 그룹은 모두 달거나 모두 안 단다. 알아볼 아이콘이 없으면 달지 않는다. `[HIG:menus]` 이 항목은 2026-06-08 에 갱신됐다고 이력에 적혀 있으나 바뀐 내용은 이력에서 확인 못 함. macOS 27 이 메뉴 아이콘 수를 줄였다는 것은 보도(2차)에서만 확인했다.
- **Full Keyboard Access**: 키보드만으로 창 · 메뉴 · 컨트롤을 쓸 수 있도록. 영역 이동 F5(툴바) · F6(패널) · F4(창) 같은 표준 이동 키가 있다. `[HIG:keyboards]`

### 4.8 문맥 메뉴
- 현재 맥락에서 가장 필요한 항목만, 적게, **앱 전체에서 일관되게**. 항목은 반드시 메인 인터페이스(메뉴 · 툴바)에도 있어야 한다. 사용할 수 없는 항목은 흐리지 말고 **숨긴다**(일반 메뉴와 반대). 하위 메뉴는 한 단계. 가장 자주 쓰는 항목이 포인터 가까이에. 구분선 그룹은 약 3개. `[HIG:context-menus]`

### 4.9 시트 · 팝오버 · 알림(Alert)

| 수단 | 쓰는 때 | 피할 때 |
|---|---|---|
| 시트 | 모달 작업 하나(이름 · 내보내기 옵션). macOS 의 시트는 부모 창을 어둡게 하고, 기본 크기는 합리적으로 | 반복 입력 · 결과 관찰(→ 패널). 시트에서 시트를 여는 것. 복잡하고 긴 흐름 `[HIG:sheets]` |
| 팝오버 | 소량의 정보 · 기능. 밖을 누르면 닫히므로 **닫힐 때 작업을 저장**. 한 번에 하나 | 경고 전달(놓칠 수 있다 → 알림). 크게 만들기 `[HIG:popovers]` |
| 패널 | 문서 곁에 떠서 계속 쓰는 컨트롤 · 정보 | 타이핑이 많은 폼 `[HIG:panels]` |
| 알림 | 사람이 바로 알아야 할 위험 · 파괴 확인 | 정보만 줄 때, 되돌릴 수 있는 흔한 동작(파일 삭제 후 되돌리기), 앱 시작 직후 `[HIG:alerts]` |

- 알림 문구: 직접적이고 중립적인 어조, 제목은 무슨 일이 일어났는지, **버튼은 결과를 뜻하는 한두 단어 동사**("OK" 는 정보성 알림만), 취소 버튼 제목은 항상 "Cancel". 기본 버튼은 오른쪽(또는 위), 취소는 왼쪽(또는 아래). 사용자가 직접 고른 파괴 동작(휴지통 비우기)의 버튼에는 파괴 스타일을 입히지 않는다. `[HIG:alerts]`
- **Return 기본 버튼**: 파괴 동작 알림에는 취소 버튼을 두되 **취소를 기본 버튼으로 하지 않는다**. 읽기를 유도하려면 아예 기본 버튼을 두지 않는다. `[HIG:alerts]` (JayDocs 는 되돌릴 수 없는 확인에서 처음 포커스를 취소에 둔다 — 5절 F 참고)
- **빠른 취소**: Esc 또는 Cmd+. 로 알림을 취소할 수 있게. `[HIG:alerts]`
- 버튼 순서는 시트에서도 일관 — 완료는 항상 Cancel 과 짝, 취소 · 완료 · 뒤로 세 개를 같이 두지 않는다. `[HIG:sheets]` (2026-03 갱신)
- 알림 아이콘: 경고 삼각형은 데이터 손실 같은 정말 필요한 때만. `[HIG:alerts]`

### 4.10 피드백 · 진행 표시
- 피드백은 중요도에 맞는 방식으로: 상태는 수동적으로(보고 싶을 때 보게), 데이터 손실 경고는 능동적으로 끊고 들어간다. `[HIG:feedback]`
- **예상 못 한 · 되돌릴 수 없는** 손실만 경고하고, 삭제처럼 기대한 결과는 경고하지 않는다(Finder 는 파일을 버릴 때 묻지 않는다). 중요한 동작이 끝났다는 확인은 아껴서. 명령을 못 하는 경우엔 이유를 알려 준다. `[HIG:feedback]`
- 진행 표시: 가능하면 **확정(determinate) 진행**, 진행 속도를 고르게, 멈춘 것처럼 보이면 안 되니 계속 움직이게, 중도 취소(및 취소 시 불이익이 있으면 확인)를 준다. 스피너는 작은 영역 · 백그라운드 작업에, 라벨 "loading" 같은 빈말은 피한다. 표시 위치는 일관되게. `[HIG:progress-indicators]`
- 로딩: "가능한 빨리 무언가를 보여 주고", 기다리는 동안 다른 일을 하게 한다. `[HIG:loading]`
- 사용자가 시간 제한 UI(자동으로 사라지는 알림)에 쫓기지 않게 — 인지 접근성 항목이다. `[HIG:accessibility]`
- **빈 상태**: HIG 에 빈 상태 전용 쪽은 **확인 못 함**(주소가 열리지 않았다). 온보딩 쪽의 "상황별 팁이 한 번의 안내 흐름보다 낫다", "탐색을 막지 말고 건너뛰기 쉽게" 가 가장 가깝다. `[HIG:onboarding]`, `[HIG:design-principles]`

### 4.11 되돌리기
- 되돌리기는 **여러 번** 되도록, 무엇이 되돌려질지 예측 가능하게(메뉴 라벨에 "Undo 서식"), 결과를 **보여 준다**(화면 밖 변경이면 그곳으로 이동 · 강조). 되돌리기 · 다시 실행 버튼은 꼭 필요할 때만, 기본은 편집 메뉴 + 표준 단축키. `[HIG:undo-and-redo]`
- 원칙 쪽 문장: 실수 복구가 쉽다고 느낄 때 사람이 더 탐색한다. `[HIG:design-principles]`, `[W26-250]`

### 4.12 색 · 다크 모드 · 대비
- **다크 모드**: 앱 전용 모양 설정은 **두지 않는 것이 원칙**(시스템 설정이 둘이 되어 앱이 고장난 것처럼 보임). 라이트 · 다크 · 자동에서 모두 좋아야 한다. `[HIG:dark-mode]`
- 시맨틱 색(label · separator 등)을 쓰고 색 값을 박지 않는다. **대비 4.5:1 이상**. 흰 배경 이미지는 어두운 배경에서 눈부시니 살짝 낮춘다. 대비 높이기 + 투명도 줄이기를 단독 · 함께 켜고 시험. `[HIG:dark-mode]`, `[HIG:color]`
- **Liquid Glass 의 색**: 유리 자체엔 색이 없고 뒤 콘텐츠를 따른다. 색은 **주 동작의 배경**(강조색 채움)에 아껴서. 여러 컨트롤 배경에 색을 넣지 않는다. 콘텐츠가 화려하면 툴바 라벨은 단색. `[HIG:color]`
- 색만으로 의미를 구분하지 않는다(적록 색약). 같은 색을 다른 뜻으로 쓰지 않는다. `[HIG:color]`
- 시스템 접근성: 큰 글자(최소 200% 확대 가능), 대비 기준(WCAG), 시스템 색 우선. `[HIG:accessibility]`

### 4.13 타이포그래피
- macOS 내장 텍스트 스타일(pt): Large Title 26 / Title1 22 / Title2 17 / Title3 15 / Headline 13 굵게 / **Body 13** / Callout 12 / Subheadline 11 / Footnote 10 / Caption 10. macOS 는 Dynamic Type 을 지원하지 않는다. `[HIG:typography]`
- **가벼운 굵기(Ultralight · Thin · Light)를 피하고** Regular 이상을 쓴다. 서체 종류를 최소로. 굵기 · 크기 · 색으로 계층을 만들고 텍스트 크기가 바뀌어도 계층이 유지되게. `[HIG:typography]`
- WWDC25: 타이포가 "더 굵게, 왼쪽 정렬" 로 갈려 알림 · 온보딩에서 읽기 좋아졌다. `[W25-356]`

### 4.14 아이콘 · SF Symbols
- 인터페이스 아이콘은 **아주 단순화**, 한 앱 안에서 크기 · 선 굵기 · 세부 정도가 일관, **옆의 글자와 굵기를 맞춘다**. 벡터(SVG · PDF). 시각적 정렬을 위해 광학 보정. 보조기술용 대체 텍스트. `[HIG:icons]`
- 툴바는 "의미가 분명한 단순 기호" 를 글자보다 우선하되, *편집* 처럼 기호로 표현이 약한 건 글자로. 테두리 없는 시스템 기호. `[HIG:toolbars]` 세션 356: 연필=주석? 체크=확인? 처럼 읽기 모호하면 글자 라벨이 낫다.
- 같은 뜻의 동작엔 같은 기호를 장치 · 위치가 달라도 반복한다. 가까운 동작(복사의 여러 방식)은 기호를 반복하지 않고 그룹에 한 번만. `[W25-356]`
- SF Symbols: 같은 계열 가중치 · 크기 · 렌더링 모드(단색 · 계층 · 팔레트 · 멀티컬러), 애니메이션은 목적이 있을 때만. `[HIG:sf-symbols]`

### 4.15 모션
- 목적 없는 모션을 넣지 않는다. 자주 하는 UI 상호작용에는 모션을 더하지 않는다. **취소 가능**해야 하고 애니메이션이 끝나기를 기다리게 하지 않는다. 모션 줄이기 설정에서 재질의 탄성 · 강도가 줄어든다. `[HIG:motion]`, `[HIG:materials]`
- macOS 27: 유리 컨트롤이 클릭에 살짝 튕기는 효과가 옵트인으로 생겼다 — "조금만 써라" 는 설명이 붙는다. `[W26-289]`

### 4.16 접근성 · 키보드 · 포커스
- **키보드만으로 쓸 수 있게**: 포커스 이동은 Tab / Shift+Tab, 시스템의 Full Keyboard Access 가 켜지면 모든 컨트롤에 닿아야 한다. `[HIG:keyboards]`, `[HIG:accessibility]`
- **포커스 표시**: 텍스트 · 검색 필드는 포커스 링, 목록 · 컬렉션은 **행 전체 강조**. 사람이 조작하지 않았는데 포커스를 옮기지 않는다. 시스템 포커스 효과를 기본으로. `[HIG:focus-and-selection]`
- **키 뷰 루프**: Tab 순서는 읽는 순서(왼쪽 → 오른쪽, 위 → 아래)여야 한다. `[W26-289]`
- **VoiceOver**: 주요 요소에 대체 라벨, 제목 · 머리글로 구조, 순서 · 묶음 명시, 화면 변화는 알리기(예: 알림이 뜰 때). 장식 이미지는 제외. `[HIG:voiceover]`
- 제스처의 대안을 화면에 두고, 컨트롤 크기와 간격 확보. `[HIG:accessibility]`
- 모션 줄이기 · 대비 높이기 · 투명도 줄이기 를 존중. `[HIG:materials]`

### 4.17 쓰기와 용어
- 동작 이름은 간결하게(단어를 정확히 골라 쓰기). 원칙 쪽도 "간결하라" 를 단순함의 항목으로 둔다. 창을 가리키는 말은 "window" 로 통일. `[HIG:design-principles]`, `[HIG:windows]`

## 5. JayDocs 에 가져올 만한 것

현재 UI(HANDOFF · SHORTCUTS · 소스에서 확인): 왼쪽 파일 트리 + 오른쪽 탭 · 분할(flexlayout), 창 막대, 명령 팔레트(항목 오른쪽에 단축키 `hint`), `F1` 도움말, 앱 대화상자(`DialogHost`: 취소가 처음 포커스, `Enter`/`Esc`, 오류는 `role="alert"`), 오른쪽 아래 알림(`role="region"`, 실패는 남는다), 훑어보기 창 · 패널, 하이브리드 목차, 다크/라이트(`prefers-color-scheme` 로 시작 + `Ctrl+Alt+D`), 포커스 링 `2px solid var(--accent)`, 레이아웃 복원. CSS 에 `transition` · `animation` · `prefers-reduced-motion` · `prefers-contrast` · `forced-colors` 규칙은 **없다**(grep 으로 확인).

| **C. 접근성 설정 존중: 모션 줄이기 · 대비 높이기 · 강제 색상** (4.12 · 4.15 · 4.16) | 높음 | 전역 CSS(`styles.css`), 훑어보기 · 대화상자 · flexlayout 탭 | `@media (prefers-reduced-motion)`, `(prefers-contrast: more)`, `(forced-colors: active)` 블록 추가. 지금 모션이 거의 없으니 **새 모션을 넣기 전에** 먼저 | 색 변수만 바꾸는 구조(`:root[data-theme]`)라 대비 높이기 변수 세트를 한 벌 더 두면 된다 |

| **E. 되돌리기 우선, 확인창은 되돌릴 수 없는 것에만** (4.9 · 4.11) | 높음 | 대화상자 · 알림 · 그리드 열 조작("바로 실행 + 되돌리기 알림" 이미 도입) | 파일 삭제 · 닫기(저장 안 함) · UTF-8 덮어쓰기만 확인창. 파일 삭제 되돌리기는 FSA 에 휴지통이 없어 불가 → 확인창 유지가 맞다 | 새 파괴 동작을 넣을 때의 체크리스트로 쓴다 |
| **F. 알림 버튼 문구 규칙** — 결과를 뜻하는 동사("삭제" · "저장 안 함"), "확인" 은 정보성만, 취소는 항상 같은 말 (4.9) | 중간 | `askConfirm` · `askText` 호출 26곳 문구 | 호출부 문구 점검(코드 변경 거의 없음) | 한국어는 "확인/취소" 가 관용이라 **동사 + 취소** 로만 바꿔도 충분. HIG 는 "취소를 기본 버튼으로 하지 말라" 지만 JayDocs 는 되돌릴 수 없는 확인에서 취소에 처음 포커스를 둔다 — 웹 대화상자의 안전한 관행이라 **유지**하길 권한다(해석) |
| **G. 사이드바 · 패널 숨김 복구 경로 여러 개** (4.3 · 4.4) | 중간 | 파일 트리(`Ctrl+B`), 훑어보기 패널(`Ctrl+Alt+M`), 목차(`Ctrl+Alt+T`) | 숨긴 패널마다 **창 막대 버튼 + 팔레트 명령 + 단축키** 3중 확인. 이미 대부분 있음 | 목차는 창 600px 미만에서 자동으로 숨는다 — 숨은 이유를 막대에 한 줄로 알리면 좋다 |
| **H. 빈 상태 · 처음 화면에 "다음에 할 수 있는 일"** (4.10) | 중간 | 문서 없는 빈 창(`empty-pane`), 시작 화면 | 새 문서 · 파일 열기 · 팔레트 · F1 안내를 한 줄씩. 상황별 팁(온보딩 쪽) 형태 | HIG 에 빈 상태 전용 쪽은 확인 못 함 — 온보딩 지침을 근거로 |
| **I. 진행 표시: 확정 진행 + 취소** (4.10) | 중간 | 큰 폴더 가져오기, 폴더 훑어보기 썸네일 격자, 서비스 워커 업데이트(`UpdateButton`) | `<progress value max>` 또는 얇은 막대, 취소 가능하면 버튼 | 0 에서 한참 멈추면 고장으로 보인다 — 확정 불가하면 "n개 읽음" 같은 숫자 카운터로 |
| **J. 파일 저장: 자동 저장 옵션** (4.6) | 중간 (Jay 가 정할 일) | 저장 / dirty 배지 / `Ctrl+S` | 옵션(기본 꺼짐)으로 N 초 뒤 저장 + 창 숨김 · 닫기 때 저장 | **포맷 계약(바뀐 셀의 행만 diff)** 과 git 작업 흐름상 의도하지 않은 저장이 diff 에 들어간다. 한글 IME 조합 중 저장 금지. 외부 변경 충돌 배너와의 상호작용 확인 |
| **K. 상태 복원** (4.6) | 낮음(이미 구현) | 레이아웃 · 열 너비 · 보기 모드 · 트리 펼침 저장 | 스크롤 위치 · 커서 위치까지 복원 여부 점검 | HANDOFF 에 스크롤 복원은 언급 없음 — 확인 못 함 |
| **L. 툴바 장식 줄이기 · 색은 주 동작에만** (4.2 · 4.12) | 중간 | 창 막대 · 상단 막대 · 그리드 막대 버튼 | 버튼 배경 · 테두리 기본 투명, hover 에서만 `--hover`. 강조색 채움은 한 화면에 하나 | 문서 영역과 막대를 **구분하는 얇은 선 / 아주 약한 그림자 하나** 는 유지 |
| **M. 기호 아이콘 통일** (4.14) | 낮음 | 📂 ☀ ? ↻ · ↶ ↷ ＋ 같은 유니코드 기호(HANDOFF 의 "글자로 통일할지" 숙제) | 인라인 SVG 한 세트(예: 스트로크 1.5px, 같은 크기). 이모지는 OS 마다 모양 · 색이 다르다 | 외부 아이콘 라이브러리를 새로 들일지는 번들 크기와 같이 판단. 글자 라벨이 더 나은 동작은 글자 유지 |
| **N. 포커스: 목록은 행 전체 강조, 입력은 링** (4.16) | 낮음(대부분 지켜짐) | 트리 · 팔레트 · 그리드(`outline: 2px`) | 이미 `.tree-body:focus-visible` 가 inset 강조. 점검만 | 포커스를 사람이 조작하기 전에 옮기지 않는다 — `runCommand('focusEditor')` 호출 위치 점검 |
| **O. 스크롤 가장자리 효과 (스크롤 가장자리의 부드러운 블러)** (4.1) | 낮음 | 하이브리드 / 미리보기 위의 창 막대, 훑어보기 창 위 · 아래 | 막대 아래 8~12px 그라디언트 마스크 · `position: sticky` 로 스크롤이 시작된 때만 | 성능 · 한글 조합 입력 영역을 가리지 않게. 필수 아님 |
| **P. 투명도 · 질감 사용자 설정 (macOS 27 슬라이더)** | 낮음 | 설정 | **하지 않는다**(6절 첫 줄 참고). 유리를 안 쓰므로 조절할 대상이 없다. 대신 C 의 대비 높이기만 | — |

**해석 — 위 표에서 내가 고른 상위 3개**: ① C+D(접근성 설정 + 대비 점검: 비용이 작고 지금 0 인 영역), ② A+B(명령 · 단축키 노출 규칙: JayDocs 의 정체성인 "모든 작업이 키보드로" 와 정확히 맞고, 점검이 곧 작업이라 비용이 낮음), ③ E+F(되돌리기 우선 · 확인창 문구: 데이터를 잃는 사고를 막는 쪽이라 가치가 큼).

## 6. 맞지 않아 가져오지 않을 것과 이유

| 항목 | 이유 |
|---|---|
| Liquid Glass 의 굴절 · 하이라이트 · 클리어 변형 · 유리 탄성 모션 | 웹은 `backdrop-filter` 로 흐림 정도만 흉내 내며, 굴절 렌더링은 없다. 흐림 + 뒤 콘텐츠 비침은 **글을 읽는 편집기**에 가독성 비용이 크다. Apple 도 클리어는 "사진 · 영상 위" 로 한정한다 `[HIG:materials]`. JayDocs 의 층은 문서 · 표라서 해당 없음 |
| 메뉴 막대(File · Edit · View…) | 웹 PWA 에 시스템 메뉴 막대가 없고, Windows 에는 관행도 다르다. 대신 **명령 팔레트가 그 역할**(HIG 의 "전부 노출 · 흐려도 보이게" 는 팔레트에 비활성 항목을 그대로 두는 것으로 대응) |
| 앱 전용 모양 설정 금지 (4.12) | Windows · Edge PWA 사용자는 OS 다크 모드와 별개로 앱에서 토글하는 관행이 흔하고 JayDocs 에 `Ctrl+Alt+D` 가 이미 있다. **시작은 OS 설정을 따르고 토글은 유지**(지금 방식)가 맞다 |
| macOS 키 표기(⌘ ⌥ ⇧ ⌃) · 표준 단축키 표를 그대로 | Windows 사용자 다수라 Ctrl · Alt 표기. `SHORTCUTS.md` 가 "Mac 에서는 Ctrl 을 ⌘ 로 읽는다" 로 이미 처리. 또 브라우저가 가로채는 조합(Ctrl+W/T/N/Tab/숫자)은 쓰지 않는 것이 CLAUDE.md 규칙 |
| Cmd+. 로 알림 취소 · Cmd+, 설정 같은 Mac 관행 | Windows 관행은 `Esc` 만. `Esc` 는 이미 대화상자 취소에 쓰인다 |
| 문서 창을 여러 OS 창으로 분리 | PWA 하나의 창 안에서 탭 · 분할을 쓰는 설계(flexlayout)와 다르다. HIG 의 "새 창에서 보기" 는 분할(`Ctrl+\`)로 대응되어 있다 |
| 창 아래쪽 정보 금지 (4.3 · 4.5) | 웹 앱 창은 OS 창과 달리 화면 밖으로 밀리는 일이 드물다. 상태 표시줄을 두려면 둘 수 있다. 다만 **핵심 동작은 아래에 두지 않는다** 는 정도로만 |
| Dynamic Type | macOS 가 지원하지 않는 기능이고(`[HIG:typography]`) 웹에서는 브라우저 확대 · `rem` 단위로 대응한다. 훑어보기 창의 `Ctrl+= / Ctrl+-` 가 이미 별도 배율을 가진다 |
| 터치 입력 확장(2026-10 macOS 지침) | 사용자는 키보드 · 마우스. 터치가 필요해지면 다시 본다 |
| SF Symbols 자체 | Apple 의 사용 허가는 Apple 플랫폼용 앱으로 제한된다(라이선스 문서를 직접 확인하지는 못했다 — 확인 못 함). 웹에서는 직접 만든 SVG 나 라이선스가 확인된 외부 세트를 쓴다 |
| 가운데 영역 툴바 사용자 맞춤(drag 로 항목 추가 · 제거) | 항목 수가 적고, 팔레트가 이미 "전부 있는 곳" 이다. 개편 규모에 비해 이득이 작다 |
