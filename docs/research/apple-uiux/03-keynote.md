# 03. Apple Keynote — UI/UX 조사

조사일 2026-11-22. 대상은 Keynote for Mac(주), iPad(참고). Apple 공식 지원 문서(Keynote 16.0 사용 설명서) · 뉴스룸 · MacRumors 를 읽었다. 확인 못 한 것은 '확인 못 함' 으로 적었다.

## 1. 한 줄 요약

Keynote 는 **슬라이드 한 벌을 보기만 바꿔 가며(네비게이터 · 라이트 테이블 · 개요 · 슬라이드만) 다루고, 오른쪽 인스펙터 하나가 선택에 따라 내용을 바꾸는** 구조다. JayDocs 에 가져올 것은 화려함이 아니라 이 **구조 감각** — 같은 문서의 여러 보기를 한 메뉴로 고르기 · 개요를 직접 편집하기 · 객체 목록 같은 블록 목록이다.

## 2. 개요

- **무엇**: Apple 의 발표 자료 편집기. Mac · iPad · iPhone · 웹(iCloud). 슬라이드 = 레이아웃(placeholder)을 채운 한 장, 테마 = 레이아웃 묶음 + 글꼴 · 색.
- **누구를 위한 것**: 디자인 지식이 없어도 보기 좋은 발표를 만들려는 일반 사용자. 파워 유저에게는 정렬 안내선 · 객체 목록 · 레이아웃 편집을 준다.
- **2026 기준 변화** (Apple 뉴스룸 · MacRumors)
  - 2026-01-28 Apple Creator Studio 출시와 함께 Keynote 에 Liquid Glass 디자인 · 편집 가능한 도형 · HDR 이 들어갔다(전체 사용자). 구독자 전용: 전용 테마, Content Hub(사진 · 그래픽), AI 이미지 생성, 개요로 슬라이드 초안 만들기(베타), 발표자 노트 자동 작성(베타), 레이아웃 정리(베타) [4][5].
  - 2026-06-30 새 전환 효과 · 빌드(전체 사용자로 분류됨), Pixelmator Pro 연동(구독 여부는 글에서 불분명) [6].
  - 2026-09-29 구독자용 새 템플릿 · 테마, **지능형 슬라이드 생성**(발표 내용에 맞는 이미지를 자동으로 만든다) [7]. 같은 달 소식이지만 MacRumors 는 일부가 11월에 순차 배포라고 했다(간접 확인, 지금 모두 배포됐는지는 확인 못 함).
  - 버전: MacRumors 는 Creator Studio 판이 15.1, 옛 앱은 14.5(기능 동결)라고 했다. 지원 문서는 16.0 이다. **현재 Mac 버전은 확인 못 함** — 서로 어긋난다.
  - 구독 모델이 새 기능을 가른다는 점은 JayDocs(무료 · 로컬)와 무관하다. UI 구조는 구독 여부와 상관없이 같다.

## 3. 디자인 철학

**Apple 이 공식적으로 말한 것**

- Liquid Glass 는 "새 재료" 이고, 컨트롤은 앱 콘텐츠 위의 "별개의 기능 층" 이다. 툴바 · 사이드바 · 탐색을 다시 설계했고 목적은 콘텐츠에 더 집중하게 하는 것이다. macOS 사이드바는 뒤의 콘텐츠를 굴절시켜 맥락을 유지한다 [8]. (WWDC25 보도자료. Keynote 를 직접 언급하지는 않는다.)
- 사이드바 지침(HIG): 앱의 큰 영역이나 최상위 콘텐츠 모음(폴더 · 재생목록) 사이를 오가는 곳이다. 2025 년 갱신에서 사이드바가 콘텐츠 위에 떠 있는 유리판이 되었고, 그 아래로 콘텐츠를 펼치되 글자 · 컨트롤은 그 위 층에 둬 왜곡을 막으라고 했다(검색 요약 기준) [11].
- 툴바는 자주 쓰는 명령 · 컨트롤 · 탐색 · 검색을 가까이 두는 곳이다. 탭 막대는 탐색용, 현재 보기에 작용하는 컨트롤은 툴바로 구분한다(HIG) [11][12].
- Keynote 사용 설명서는 "슬라이드 레이아웃을 고르고 placeholder 를 바꿔 쓴다" 는 방식으로 레이아웃 편집을 설명한다 [3-b]. 철학이라기보다 사용 방식 설명이다.
- **Keynote 자체의 디자인 철학을 Apple 이 한 글로 밝힌 자료는 찾지 못했다(확인 못 함).** HIG 본문 페이지는 자동 수집이 제목만 돌려줘(JS 렌더링) 읽지 못했고, 위 HIG 내용은 검색 요약에서 얻었다.

**해석 (내 해석이다)**

- 한 문서 · 여러 보기: 데이터(슬라이드)는 하나이고 네비게이터 · 라이트 테이블 · 개요 · 슬라이드만은 같은 데이터를 보는 창만 다르다. 사용자는 '모드' 가 아니라 '시점' 을 고른다. 보기를 바꿔도 선택과 편집 내용이 유지된다.
- 점진적 공개: 기본 화면은 네비게이터 + 슬라이드 + 툴바 + 인스펙터뿐이고, 객체 목록 · 정렬 안내선 · 눈금자 · 발표자 노트는 View 메뉴에 숨어 있다. 초보는 건드리지 않고, 필요한 사람은 찾아 쓴다.
- 인스펙터는 하나, 내용은 선택이 정한다: 사용자가 '어느 패널을 열지' 가 아니라 '무엇을 골랐는지' 만 정하면 된다.
- 툴바는 기본이 '아이콘만' 이고 마우스를 올리면 설명이 뜬다. 사용자가 항목 · 표시 방식을 바꿀 수 있다 [3-d].

## 4. 핵심 UI/UX 요소

### 4.1 슬라이드 네비게이터 + 보기 전환 [1]

- **무엇**: 왼쪽에 슬라이드 썸네일 열, 오른쪽에 선택한 슬라이드. 기본 보기.
- **어떻게**: 툴바의 **보기(View) 메뉴 버튼** 에서 고른다. 네비게이터 · 슬라이드만(네비게이터를 숨긴다, ↑↓ 로 이동) · 라이트 테이블 · 개요. 클릭 선택, Shift 클릭 여러 개, 썸네일을 끌어 순서 변경, 오른쪽으로 끌어 들여쓰면 슬라이드를 묶는다. 같은 보기 메뉴에 객체 목록 · 발표자 노트 · 눈금자 · 레이아웃 편집이 함께 있다.
- **왜 좋은가**: 한 곳에서 '지금 무엇을 볼지' 를 모두 고른다. 순서 변경은 어느 보기에서도 같은 끌기이고, 놓을 자리에 선이 뜬다 [2].

### 4.2 라이트 테이블 [1]

- **무엇**: 슬라이드 전체를 큰 격자로 본다. 구조 · 흐름 점검용.
- **어떻게**: 끌어서 순서 변경, 더블클릭하면 그 슬라이드를 편집하며 이전 보기로 돌아간다. 창 오른쪽 아래 **슬라이더로 썸네일 크기**를 바꾼다. "건너뛴 슬라이드 숨기기" 체크 — 숨기지 않으면 흐리게 보인다.
- **왜 좋은가**: '훑어보기 → 고르기 → 들어가기' 가 한 보기 안에서 끝난다. 크기 슬라이더가 항상 화면에 있어 조절이 발견된다.

### 4.3 개요(Outline) 보기 [1]

- **무엇**: 왼쪽에 슬라이드 제목 + 글머리 텍스트만 나열하고, 가운데는 선택한 슬라이드, 오른쪽은 인스펙터.
- **어떻게**: 제목을 치고 Return · Tab 으로 하위 글머리를 만든다. 글머리를 끌면 순서 · 들여쓰기가 바뀌고, 슬라이드 아이콘을 끌면 슬라이드가 옮겨 간다. 글꼴 크기는 설정에서, 인쇄는 인쇄 창의 '개요' 로.
- **왜 좋은가**: 글을 쓰는 사람은 구조만 먼저 잡고, 그 구조 편집이 곧 문서 편집이다. 개요는 읽는 창이 아니라 **편집하는 창**이다. (구독자는 개요에서 슬라이드를 생성하는 기능도 있다 — 4.10.)

### 4.4 객체 목록 [1][2-c]

- **무엇**: 선택한 슬라이드 위 객체를 쌓인 순서(레이어)대로 나열한 패널. 네비게이터 · 슬라이드만에서만 켠다. 보기 메뉴 > '객체 목록 보기'.
- **어떻게**: 끌어서 앞 · 뒤 순서를 바꾸고, 다른 슬라이드로 끌어 옮긴다. 그룹 · 해제, 잠금(자물쇠 아이콘), 이름 바꾸기(더블클릭), 하단의 **필터(종류별)와 이름 검색**, 키보드 이동(방향키 · Return · Tab). 다른 객체에 가려졌거나 그룹 안의 객체를 고르는 데 쓴다. 작은 썸네일 옵션이 설정에 있다.
- **왜 좋은가**: 캔버스에서 마우스로 잡기 어려운 대상을 이름과 종류로 고른다. 파워 유저용 보조 보기를 기본 화면에서 빼 두었다.

### 4.5 인스펙터 — Format · Animate · Document [3-c]

- **무엇**: 창 오른쪽의 사이드바 하나. 툴바 오른쪽의 라디오 버튼 세 개로 Format · Animate · Document 를 고른다. 같은 버튼을 다시 누르면 접힌다. 메뉴 보기 > 인스펙터 로도 켠다.
- **어떻게**: Format 은 **선택한 것(텍스트 · 도형 · 이미지 · 영상…)에 따라 내용이 바뀐다.** 슬라이드 레이아웃 버튼, 스타일 탭이 있다. Animate 는 객체 애니메이션 · 전환. Document 는 문서 전체(테마 · 사운드트랙 등). 세 버튼은 툴바 커스터마이즈에서도 묶여 움직이고 떼지 못한다.
- **확인 못 함**: 하위 탭의 정확한 이름(Text · Arrange · Transition 등)은 가져온 본문에서 확인하지 못했다. 이미지 설명에는 Style · Movie · Arrange, Build In · Action · Build Out 이 보인다.
- **왜 좋은가**: 편집 대상과 속성 패널 사이의 관계가 항상 같다. '속성은 오른쪽'.

### 4.6 정렬 안내선 · 스마트 가이드 [2-d]

- **무엇**: 드래그 중 다른 객체와 정렬되거나 간격이 같을 때 자동으로 나타나는 선(스마트 가이드), 그리고 사용자가 눈금자에서 끌어내 두는 **고정 안내선**.
- **어떻게**: 설정 > 눈금자에서 네 가지를 켠다 — 객체 중심, 객체 가장자리, 상대 크기(높이 등이 같을 때), 상대 간격(세 개 이상 등간격). 고정 안내선은 슬라이드마다 따로 저장되고 색은 설정에서 바꾼다. 보기 > 안내선 > 숨기기 / 현재 슬라이드의 안내선 모두 지우기. 툴바에 안내선 토글 버튼을 넣을 수 있다.
- **왜 좋은가**: 자유 배치 캔버스에서 정확도를 잡아 주는 장치. 자동(맥락 때문에 임시로 나타남)과 수동(내가 둔 것이 남음)을 구분했다.

### 4.7 테마 선택기와 슬라이드 레이아웃(마스터) [3-a][3-b]

- **테마 선택기**: 새 문서를 만들 때 뜬다. 왼쪽에 분류 목록, 오른쪽에 썸네일을 분류별 줄로. 더블클릭으로 선택. 일부 테마는 고르는 순간 내려받는다(오프라인에서는 그림이 거칠 수 있다). 기본 테마를 설정에서 정할 수 있다(`옵션` + 새로 만들기로 일회성 선택기). 구독자는 선택기에서 테마를 고르고 **생성** 을 눌러 개요로 슬라이드를 만든다.
- **테마 바꾸기**: 파일 > 테마 변경. '내 스타일 변경 유지' 체크를 끄면 새 테마가 덮어쓴다. 공유 중인 문서는 못 바꾼다.
- **마스터**: Apple 용어는 '마스터' 가 아니라 **슬라이드 레이아웃**이다(TOC 에 '슬라이드 마스터' 페이지는 없다 — 별도 마스터 편집기는 확인 못 함). 보기 메뉴 > '슬라이드 레이아웃 편집' 으로 들어가면 네비게이터에 레이아웃 목록이 뜬다. 레이아웃에 올린 객체는 편집 불가 배경이 되고, 텍스트 · 미디어 **placeholder 로 정의**한 것만 슬라이드에서 채운다. placeholder 에 **태그**를 붙여 두면 레이아웃을 바꿀 때 같은 태그의 자리로 내용이 옮겨 간다. 아래에 파란 막대와 '완료' 가 떠 지금이 레이아웃 편집 모드임을 알린다.
- **왜 좋은가**: 내용과 틀을 분리해 일관성을 유지한다. 모드 진입을 눈에 띄게 알린다.

### 4.8 발표자 노트 · 리허설 [1][9]

- **노트**: 보기 메뉴 > '발표자 노트 보기' 로 슬라이드 아래에 노트 칸이 뜬다. 노트가 있는 슬라이드는 네비게이터 썸네일 오른쪽 위에 **작은 네모 표시**가 붙는다. 인쇄에 포함할 수 있다.
- **리허설**: 재생 > 리허설 슬라이드쇼. 현재 · 다음 슬라이드, 노트, (15.2 문서 기준) 타이머와 진행 추적이 있는 **발표자 화면**이 뜬다. 외부 모니터가 없어도 연습한다. 화면 오른쪽 위 모서리로 포인터를 옮겨 요소를 끌어 배치하거나 자동 배치, 노트 글꼴 크기 · 색 반전을 정한다. `X` 로 발표자 화면과 슬라이드를 오가고 `?` 로 단축키 목록이 열린다.
- **왜 좋은가**: 같은 문서의 **발표용 시점**을 별도 편집 없이 제공한다. 상황에 맞는 단축키 도움말이 그 화면 안에서 열린다.

### 4.9 툴바 · 창 구성 [3-d]

- 기본은 아이콘만이고 올려 두면 설명이 뜬다. 보기 > 툴바 사용자화에서 항목을 끌어 추가 · 제거 · 순서 변경하고, '아이콘과 텍스트 / 아이콘만 / 텍스트만' 을 고른다. 기본 세트로 되돌리는 칸이 있다. 툴바 전체를 숨길 수도 있다.
- 알려진 버튼: 슬라이드 추가(레이아웃 선택) · 재생 · 보기 메뉴 · 확대/축소 팝업 · 표 · 차트 · 텍스트 · 도형 · 미디어 삽입 · 인스펙터 세 버튼. 전체 목록은 문서에 없어 확인 못 함.
- 확대: 툴바 팝업으로 10%~400% 또는 '슬라이드에 맞춤'. 자동 가운데 맞춤을 끄면 슬라이드 밖으로 작업 공간이 넓어진다.

### 4.10 지능형 기능 (2026) [4][5][7]

- 개요 → 슬라이드 초안, 발표자 노트 자동 작성(Apple silicon · macOS 26 이상 필요), 이미지 생성 · 편집, 슬라이드 생성에 맞춘 이미지. 모두 구독 · 클라우드 계정과 묶여 있다. UI 로는 툴바의 **생성** 버튼과 테마 선택기의 **생성** 버튼이다. 정확한 동작은 구독 문서를 보지 못해 확인 못 함.

### 4.11 문서 관리

- **Mac**: 별도의 문서 관리자 화면은 사용 설명서 TOC 에서 찾지 못했다. 파일 > 열기 대화상자(iCloud Drive 등 위치 목록), 파일 > 최근 항목(최대 10개), Dock · 앱 위에 파일 끌어놓기, 탭 창 옵션이 전부다. 열 수 없는 파일은 흐리게 표시한다 [9].
- **iPad**: 문서 관리자(썸네일 · 폴더 · 검색)는 **확인 못 함** — iPad 설명서 TOC 만 읽었다.

## 6. 맞지 않아 가져오지 않을 것과 이유

- **Liquid Glass 의 반투명 유리 · 떠 있는 사이드바**: 문서 편집기는 글이 콘텐츠다. 유리 뒤 흐림은 글자 대비를 떨어뜨리고 `backdrop-filter` 는 Windows 에서 비용이 든다. Apple 자체도 글자 · 컨트롤을 위층에 두라고 한다 [11]. (해석) 이 효과는 macOS 시스템 재료에 기대는 것이라 웹에서는 모사만 된다.
- **자유 배치 캔버스 도구: 스마트 가이드 · 고정 안내선 · 눈금자 · 객체 목록의 레이어**: JayDocs 문서는 선형 텍스트와 표라 객체 좌표가 없다. 4.4 는 '레이어' 가 아니라 '블록 목록' 으로만 가져온다.
- **테마 · 슬라이드 레이아웃 편집기(마스터)**: 문서가 서식 틀을 갖지 않고 마크다운 + 앱 테마가 서식을 정한다. 포맷 계약(DESIGN §2)과도 충돌한다.
- **애니메이션 · 전환 · 재생 · 리허설 · 발표자 화면**: 발표 도구가 아니다. 쪽 나눔 · 인쇄 · PDF 도 하지 않는다는 Jay 방침이다.
- **지능형 슬라이드 생성 · 이미지 생성 · 노트 자동 작성**: 서버 없음 · 로컬 앱 원칙에 맞지 않고, Apple 도 구독 · Apple silicon · 클라우드에 묶었다. 개요 → 문서 뼈대를 만드는 정도는 템플릿으로 충분하다.
- **구독으로 갈리는 기능 구조 · Content Hub**: 무관.
- **Mac 의 `Cmd` 중심 조작 · 메뉴바**: Windows 사용자 다수라 `Ctrl` 기준 + 앱 안 팔레트가 맞다(이미 그렇다). 메뉴 항목에 단축키를 옆에 적는 관습만 가져온다(5절 '보기 메뉴').
- **문서 관리자**: Mac 에 전용 관리자가 없고(확인한 범위), iPad 것은 확인 못 했다. JayDocs 의 파일 트리 · 폴더 썸네일 격자가 이미 더 풍부하다.
