## 1. 결론

**Apple 에서 가져올 것은 유리 효과가 아니라 규율이다.** 콘텐츠를 앞에 두고, 컨트롤은 선택에 따라 그 곁에 나타나고, 모든 명령은 한 곳(메뉴 — JayDocs 에서는 팔레트)에 단축키와 함께 있고, 실수는 확인창보다 되돌리기로 푼다.

**권고: 첫 묶음은 "위치와 상태를 보이게" 한다.** 경로 막대 + 문서 상태 줄(TSV 는 셀 정보 · 선택 요약) + 창 제목의 수정됨 표시 + 마지막 저장으로 되돌리기. 이유:
1. 여러 리포트가 따로 같은 결론에 닿았다(경로 막대는 Xcode · Finder, 상태 표시는 TextEdit · Numbers · Pages).
2. 모두 표시이거나 이미 있는 동작의 노출이라 포맷 계약(DESIGN §2)을 건드리지 않는다.
3. 구현이 작고, 개편의 뼈대(창 위 · 아래 막대 자리)를 먼저 정해 두면 뒤의 기능이 들어갈 자리가 생긴다.

## 2. 도구들에 공통인 디자인 철학

Apple 이 직접 말한 것과 리포트들의 해석을 묶었다. 괄호는 근거가 된 리포트 번호.

1. **콘텐츠가 주인, 컨트롤은 별도의 층** (09, 01, 02). Liquid Glass 는 컨트롤 · 내비게이션을 콘텐츠 위의 "별개의 기능 층" 으로 두고, HIG 는 콘텐츠 층에는 유리를 쓰지 말라고 한다. 글이 많은 면은 불투명이 원칙이다. Apple 은 2026 macOS 27 에서 대비를 높이고 투명도 슬라이더를 넣었다 — 리포트 09 는 이를 유리 효과의 비용이 가독성이라는 것을 Apple 도 인정한 것으로 해석한다.
2. **한 문서 · 여러 보기** (03, 08, 01, 04). Keynote 는 네비게이터 · 라이트 테이블 · 개요 · 슬라이드만을 한 "보기" 메뉴에서 고르고, Finder 는 한 폴더를 아이콘 · 목록 · 열 · 갤러리로 본다. 사용자는 모드가 아니라 시점을 고르고, 보기를 바꿔도 선택이 남는다.
3. **선택이 곧 문맥** (01, 03, 06). Pages · Keynote 는 오른쪽 인스펙터 하나가 선택에 따라 내용을 바꾸고, Freeform 은 고른 대상 곁에 그 종류의 도구만 띄운다. 사용자는 도구를 찾지 않고 대상을 고른다.
4. **점진적 공개** (02, 03, 01). Numbers 의 열 메뉴 화살표 · 행 추가 손잡이는 호버 · 선택 때만 나온다. 객체 목록 · 안내선 · 보이지 않는 문자는 보기 메뉴 안에 둔다. 평소 화면은 비운다.
5. **찾아가는 비용을 줄인다** (07, 08, 04). Xcode 는 모든 목록 · 메뉴에서 글자를 치면 거르고, 경로 막대의 각 단계가 이웃으로 가는 메뉴다. 메모 · Finder 는 조건을 저장한 "스마트 폴더" 로 반복 검색을 클릭 한 번으로 만든다.
6. **열지 않고 본다** (08, 06). Quick Look 은 같은 키로 열고 닫아 확인 비용을 0 에 가깝게 만든다. Freeform 은 파일을 카드로 놓고 Space 로 훑게 한다. JayDocs 의 트리 훑어보기가 이미 이 계열이다.
7. **실수는 되돌리기로 푼다** (09, 05, 01, 04). HIG 원칙 "주체성" 의 항목이 실수에서의 복구다. 버전 탐색 · "마지막 저장으로 되돌리기" · 30일 휴지통 · 이름 있는 되돌리기("Undo 서식"). 확인창은 예상 못 한 · 되돌릴 수 없는 손실에만 쓴다.
8. **명령은 한 곳에 모두, 단축키를 옆에** (09, 03, 04, 07). macOS 는 툴바 · 문맥 메뉴에 있는 명령도 메뉴 막대에 반드시 두고, 상황에 맞지 않으면 숨기지 않고 흐리게 둔다. 단축키는 메인 메뉴에 표시하고 문맥 메뉴에는 표시하지 않는다. 발견은 메뉴로, 숙련은 키로.

## 3. JayDocs 에 가져올 것 — 통합 우선순위

"근거" 는 그 요소를 권한 리포트다. 여러 리포트가 독립적으로 권한 것일수록 위에 두었다. 구현 방법 · 주의는 근거 리포트의 5절에 있다.

### 3.1 먼저 — 작고, 포맷 계약과 무관하고, 효과가 큼

| 요소 | 무엇을 | JayDocs 화면 | 근거 |
|---|---|---|---|
| **경로 막대** | `@별칭 › 폴더 › 파일 › 제목` 한 줄. 각 단계를 누르면 같은 단계의 이웃 목록이 뜨고, 치면 거른다. 제목 단계는 `lib/md/outline.ts`, TSV 는 열 또는 `_Field` 블록 | 탭과 편집기 사이(또는 창 아래) | 07, 08 |
| **문서 상태 줄** | 모든 형식에 `UTF-8 · LF · BOM` 표시, 누르면 관련 명령. TSV 는 왼쪽에 활성 셀의 열 이름 · 타입 · Field 설명 · 검증 오류, 오른쪽에 선택 범위의 합 · 평균 · 최소 · 최대 · 개수 | 문서 창 아래 | 05, 02 |
| **창 제목의 수정됨 표시** | 저장 안 한 문서가 있으면 `● 파일명 — JayDocs`. 지금 `document.title` 은 폴더 이름만 쓴다(확인: `src/App.tsx:141`) | 브라우저 탭 · 설치한 PWA 창 제목 | 05 |
| **마지막 저장 상태로 되돌리기** | 팔레트 명령. 디스크의 원본으로 교체하되 `Ctrl+Z` 한 번으로 되돌릴 수 있게 | 팔레트 · 창 막대 | 05, 01 |
| **명령 노출 점검 + 버튼 툴팁 단축키 병기** | 창 막대 · 그리드 막대 · 문맥 메뉴의 모든 동작이 팔레트 명령과 단축키 표에 있는지 확인한다(`＋위` `＋끝` `＋왼쪽` 은 HANDOFF 숙제). 툴팁은 `이름 (Ctrl+…)` 하나로, `shortcuts-table.mjs` 에서 생성 | 전체 | 09, 01, 03, 08, 07 |
| **접근성 설정 존중 · 대비** | `prefers-reduced-motion` · `prefers-contrast: more` · `forced-colors` 규칙 추가(지금 하나도 없음 — 확인). 라이트 `--muted: #6e7781` 은 흰 바탕에서 4.5:1 경계라 조금 어둡게 | `styles.css` | 09 |
| **빈 폴더 · 빈 화면 안내** | 폴더 격자가 비었을 때 한 줄 안내 + "새 문서" 버튼(읽기 전용이면 이유) | 폴더 훑어보기 · 빈 창 | 08, 09 |
| **훑어보기 창의 "열기" · "분할로 열기" 버튼** | Enter 로 이미 되는 동작을 눈에 보이게 | `QuickLook.tsx` 머리 | 08 |
| **Mermaid 확대 · 이동 · 맞춤** | 지금은 SVG 를 그대로 넣을 뿐 확대가 없다. 포커스된 블록에서만 휠 확대 · 끌어 이동 · "맞춤" 버튼 | 미리보기 · 하이브리드 | 06 |

## 4. 리포트끼리 엇갈린 것 — 권고

| 쟁점 | 엇갈림 | 권고 |
|---|---|---|
| **버전 기록** | 01 은 저장마다 IndexedDB 스냅숏 + 타임라인을 "높음" 으로, 02 · 05 는 "git 이 맡는다, 하지 않는다" | **타임라인은 하지 않고 기준점 두 개("마지막 저장" · "연 시점")만 넣는다.** 문서 폴더가 git 작업 트리라 이력은 git 이 맡고 있고, 앱 안 사본은 용량 · 동기화 · 혼동(어느 것이 원본인가) 비용이 든다 |
| **자동 저장** | 09 는 "옵션(기본 꺼짐)" 을 제안, 나머지는 모두 하지 않음 | **하지 않는다.** 저장이 diff · 커밋의 경계이고 외부 변경 충돌 배너와 부딪힌다. 비정상 종료 대비 임시 보관(디스크는 건드리지 않음, 05)은 별도 결정 |
| **오른쪽 인스펙터 vs 아래 막대** | 01 · 03 은 오른쪽 문맥 인스펙터, 02 는 그리드 아래 막대 | **아래 막대부터.** 가로 공간을 쓰지 않고 키보드 사용자에게 바로 보인다. 인스펙터는 막대로 모자랄 때 다시 본다 |
| **되돌릴 수 없는 확인의 첫 포커스** | HIG 는 "취소를 기본 버튼으로 하지 말라", JayDocs 는 처음 포커스가 취소 | **유지.** 웹 대화상자에서 Enter 연타로 지우는 사고를 막는 쪽이 낫다 |
| **앱 안 다크/라이트 토글** | HIG 는 앱 전용 모양 설정을 두지 말라 | **유지.** 시작은 OS 설정을 따르고(`prefers-color-scheme`) `Ctrl+Alt+D` 토글은 Windows PWA 관행에 맞다 |

## 5. 가져오지 않을 것 (공통)

- **Liquid Glass 의 반투명 · 굴절 효과** — 글을 읽는 면의 대비를 떨어뜨리고, 웹 `backdrop-filter` 는 흐림만 흉내 내며 Windows 에서 비용이 든다. 층을 나누는 규칙(얇은 경계선 · 불투명한 면)만 가져온다.
- **자유 배치 캔버스 · 안내선 · 도형 · 테마/마스터 · 애니메이션** — JayDocs 문서는 순서 있는 텍스트와 표다. 다이어그램은 Mermaid 가 맡는다.
- **iCloud · 공유 · 협업 · 잠금 · 휴지통** — 서버가 없다. FSA 의 삭제는 영구라 삭제 확인창이 맞다.
- **AI 기능(Creator Studio 구독, Magic Fill, 슬라이드 생성)** — 서버 · 외부 호출 없는 로컬 앱이다.
- **메뉴 막대 · ⌘ 표기 · 트랙패드 제스처** — 팔레트가 메뉴 막대 역할을 한다. 표기는 Ctrl · Alt.
- **첫 줄이 제목 · 파일 이름 없는 모델(메모)** — 파일 이름이 정체성이다(트리 · 링크 · git).
- **스마트 따옴표 · 자동 치환 · 서식 있는 텍스트 전환** — 원문을 바꿔 포맷 계약을 깬다.
- **SF Symbols** — 사용 허가가 Apple 플랫폼용이라 웹에 쓰지 않는다(허가 문서는 확인 못 함).

## 6. 이미 Apple 수준이거나 앞선 것

리포트들이 "이미 있다" 로 짚은 것: 트리 Space 훑어보기와 폴더 썸네일 격자(Quick Look), 팔레트의 단축키 표시, 최근 순 파일 검색, 줄 끝 · BOM 보존과 표시(TextEdit 은 줄 끝을 아예 못 보여 준다), 하이브리드 모드(메모는 Markdown 기호를 볼 수 없다), flexlayout 탭 · 분할(TextEdit 의 창 탭보다 강하다), 되돌릴 수 있는 그리드 열 조작("바로 실행 + 알림의 되돌리기" — HIG 의 되돌리기 우선과 같다).

## 7. 단축키 개편 때 볼 점

목록은 Jay 가 정한다. 조사에서 나온 것만 적는다.

- 3절의 새 기능 중 키가 필요한 것: 보기 모드 4종 각각으로 바로 가기, 경로 막대 열기, 뒤로 · 앞으로(브라우저의 `Alt+←/→` 와 겹침), 제목 접기(CM6 기본은 `Ctrl+Shift+[` · `]`), 집중 모드, 마지막 저장으로 되돌리기, 절 옮기기(`Alt+↑/↓` 는 이미 마크다운의 줄 옮기기).
- HIG 의 단축키 규칙(09): 사용자 지정 단축키는 가장 자주 쓰는 앱 고유 명령에만 준다. 표준 단축키에 수정키를 붙여 관련 없는 명령을 만들지 않는다. 수정키 표기 순서는 Control · Option · Shift · Command — JayDocs 의 `Ctrl+Alt+Shift` 순서와 같다.
- 보여 주는 곳: 메인 목록(F1 · 팔레트)과 버튼 툴팁에는 늘 보이고, 문맥 메뉴에는 보이지 않는다(HIG). 지금 트리 문맥 메뉴가 어떻게 하는지 맞춰 볼 것.
- 숨긴 패널을 되살리는 길은 버튼 · 팔레트 · 단축키 세 가지 모두 둔다(HIG 분할 보기).

## 8. 조사의 한계

- HIG 본문은 스크립트로 그려지는 페이지라 일부 리포트(01 · 02 · 03 · 05)는 검색 요약으로만 읽었다. 04 · 08 · 09 는 `developer.apple.com/tutorials/data/design/human-interface-guidelines/<쪽>.json` 경로로 본문을 직접 읽었다 — HIG 관련 판단은 09 를 우선한다.
- Apple 지원 문서가 macOS 27 판으로 내려와 Tahoe 26 과의 차이는 확인하지 못했다(08).
- Pages for Mac 의 Screen View 는 2026-09-29 Apple 뉴스룸 발표에 나오지만, 메뉴 경로와 동작은 01 에서 확인 못 했다.
- Keynote · Numbers 의 현재 Mac 버전 번호는 자료끼리 어긋난다(설명서 16.0, 보도 15.1).
- JayDocs 코드에 대한 리포트 주장 중 이 종합에서 직접 확인한 것은 `document.title`, `--muted` 값, 접근성 미디어 쿼리가 없다는 것, 마크다운만 줄바꿈이 켜진다는 것이다. 나머지("트리 클릭이 새 탭을 여는가" 등)는 구현 전에 확인한다.
