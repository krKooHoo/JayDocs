# 08 · Apple Finder 와 Quick Look — 문서를 찾고 훑어보는 UI/UX

조사일 2026-11-22. 대상은 macOS 의 Finder 와 Quick Look. 단축키 목록 조사는 하지 않았다(Jay 가 따로 정리).

## 1. 한 줄 요약

Finder 는 "같은 폴더를 네 가지 모습(아이콘 · 목록 · 열 · 갤러리)으로 보고, 열지 않고 미리 보고(Quick Look · 미리보기 열), 이름 대신 태그 · 저장된 검색으로 묶는" 도구다. JayDocs 는 Quick Look(Space 훑어보기 · 폴더 격자)을 이미 본떴으므로, 아직 없는 것 중 **훑어보기 창의 파일 넘겨 보기 · 열 보기식 빠른 탐색 · 경로 막대 · 태그/저장된 검색**이 다음 후보다.

## 2. 개요

- **무엇**: Finder 는 macOS 의 파일 관리자, Quick Look 은 파일을 열지 않고 크게 미리 보는 기능이다. Apple 은 Quick Look 을 "거의 모든 종류의 파일을 열지 않고 전체 크기로 미리 보기" 로 설명한다. Finder 창뿐 아니라 데스크탑 · 메일 · 메시지 등에서도 같은 Space 로 동작한다.
- **누구를 위한 것**: 파일이 많은 일반 사용자 전반. 사진 · PDF · 영상 · 문서가 섞인 폴더에서 "무엇이 어디 있는지" 를 빨리 파악하는 것이 목적이다.
- **최근 변화**
  - macOS 26 Tahoe: 폴더에 태그를 달면 폴더 아이콘에 색이 입혀지고 기호 · 이모지를 붙일 수 있다(Six Colors 평: 태그가 달린 파일 자체나 사이드바에는 색이 안 번지는 등 덜 다듬어짐). 열 보기에 "열 너비를 가장 긴 파일명에 맞춤" 옵션이 생겼다(Daring Fireball 평: 그전부터 숨은 설정으로 있던 것). Liquid Glass 로 툴바 · 사이드바가 콘텐츠 위에 떠 있고, Gruber 는 투명도 때문에 읽기 어렵다고 비판했다.
  - 이번에 받은 Apple 지원 문서는 서버가 **macOS 27 판**으로 내려준 것이었다(버전 선택기 기본값). 본문에 Tahoe 26 전용 표기는 없었고, 26 판과의 차이는 **확인 못 함**.
  - HIG 사이드바 페이지가 2026-06-08 에 "아이콘 색 · 적응형 사이드바 스타일" 로 갱신됐다(변경 기록 기준).

## 3. 디자인 철학

Apple 이 문서에서 직접 한 말(출처 5절)과 내 해석을 나눈다.

**Apple 이 말한 것**
- 사이드바는 앱의 최상위 모음 사이를 오가는 도구이고, 내용을 사용자가 바꿀 수 있게 하라. 계층은 두 단계까지만 보이고 그보다 깊으면 분할 보기(내용 목록)로 가라. (HIG 사이드바)
- 사이드바는 기본으로 숨기지 말고(발견 가능성), 보이기/숨기기 버튼이나 View 메뉴 명령을 두라. 창이 좁아지면 자동으로 접는 것도 고려하라. (HIG 사이드바)
- 사이드바 아이콘은 기본적으로 앱 강조색을 따른다. 고정 색은 강조용으로 아껴 쓴다. (HIG 사이드바)
- 사이드바 밑에는 중요한 정보·동작을 두지 마라 — 창을 옮기다 아래가 가려지기 쉽다. (HIG 사이드바)
- 분할 보기에서는 각 창에서 지금 선택한 항목을 계속 강조하라. (HIG 분할 보기)
- 경로 막대(path control)는 선택한 항목의 파일 시스템 경로를 보여 주고, 도구 막대나 상태 막대가 아니라 **창 본문**에 둔다. 길면 가운데 항목을 숨긴다. (HIG 경로 컨트롤)
- 열 보기(column view)는 첫 열에 루트를 두고, 자식이 없는 항목은 미리보기나 파일 정보를 보여 주고, 열 너비를 사용자가 바꿀 수 있게 하라. (HIG 열 보기)
- 끌어다 놓기: 끌기를 시작한 뒤 약 3pt 뒤에 반투명 드래그 이미지를 띄우고, 받는 곳은 **받을 수 있을 때만** 강조한다(아니면 아무 표시 없이, 또는 "안 됨" 기호). 놓기가 실패하면 원래 자리로 되돌아가는 애니메이션. 여러 개를 끌 때는 개수 배지를 단다. (HIG 끌어다 놓기)
- 스프링 로딩: 끌고 있는 내용을 버튼 · 분할 컨트롤 위에 머물게 하면 활성화된다는 설명이 HIG 에 있다(예: Calendar 툴바). Finder 폴더가 열리는 동작과 지연 시간에 대한 Apple 문서는 **확인 못 함**.
- 파일 관리: 자동 저장하고, 확장자는 기본으로 숨기되 보이게 할 수 있게 하라. 직접 만든 파일 형식에는 Quick Look 미리보기 생성기를 제공하라. (HIG 파일 관리)
- 검색: 현재 검색 범위를 분명히 보이고(자리 표시 글, 범위 막대, 제목), 최근 검색 · 제안을 보이되 지울 수 있게 하라. (HIG 검색)

**해석** (Apple 문서에 이렇게 쓰여 있지 않다)
- 한 폴더를 네 가지 보기로 바꿔 보는 설계는 "찾는 이유가 사람마다·순간마다 다르다" 는 전제다. 이름으로 찾는 일은 목록, 모양으로 찾는 일은 아이콘 · 갤러리, 위치를 따라가는 일은 열 보기.
- Quick Look 의 핵심은 **되돌릴 필요가 없는 확인**이다. 파일을 열면 앱이 뜨고 창이 늘고 닫아야 하지만, Space 는 눌렀다 떼는 것만으로 끝나 "열기" 의 비용을 없앤다. 그 안의 마크업 · 회전 · 다듬기는 "열기 앱으로 갈 만큼은 아닌 작은 손질" 을 같은 자리에서 끝내게 하려는 것으로 읽힌다.
- 태그 · 폴더 색 · 스택은 폴더 위치(트리)와 별개의 **두 번째 분류 축**이다. 트리 하나로 못 푸는 분류를 파일을 옮기지 않고 해결한다.

## 4. 핵심 UI/UX 요소

### 4.1 보기 네 가지
- **무엇**: 툴바 보기 버튼(창이 좁으면 팝업 메뉴)으로 아이콘 · 목록 · 열 · 갤러리를 고른다.
- **어떻게**
  - 아이콘: 격자. 아이콘 크기 · 격자 간격을 View Options 로 조정.
  - 목록: 한 줄에 한 항목, 이름 외 열(날짜 등). 열 머리를 눌러 정렬, 머리를 Control-클릭해 열을 켜고 끈다. 최근 날짜 표시 방식 옵션.
  - 열: 폴더가 가로로 이어지는 열로 펼쳐지고, 마지막 열에 선택 항목의 썸네일 · 정보가 뜬다. 열 너비 조절.
  - 갤러리: 위에 큰 미리보기, 아래에 썸네일 한 줄. 좌우 스와이프 · 방향키로 넘긴다. 파일 이름을 숨기는 옵션.
  - 폴더마다 보기를 기억시키는 "Always open in", 하위 폴더까지 적용하는 "Browse in", 같은 보기의 모든 폴더 기본값으로 삼는 "Use as Defaults"(열 보기는 불가).
- **왜 좋은가**: 사용자가 "지금 무엇을 찾는지" 에 맞춰 같은 폴더의 표현을 바꾼다. 폴더별로 기억하므로 사진 폴더는 갤러리, 문서 폴더는 목록으로 굳는다.
- 맞는 상황(해석): 사진 · 디자인 시안 = 아이콘/갤러리, 이름 · 날짜로 정렬 = 목록, 깊은 폴더를 따라 들어가기 = 열, 한 장씩 훑으며 고르기 = 갤러리.

### 4.2 사이드바 (즐겨찾기 · 위치 · 태그)
- **무엇**: 창 왼쪽의 바로가기 목록. 구역(즐겨찾기, iCloud, 위치, 태그)으로 나뉘고, 구역 제목을 눌러 접는다.
- **어떻게**: 폴더 · 디스크를 끌어 넣으면 즐겨찾기에 별칭이 생기고(원본은 안 움직인다), 파일 · 앱은 Command-드래그. 밖으로 끌어내면 제거. 어떤 항목을 보일지는 Finder 설정. 열기/저장 대화상자에도 같은 사이드바가 뜬다. 보기 메뉴로 숨기고, 구분선을 끌어 너비 조절. 태그를 누르면 그 태그의 모든 파일이 모인다.
- **왜 좋은가**: 트리를 매번 펼치지 않고 자주 가는 곳으로 한 번에 간다. 사용자가 구성한다. 열기/저장 창과 공유해 "어디서나 같은 지도" 가 된다.

### 4.3 경로 막대 · 상태 막대
- **무엇**: 경로 막대는 창 아래쪽에 선택 항목의 경로를 `폴더 › 폴더 › 파일` 로 보여 준다(보기 메뉴의 Show Path Bar). 상태 막대는 항목 수 · 남은 용량.
- **어떻게**: 경로의 각 단계가 아이콘 + 이름이고, 단계를 눌러(더블클릭) 그 폴더로 이동, 항목을 끌어다 단계에 놓아 옮길 수도 있다(편집 가능일 때, HIG). 툴바를 숨기면 상태 막대가 위로 올라간다(지원 문서).
- **왜 좋은가**: 열 보기 없이도 "지금 어디인가" 를 항상 보이고 한 번에 위로 올라간다. 세부 동작(더블클릭 이동 등)은 HIG 가 아니라 일반 사용 경험이며, 지원 문서에서는 경로 막대 설명을 **확인 못 함**.

### 4.4 미리보기 열 (열 · 갤러리 보기의 오른쪽)
- **무엇**: 선택한 항목의 작은 미리보기 + 메타데이터 목록(만든 날짜, 사진이면 카메라 · 렌즈 등).
- **어떻게**: View > Show Preview, 어떤 정보를 보일지는 Show Preview Options(파일 형식마다 항목이 다르다). 그 안의 "빠른 동작" 체크 시 이미지 회전 · PDF 만들기 같은 버튼이 뜬다(지원 문서가 든 예시. 마크업 · 다듬기가 같은 자리에 있는지는 해당 페이지에서 **확인 못 함**). 경계선을 끌어 너비 조절, 끝까지 밀면 닫힌다.
- **왜 좋은가**: 파일을 고르는 동안 "맞는 파일인가" 를 같은 창에서 판단하고, 흔한 손질은 앱 열기 없이 끝낸다.

### 4.5 Quick Look (Space)
- **무엇**: 선택 항목을 열지 않고 별도 창에 크게 띄우는 미리보기. 같은 키로 닫는다.
- **어떻게** (Apple 지원 문서)
  - 여러 항목을 고르고 Space 면 마지막에 고른 것이 먼저 뜬다. 창 왼쪽 위 화살표나 ← → 로 넘겨 본다.
  - 인덱스 시트(격자 보기)로 한꺼번에 본다. 전체 화면에서는 재생 버튼이 슬라이드쇼.
  - 창은 모서리를 끌어 크기를 바꾸고, 전체 화면 버튼으로 키운다. 이미지는 확대/축소 명령이 있다.
  - 그 안에서 바로: 왼쪽 회전(Option 이면 오른쪽), 마크업, 오디오/영상 다듬기(노란 핸들, 완료할 때 원본 교체 또는 새 파일), 공유, "다음 앱으로 열기" 버튼. 이미지는 컨텍스트 메뉴 "Copy Subject"(피사체만 복사).
  - HDR · Live Photo 같은 형식별 동작도 지원 문서에 있다.
  - 창 크기를 기억하는지는 지원 문서에서 **확인 못 함**(JayDocs 쪽은 SK17 에서 기억하기로 이미 정했다).
- **왜 좋은가**: "열기" 와 "닫기" 가 한 키라서 열어 보고 아니면 닫는 비용이 0 에 가깝다. 그 자리에서 작은 손질까지 끝내므로 앱 전환이 줄어든다.

### 4.6 태그 · 색
- **무엇**: 파일에 붙이는 색 + 이름 표. Tahoe 부터 태그를 단 폴더는 아이콘이 그 색으로 칠해지고(설정의 "태그에 따라 폴더 색 입히기"), 기호 · 이모지도 붙일 수 있다.
- **어떻게**: 컨텍스트 메뉴의 색 줄 / 툴바 태그 버튼 / 저장 대화상자 태그 칸. 즐겨 쓰는 태그 7개까지 단축 메뉴(Control+1~7)로. 사이드바 · 검색 칸에 색 이름을 쳐서 찾고, Group by / Sort by / 목록의 Tags 열로 묶는다.
- **왜 좋은가**: 폴더 위치와 별개로 "상태 · 중요도" 를 한눈에 보인다. 이름을 안 바꾸고 분류한다.

### 4.7 스택 (데스크탑)
- **무엇**: 데스크탑 파일을 종류 · 날짜 · 태그로 묶어 한 더미로 접는 기능. 보기 메뉴 "Use Stacks".
- **어떻게**: 더미를 눌러 펼치고, 트랙패드 두 손가락 스와이프로 더미 안을 훑는다. 새로 저장한 파일이 알맞은 더미로 자동 들어간다.
- **왜 좋은가**: 정리하지 않아도 정리된 모양. 단, 이것은 데스크탑 기능이고 Finder 창에서는 "그룹 기준" 이 같은 역할이다(해석).

### 4.8 이름 바꾸기 (인라인)
- **무엇**: 항목을 고르고 Return(또는 이름 클릭)으로 그 자리에서 편집한다.
- **어떻게**: 이름 칸이 편집 상태로 바뀌고 Return 으로 확정. 콜론은 못 쓰고 마침표로 시작할 수 없다. 확장자 변경은 권장하지 않는다는 안내. 여러 개를 고르고 Rename 하면 "Finder 항목 이름 바꾸기" 창에서 바꾸기 · 덧붙이기 · 형식(번호 · 날짜)으로 일괄 변경.
- **왜 좋은가**: 대화상자 없이 목록 위에서 끝나고, 일괄 규칙도 같은 기능이다.

### 4.9 끌어다 놓기 피드백 · 스프링 로드 폴더
- **무엇**: 끄는 동안 반투명 이미지 · 개수 배지, 받을 수 있는 폴더만 강조, 폴더 위에 머물면 열린다(스프링 로드).
- **어떻게**: 위 3절 HIG 참고. 일반 끌기는 이동, Option-끌기는 복사, Option-Command-끌기는 별칭(지원 문서). 스프링 로드 폴더의 지연 시간 · 설정 이름은 Apple 문서에서 **확인 못 함**(Finder 의 접근성/설정 항목으로 알려져 있으나 이번 조사에서 근거를 못 찾았다).
- **왜 좋은가**: 깊은 폴더로 옮길 때 "놓고 → 열고 → 다시 끌기" 를 한 번의 끌기로 줄인다.

### 4.10 검색 · 저장된 검색(스마트 폴더)
- **무엇**: Finder 검색 칸에 단어를 치면 제안(이름 · 종류 · 태그 색 등)이 뜨고, 고르면 **토큰**(검색 칩)이 되어 조건을 쌓는다. 조건을 "저장" 하면 스마트 폴더가 된다.
- **어떻게**: File > New Smart Folder → 검색 칸에 문구 · 날짜 등을 치고 제안에서 고른다 → 아래 + 로 규칙 추가(속성 목록은 "기타" 아래) → 저장 시 이름 · 위치 · 사이드바에 넣기. 저장한 폴더는 파일이 바뀌면 목록이 자동 갱신된다. 조건은 동작 버튼의 "검색 조건 보기" 로 다시 편집한다.
- Finder 검색 범위 막대(이 Mac / 현재 폴더) 와 Spotlight 토큰 문법은 이번에 열린 지원 문서에 **없어 확인 못 함**. Spotlight 는 Command-Space 로 열고 Space 로 미리보고 Tab 으로 빠른 동작을 연다는 것만 확인했다.
- **왜 좋은가**: 한 번 만든 조건이 "폴더" 로 남아 반복 검색이 사이드바 클릭 한 번이 된다. 토큰은 문법을 외우지 않고 눌러서 조건을 만들게 한다(해석).

### 4.11 빈 폴더 표시
- Finder 는 빈 폴더에서 창을 그냥 비워 둔다(안내 문구 없음). Apple 지원 문서에서 이에 대한 설명은 **확인 못 함**이므로 이 항목은 사용 경험이다(해석: 폴더 격자 같은 곳에서는 "비어 있음" 표시를 우리가 넣는 편이 낫다).

### 4.12 단축키를 보이는 방식 (참고)
- 메뉴 항목 오른쪽에 키 조합을 같이 적고, 툴바 · 컨텍스트 메뉴로도 같은 동작에 닿게 한다(일반 관행, 이번에 Apple 문서에서 인용한 것은 아님). 발견은 메뉴로, 숙련은 키로.

## 5. JayDocs 에 가져올 만한 것

JayDocs 현재(HANDOFF · SHORTCUTS 기준): 트리에서 Space 로 훑어보기 창(파일 렌더 + 폴더 썸네일 격자, ↑↓ 로 넘겨 보기, 크기 · 배율 기억, Enter 로 열기), 폴더 격자 안 방향키 · Enter · Backspace, 파일 검색(Ctrl+P), 팔레트, 훑어보기 패널(미니맵), 하이브리드 목차. **이미 있음** = Space 미리보기, 포커스를 트리에 두고 넘겨 보기, 창 크기 · 확대 기억, 폴더 썸네일 격자, F2 이름 바꾸기, 앱 대화상자 · 알림.
**아직 없음** = 보기 전환(트리는 목록 하나), 경로 막대, 태그 · 색, 저장된 검색, 훑어보기 창의 "열기" 버튼 · 전체 화면 · 격자(인덱스 시트), 폴더 격자 위의 보기 전환, 일괄 이름 바꾸기, 끌어다 옮기기 + 스프링 로드(밖에서 가져오기 드롭은 있음).

## 6. 맞지 않아 가져오지 않을 것

- **마크업 · 회전 · 영상 다듬기**: 이미지 · 영상을 고치는 기능이다. JayDocs 는 md · 표 · 텍스트 편집기이며 훑어보기 창은 읽기 전용 렌더를 본뜬 것이라 일부러 편집을 넣지 않는다(해석). 이미지 회전 정도는 필요가 생기면 그때.
- **갤러리 보기(큰 한 장 + 썸네일 줄)**: 문서는 이미지처럼 "모양" 으로 구분되지 않는다. 폴더 격자 + 훑어보기 창이 같은 역할을 한다.
- **아이콘 보기의 아이콘 크기 · 격자 간격 조절, 파일 형식별 아이콘 미리보기**: 이미 폴더 격자의 카드 크기 배율(SK17)이 있다.
- **데스크탑 스택**: 데스크탑이 없다. 같은 목적(종류 · 날짜별 묶기)은 폴더 격자의 "그룹 기준" 으로 충분하고 지금은 필요가 없다.
- **트랙패드 스와이프 중심 조작**: Windows 사용자가 많은 PWA 이고, 키보드 우선 원칙(CLAUDE.md)에 안 맞다.
- **Liquid Glass 식 투명 사이드바**: Gruber · Snell 모두 가독성 문제를 지적했고, 텍스트가 많은 작업 도구에는 불투명 배경이 맞다(해석). Apple 도 일반(regular) 변형을 글이 많은 사이드바에 권한다(HIG 재료).
- **태그 색의 폴더 아이콘 입히기**: Snell 평으로는 사이드바 · Dock 에 안 이어지는 덜 끝난 기능. 위의 "태그" 가 낮음인 이유와 같다.
- **Apple Intelligence 파일 이름 제안**: macOS 27 전용이라고 문서에 적혀 있고, 서버 없는 로컬 앱이라 맞지 않는다.
