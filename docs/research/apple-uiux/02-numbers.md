# 02. Apple Numbers — UI/UX 조사 (Mac 중심)

조사일 2026-11-22. 범위는 Numbers for Mac(사용 설명서 16.0 기준)이고 iPad 는 따로 보지 않았다(확인 못 함). 단축키 목록은 조사하지 않았다.
표기: **[공식]** 은 Apple 문서에 있는 사실, **[해석]** 은 이 조사자의 해석이다. 확인 못 한 것은 "확인 못 함" 으로 적었다.

## 1. 한 줄 요약

Numbers 는 "격자 한 장" 이 아니라 시트(캔버스) 위에 표 · 차트 · 글상자를 놓는 모델이고, 표 선택 / 셀 선택 / 범위 선택을 서로 다른 손잡이로 구분하며, 선택하면 아래쪽에서 합계 · 평균을 바로 보여 주고, 셀의 "데이터 형식" 이 곧 입력 컨트롤(체크박스 · 팝업 · 슬라이더)이 되는 도구다 — JayDocs 에는 캔버스 모델이 아니라 **하단 선택 요약 · 열 머리 메뉴 · 가장자리 추가 손잡이 · 셀 정보 막대** 가 맞는다.

## 2. 개요

- **무엇 · 누구를 위한 것**: Apple 의 스프레드시트 앱. Mac · iPad · iPhone · 웹(iCloud). 사용 설명서의 예시는 예산 · 좌석표 · 업무 목록 같은 일상 문서다. **[해석]** 그래서 데이터 모델링보다 "보기 좋은 표 문서" 쪽 도구로 읽힌다(Apple 이 대상 사용자를 정의한 문장은 확인 못 함).
- **구조 [공식]**: 스프레드시트 하나에 여러 시트(= 탭)가 있고, 시트에 표 · 차트 등을 담는다. 설명서는 시트를 "캔버스" 라고 정의하지는 않는다 — "표를 자유롭게 놓는 캔버스" 는 설명서의 정의가 아니라 화면에서 읽은 구조다(**[해석]**).
- **2026 기준 변화** (What's new on Mac 기준):
  - 15.1 (2026-01): Apple Creator Studio 편입, **Liquid Glass** 인터페이스(무료), 구독자 기능으로 **Magic Fill**. Mac 에서는 구독판이 별도 앱(15.1)으로 나뉘었고 옛 앱은 14.5 로 멈췄다(MacRumors).
  - 15.3: **시트 숨기기 · 보이기, 시트 탭 색**(모두에게). 정확한 출시일은 확인 못 함(15.1 다음 버전).
  - 15.4: 삼각 · 통계 · 논리 함수 추가, Siri 질문.
  - 16.0 (2026, macOS 26 이상): 구독자용 **지능형 어시스턴트(베타, macOS 27 이상, 미국 영어만)** — 설명으로 표 · 차트 생성, 외부 AI 에이전트용 MCP.
  - 표 · 셀 · 수식 편집기 · 사이드바의 UI 자체가 15.x 에서 바뀌었다는 항목은 찾지 못함(확인 못 함).

## 3. 디자인 철학

Apple 이 Numbers 의 철학을 직접 서술한 문장은 이번 조사에서 읽을 수 있는 공식 페이지에서 **확인 못 함**(apple.com/numbers 는 지원 허브로 넘어가고, developer.apple.com 의 HIG 표 · 재질 페이지는 본문이 읽히지 않았다). 아래는 읽은 것과 해석이다.

- **Liquid Glass [공식]**: Apple 보도자료(2025-06)는 컨트롤을 앱 위에 놓인 별도의 기능 층으로 두고, 내용에 자리를 내주며 필요할 때 모양이 바뀐다고 설명한다. 탭 바 · 사이드바도 같은 방식으로 다시 디자인했다. → https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/
- **내용과 컨트롤의 층 분리 [해석]**: 그 원칙을 Numbers 에 대면, 표 안(내용)은 불투명한 흰 격자로 두고 도구 막대 · 사이드바 같은 조작 층만 유리처럼 만든다. 표 위에 유리를 얹지 않는다.
- **"데이터 형식" 이 곧 컨트롤 [공식 사실 + 해석]**: 셀 형식에서 체크박스 · 별점 · 슬라이더 · 스테퍼 · 팝업 메뉴를 고르면 그 셀이 그 컨트롤이 된다. 값은 1/0 · 숫자 · 텍스트로 그대로 남는다. 해석: 형식을 한 번 정하면 입력 방식이 따라오고, 값 자체는 평범하다.
- **선택에 따라 나타나는 손잡이 [공식 사실 + 해석]**: 행 번호 · 열 글자는 표를 선택해야 나타나고, 열 글자에 마우스를 올려야 화살표 메뉴가 나타난다. 해석: 평소 화면은 비워 두고 맥락이 생길 때만 도구를 보인다.
- **계산 결과를 앞에 [공식 사실 + 해석]**: 범위를 고르면 합 · 평균 · 최소 · 최대를 창 아래에 보이고, 수식 셀을 고르면 같은 자리에 결과 · 참조 값 · 오류를 보인다("Smart Cell View"). 해석: 수식을 넣기 전에 결과를 먼저 본다.
- **자동 저장 + 버전 [공식]**: 첫 저장 뒤 자동 저장, 저장마다 버전, 타임라인으로 훑어보고 복원.

## 4. 핵심 UI/UX 요소

### 4.1 캔버스 위의 표 (시트 · 표 · 표 핸들)
- **무엇**: 시트 위에 표를 여럿 놓고, 표는 이동 · 크기 조절 · 잠금이 된다.
- **동작 [공식]**: 표 왼쪽 위 **표 핸들**을 누르면 표 선택(가장자리에 흰 네모 3개). 핸들을 끌면 이동, 흰 네모를 끌면 행 · 열 수가 아니라 표 크기. 표를 선택하면 열 글자 · 행 번호가 나타난다. Arrange > Lock 으로 표를 잠글 수 있다(편집 · 이동 · 삭제 불가). 개별 셀 크기는 바꿀 수 없다.
- **왜 좋은가 [해석]**: 데이터 표와 설명 · 차트를 한 쪽에 같이 배치할 수 있어 "문서" 로서 읽힌다. 대신 수천 행 데이터 관리에는 불리하다(무한 격자가 아니라서).

### 4.2 시트 탭 (2026: 숨기기 · 색)
- **동작 [공식]**: 탭에 마우스를 올리면 오른쪽에 화살표가 나타나고, 거기서 이름 바꾸기(더블클릭) · 복제 · 삭제 · **Hide Sheet** · Unhide(전체 또는 하나) · 색을 고른다. 색은 빈 곳 선택 + Format 버튼으로도 정한다. 같은 메뉴에서 그 시트의 특정 표 · 차트로 바로 이동할 수 있다. 공유한 문서에서도 받는 사람은 숨긴 시트에 접근할 수 있다(숨김은 보안이 아니다).
- 새 시트 추가 · 순서 바꾸기의 정확한 동작은 이번에 읽은 페이지에서 확인 못 함(그림 설명에 "tab bar for adding a new sheet and reorganizing" 이 있을 뿐).
- **왜 좋은가 [해석]**: 시트가 많아질 때 색으로 묶고 안 쓰는 것은 숨겨 탭 줄을 줄인다. 호버할 때만 메뉴 손잡이가 나와 탭이 깔끔하다.

### 4.3 선택의 시각 표현 — 표 / 셀 / 범위 / 행 · 열
- **동작 [공식]**: 셀은 클릭, 더블클릭으로 편집, Command-클릭으로 떨어진 셀. **범위는 셀의 흰 점을 끌어** 넓히고, **노란 점을 끌면 내용을 복사**(채우기). 행 · 열은 번호 · 글자를 클릭, 점을 끌어 여럿. 범위를 고르면 아래쪽에 합 · 평균 · 최소 · 최대.
- 선택 색(테두리 · 배경 색)은 설명서에 없음 — 확인 못 함.
- **왜 좋은가 [해석]**: 손잡이의 모양(흰 점 = 선택 확장, 노란 점 = 내용 복사)이 달라 끌 때의 의미를 미리 알 수 있다.

### 4.4 머리글 · 바닥글 · 고정
- **동작 [공식]**: 머리글 행 · 머리글 열 · 바닥글 행을 표마다 최대 5개까지 정한다(Format 사이드바 > Table 탭 > Headers & Footer). **Freeze Header Rows / Columns** 로 스크롤 때 고정. 0 으로 두면 없앤다. 머리글은 보통 배경이 달라 구분된다. 머리글을 늘리면 기존 행이 머리글로 바뀐다.
- **왜 좋은가 [해석]**: 의미(머리글)와 고정(스크롤)을 따로 켠다.

### 4.5 행 · 열 추가 손잡이와 열 크기 조절
- **동작 [공식]**: 표 모서리에 손잡이 3개 — 왼쪽 아래 **행 추가**(클릭 = 1행, 끌면 여러 행), 오른쪽 위 **열 추가**, 오른쪽 아래는 행 · 열 동시. Option-끌기는 데이터가 든 행 · 열도 지운다(기본은 빈 행 · 열만 지워짐). 열 크기는 글자 오른쪽 경계를 끌고, 더블클릭이나 메뉴로 내용에 맞춤(Fit Width to Content), 여러 열을 골라 끌면 비례, Table 메뉴에 균등 분배, 사이드바에 숫자 입력.
- **왜 좋은가 [해석]**: 추가가 표의 끝(눈이 가는 자리)에 있고, 끌어서 여러 개를 한 번에 추가한다. 데이터를 잃는 삭제는 기본으로 막는다.

### 4.6 열 머리 메뉴: 정렬 · 빠른 필터 · 숨기기
- **동작 [공식]**: 열 글자에 마우스를 올리면 화살표가 나타나고 메뉴에 **Sort Ascending/Descending**, **Quick Filter**(값 목록에서 체크), 열 숨기기가 있다. 정교한 규칙은 **Organize 사이드바**의 Sort 탭(여러 규칙, 끌어 순서 변경, Sort Now) · Filter 탭(규칙 여럿, 모두/하나 일치). 정렬은 표를 실제로 재배열한다(빈 셀은 아래, 머리글 · 바닥글은 제외, 합친 셀이 있으면 안 됨). 필터된 행은 "숨겨지는" 것이고, 숨은 행의 표시 방식은 설명서에 없다(확인 못 함).
- **왜 좋은가 [해석]**: 호버 메뉴 하나로 흔한 동작을 처리하고, 복잡한 것만 사이드바로 미룬다(점진적 노출).

### 4.7 범주(그룹)
- **동작 [공식]**: 원본 열의 값으로 행을 묶는다. 그룹 위에 **요약 행**이 생기고 소계 · 개수 · 평균을 넣을 수 있다. 범주 1개 + 하위 4개까지. 행 번호 메뉴에서 선택한 행으로 그룹 만들기, 범주 끄기/켜기. 접기 · 펼치기는 다른 페이지에 있어 읽지 못함(확인 못 함).
- **왜 좋은가 [해석]**: 정렬이나 필터로 못 하는 "묶어서 보기" 를 데이터를 건드리지 않고 한다.

### 4.8 셀 형식 컨트롤
- **동작 [공식]**: 셀 선택 → Format 사이드바 > Cell 탭 > Data Format 에서 선택. **체크박스**(값 1/true · 0/false), **별점**(0~5, 반 개 가능, 숫자 키 0~5), **슬라이더 · 스테퍼**(최소 · 최대 · 증가폭), **팝업 메뉴**(항목 최대 250개, 더블클릭 편집, 끌어 순서 변경). 선택한 셀에 이미 값이 있으면 그 값이 팝업 항목으로 미리 채워진다(중복은 합쳐짐). 형식을 바꾸면 값을 변환하고, 불가능하면 거부한다. Delete 로 내용을 비운다.
- **왜 좋은가 [해석]**: 입력을 제한하는 것이 따로 "데이터 검증" 설정이 아니라 형식 선택 하나로 끝난다.

### 4.9 조건부 강조
- **동작 [공식]**: Cell 탭 > Conditional Highlighting > Add a Rule. 숫자 · 텍스트 · 날짜 규칙, 값에 셀 참조 가능, 글자 스타일 또는 셀 채우기, 규칙이 여럿이면 목록 앞의 것이 이긴다, 끌어 순서 변경, Show Highlighting Rules.

### 4.10 아래쪽 빠른 계산 · Smart Cell View
- **동작 [공식]**: 열 · 행 · 범위를 고르면 합 · 평균 · 최소 · 최대가 창 아래쪽에 나온다. 톱니바퀴로 함수를 더하거나 뺀다. 계산 항목을 표 셀로 끌어다 놓으면 수식으로 들어간다. 수식 셀을 편집하면 같은 자리에 결과 · 참조 값 · 오류 · 경고가 나온다. 숫자 선택이 아니면 어떻게 보이는지는 확인 못 함.
- **왜 좋은가 [해석]**: 수식을 만들지 않고 "합이 얼마지" 를 해결한다. 값을 문서에 안 쓰므로 부작용이 없다.

### 4.11 수식 편집기
- **동작 [공식]**: 셀에서 `=` 를 치면 **Formula Editor** 가 열리고(이동 · 크기 조절 가능), 오른쪽에 함수 브라우저가 나타난다. 함수 인수와 참조는 **토큰**으로 보이고 토큰 ▸ 텍스트로 바꿔 볼 수 있다. Return 또는 Commit 으로 확정, Close 로 취소. 오류는 결과 셀에 아이콘. 참조 색 구분과 자동 완성의 동작은 읽은 페이지에 없음(확인 못 함).
- **JayDocs 와의 관계 [해석]**: JayDocs 는 셀에 수식이 없다(별도 `X_Calc.tsv`). 참고할 것은 "편집 중 결과 미리보기" 정도.

### 4.12 Format · Organize 사이드바(인스펙터)
- **동작 [공식]**: 도구 막대의 Format · Organize 버튼 또는 View > Inspector 로 연다. Format 에서 Cell 탭(데이터 형식 · 조건부 강조) 등, Organize 에서 정렬 · 필터 · 범주를 다룬다. 탭 구성(Table/Cell/Text/Arrange)과 "선택한 것에 따라 내용이 바뀐다" 는 설명은 확인 못 함(다만 화면 구조로는 알려진 동작이다 — 근거 문서는 못 찾음).

### 4.13 Magic Fill (구독, 15.1)
- **동작 [공식]**: 패턴이 있는 셀 + 채울 셀을 골라 Table > Magic Fill Cells, 또는 입력 중 셀 아래에 **Magic Fill Suggestions** 메뉴가 뜨고 Magic Fill Column. 결과를 보고 **As Text / As Formulas** 를 고르고 **Accept / Reject**. 설정에서 "Show suggestions when editing table cells" 로 끈다.
- **왜 좋은가 [해석]**: 제안을 값에 바로 쓰지 않고 후보로 먼저 보여 준 뒤 수락 / 거절하게 한다.

### 4.14 실행 취소 · 자동 저장 · 버전
- **동작 [공식]**: 자동 저장(첫 저장 뒤), 저장마다 버전, File > Revert To > Browse All Versions 의 타임라인, Restore 또는 Restore a Copy(복사본으로 저장). 옛 버전에서 일부만 복사해 붙일 수 있다.

### 4.15 2026 Liquid Glass 로 바뀐 점
- 15.1 의 "Liquid Glass 인터페이스" 가 확인된 전부다. 어떤 요소가 어떻게 바뀌었는지(도구 막대 · 사이드바 · 시트 탭의 구체)는 읽은 문서에 없음 — 확인 못 함. **[해석]** 위 3절의 원칙대로면 표 내용 영역은 그대로이고 도구 막대 · 사이드바가 바뀌었을 것이다(추측).

## 5. JayDocs 에 가져올 만한 것

JayDocs 현재 그리드(SHORTCUTS · HANDOFF 확인): 머리글 2행 고정, 행 번호 · 열 글자 클릭으로 행 · 열 선택, 채우기 핸들, 열 글자 끌어 옮기기, bool 체크박스 · enum 드롭다운, 오류 셀 밑줄, 열 머리 호버에 Field 설명, 찾기 막대, 행 · 열 삽입(키 + `＋위` `＋끝` `＋왼쪽` 버튼). 그리드 자체의 정렬 · 필터는 없다(tsv-view 에 있음). 하단 상태 막대 · 선택 요약은 없다.

| 요소 | 우선순위 | JayDocs 의 어느 화면 | 웹 PWA 구현 방법 | 주의 |
|---|---|---|---|---|

| 셀 정보 막대(Smart Cell View 의 응용): 활성 셀의 열 이름 · 타입 · Field 설명 · 검증 오류 · Key 중복 | **높음** | 위 막대의 왼쪽 | 지금 호버 툴팁 · 밑줄로 흩어진 정보를 활성 셀 기준으로 한곳에 보임 | 호버는 키보드 사용자에게 안 보이므로 키보드 중심 도구에 맞다. 한 줄로 끝내고 길면 잘라 F1 처럼 펼침 |

Key 유일 검증은 숨긴 행도 포함 |
| 열 폭 더블클릭 = 내용에 맞춤 | 높음 | 열 경계 | 경계 더블클릭 시 보이는 행(윈도잉 범위)의 최대 글자 폭을 측정 | 전체 행 측정은 큰 표에서 느림 → 상한(예: 앞 500행). 열 폭은 이미 경로별로 저장됨 |

| 선택에 따라 나타나는 손잡이 · 두 가지 모양의 점(끌기 의미 구분) | 중간 | 채우기 핸들 · 범위 선택 | 이미 채우기 핸들이 있다. 범위 선택 확장 손잡이를 따로 두기보다 핸들 모양과 커서로 의미를 구분 | 현재 Shift+방향키 · Shift+클릭이 있으므로 필수는 아님. 손잡이가 많으면 한글 IME · 편집 모드와 포인터 충돌 |

**권고(하나)**: 위 표의 처음 세 줄을 한 묶음으로 — "그리드 아래 막대 = 왼쪽 셀 정보 + 오른쪽 선택 요약" 을 먼저 만든다. 읽기 전용이라 포맷 계약을 건드리지 않고, 키보드 사용자에게 바로 이득이고, 구현이 작다. 열 머리 ▾ 메뉴(보기 전용 정렬 · 필터)는 그다음에, 정렬 상태에서의 편집 규칙을 먼저 정한 뒤 넣는다.

## 6. 맞지 않아 가져오지 않을 것

- **캔버스 위에 표를 자유롭게 놓는 모델(표 핸들 · 이동 · 잠금)**: JayDocs 는 파일 하나 = 표 하나이고 탭 · 분할이 배치를 맡는다. 마크다운 안의 `tsv-view` 가 "문서 안의 표" 역할을 이미 한다. 표를 문서 안에서 이동 · 크기 조절하는 UI 는 필요 없다.
- **시트 탭 모델**: JayDocs 의 탭은 파일이다. 한 TSV 에 시트 여럿을 두면 포맷 계약(1행 타입 행 · 2행 머리글, `_Field` 는 빈 줄로 블록 구분)과 충돌한다. 대신 4.2 의 숨기기 · 색은 파일 단위 보기 설정으로 낮은 우선순위로만 둔다.
- **수식 편집기 · 수식 셀 · 토큰 · 함수 브라우저**: JayDocs TSV 는 셀에 수식이 없다(계산식은 `X_Calc.tsv` 와 F9). 선택 요약 막대의 "계산 항목을 셀로 끌어다 놓기" 도 가져오지 않는다.
- **정렬 · 범주를 파일에 반영하는 방식(표를 실제로 재배열)**: 계약상 바꾼 셀의 행만 diff 에 나와야 하고 Key 순서는 데이터의 의미일 수 있다. 정렬은 보기 전용으로만.
- **합친 셀 · 개별 셀 스타일(글꼴 · 채우기) · 표 스타일 · 바닥글 행**: TSV 에 저장할 자리가 없고(탭 split 만), 스타일을 파일 밖에 두면 사람마다 다르게 보인다. 머리글 행 개수 0~5 선택도 맞지 않는다(타입 행 + 머리글 행으로 고정).
- **별점 · 슬라이더 · 스테퍼**: 타입 행에 해당 타입이 없다(`string / enum / bool / byte / uint / int / float`). 표시만 다르게 한다고 해도 값이 그냥 숫자이므로 이득이 작다. 팝업 메뉴는 enum, 체크박스는 bool 로 이미 대응.
- **Magic Fill 의 AI 부분 · 지능형 어시스턴트 · MCP**: 서버 · 외부 호출 없는 로컬 PWA 이고 구독 기능이다. 패턴 채우기는 채우기 핸들이 이미 한다.
- **자동 저장 + 버전 타임라인**: JayDocs 는 사용자의 실제 폴더(git 로 관리하는 SagaDocs 등)에 직접 쓴다. 저장은 명시적이고(미저장 `●`) 이력은 git 이 맡는다. 자동 저장은 원치 않는 파일 변경 · 충돌 배너와 겹친다. 되돌리기는 지금처럼 문서 단위 Undo 로.
- **클라우드 협업 · 공유 · 숨긴 시트의 공유 규칙**: 서버 없음.
