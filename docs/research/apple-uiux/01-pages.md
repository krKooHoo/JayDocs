# 01 — Apple Pages UI/UX 조사

조사일 2026-11-22. 대상은 Mac용 Pages(사용 설명서 기준 16.0), iPad · iPhone 은 문서 관리자 · Screen View 만 참고했다.
**확인 못 한 것은 본문에 '확인 못 함' 으로 적었다.** 가장 큰 공백 두 가지: ① HIG(developer.apple.com/design/human-interface-guidelines) 본문은 페이지가 스크립트로 그려져 직접 읽지 못했고, 검색 요약으로만 확인했다. ② Mac 의 Screen View 는 메뉴 경로 · 도입 날짜를 공식 페이지에서 찾지 못했다.

## 1. 한 줄 요약

Pages 는 "문서가 주인공이고 도구는 선택에 따라 바뀌는 오른쪽 인스펙터 하나에 모은다" 는 구조다. JayDocs 가 가져올 핵심은 **저장 시점 버전 기록(되돌리기 타임라인)**, **문맥에 따라 바뀌는 오른쪽 인스펙터 한 자리**, **보이지 않는 문자 보기** 세 가지다. Liquid Glass 의 반투명 재질은 텍스트 편집 앱에 맞지 않아 가져오지 않는다.

## 2. 개요

### 무엇이고 누구를 위한 것

- Apple 의 워드 프로세서 겸 간단한 레이아웃 도구. 편지 · 보고서 · 포스터 · 책(EPUB)까지 템플릿으로 시작한다. 일반 사용자 대상이고, 코드 · 데이터 편집기가 아니다.
- 문서 종류가 둘이다: **워드 프로세싱**(본문 영역이 있고 쪽이 자동으로 늘어난다)과 **쪽 배치**(본문 없이 텍스트 상자 · 개체를 자유 배치). 도구 막대의 문서 버튼 → "Document Body" 체크로 구분하고, 둘 사이를 바꿀 수 있다(쪽 배치로 바꿀 때 본문 글이 지워질 수 있다는 경고가 있고 Cmd+Z 로 되돌린다).
- 모든 문서는 템플릿에서 시작한다. 만든 뒤에는 템플릿을 바꿀 수 없다.

- 만들기 · 보기 · 편집 · 실시간 공동 작업은 구독 없이 된다고 설명서가 밝힌다. 구독(Creator Studio)은 AI · 콘텐츠 허브 같은 추가 기능이다.

## 3. 디자인 철학

### Apple 이 공식적으로 말한 것

- **Liquid Glass**(Apple Newsroom, 2025-06-09): 컨트롤 · 도구 막대 · 내비게이션은 콘텐츠 위에 놓이는 "별개의 기능 층" 이고, 콘텐츠에 자리를 내주다가 더 많은 선택이 필요할 때 모습이 바뀐다. 사이드바는 뒤의 콘텐츠를 굴절시킨다. 새 요소는 창 · 하드웨어의 둥근 모서리와 동심원으로 맞춘다.
- **HIG 재질(materials)** (검색 요약, 본문 직접 확인 못 함): Liquid Glass 는 탭 막대 · 사이드바 같은 컨트롤 · 내비게이션 층에만 쓰고 콘텐츠 층에는 쓰지 않는다. 글이 많은 구성요소(알림 · 사이드바 · 팝오버)에는 불투명도가 높은 "regular" 변형을 쓴다. 유리 위에 유리를 겹치지 않는다.
- **HIG macOS 설계**(검색 요약): "개인화를 허용하라" — 도구 막대 사용자화, 자주 쓰는 보기로 창 구성 등을 예로 든다.
- **WWDC25**(검색 요약): 사이드바는 콘텐츠 위에 떠 있는 유리판, 인스펙터는 콘텐츠 옆에 붙는 가장자리 끝까지의 유리. 사이드바 지침이 2026-06-08 에, 도구 막대 지침이 2025-12-16 에 Liquid Glass 에 맞춰 갱신됐다고 HIG "What's new" 에 올라 있다(검색 요약 기준, 내용은 확인 못 함).
- **Pages 만의 철학 선언**: 사용 설명서 · 보도 자료에서 찾지 못했다(확인 못 함). 아래는 모두 동작에서 읽은 해석이다.

### 해석 (내 해석)

1. **선택이 곧 문맥이다.** 오른쪽 Format 인스펙터가 선택(텍스트 · 도형 · 표 · 차트)에 따라 내용을 바꾼다. 사용자는 도구를 찾지 않고 대상을 고른다. 선택이 없으면 비어 있다.
2. **미리 만든 것에서 시작한다.** 빈 문서 하나가 아니라 템플릿 선택기가 첫 화면이다. 빈 화면의 막막함을 없애는 방향.
3. **저장을 걱정하게 만들지 않는다.** 저장할 때마다 버전이 남고 타임라인으로 돌아간다. "잃을까 봐 두려워하는 비용" 을 앱이 진다.
4. **일은 메뉴 막대에, 자주 하는 일은 도구 막대에.** Show Invisibles 같은 보조 보기는 도구 막대가 아니라 View 메뉴에 있다. 도구 막대는 사용자가 고쳐 쓴다.
5. **같은 개념을 같은 자리에서.** 스타일은 항상 Format 사이드바 맨 위 이름 상자, 되돌리기는 항상 이름 눌러서. 개체 종류가 달라도 규칙이 같다.

## 4. 핵심 UI/UX 요소

### 4.1 문서 관리자 · 템플릿 선택기 · 최근 문서

- **무엇**: Mac 은 켜면 "새 문서" 버튼이 있는 시작 대화상자, 또는 File > New 로 템플릿 선택기. iPhone · iPad 는 **문서 관리자** — 하단 **Recents / Browse**, 위쪽에 **Create Document** 버튼과 기존 문서 썸네일.
- **어떻게**: 선택기는 왼쪽 사이드바에 범주(기본부터), 오른쪽에 범주별 썸네일 줄. 줄에 마우스를 올리면 좌우 화살표나 두 손가락 스와이프로 더 본다. 두 번 클릭하면 연다. 아래 왼쪽에 언어 팝업. 설정(Pages > Settings > General)에서 "항상 이 템플릿으로 시작" 을 정하면 File > New 가 선택기를 건너뛰고, Option 을 누른 채 File > New 로 선택기를 다시 연다. 내 문서를 "사용자 템플릿으로 저장" 할 수 있다.
- **왜 좋은가**: 시작이 한 동작이다(기본 템플릿 지정). 자주 쓰는 틀은 한 번에, 가끔 고를 때만 선택기가 나온다. 범주 사이드바가 가짓수가 많아도 훑게 한다.

### 4.2 오른쪽 Format 인스펙터 (문맥 인스펙터)

- **무엇**: 도구 막대의 **Format** 버튼과 **Document** 버튼이 여는 오른쪽 사이드바. Format 은 선택한 것의 서식, Document 는 쪽 방향 · 크기 · 여백 · 머리말 꼬리말 같은 문서 전체 설정.
- **어떻게**: 선택에 맞는 탭으로 내용이 바뀐다. 위쪽 탭들(예: 개체의 Style / Arrange, 텍스트 상자 안 글의 Text 탭 — 설명서가 "텍스트 상자 · 표 · 도형 안의 글이면 Text 탭을 먼저 누르라" 고 안내한다). 선택이 없으면 거의 비어 있다. Format 버튼을 다시 누르면 닫히고, Document 버튼은 열린 채 탭만 바꾼다. 탭 이름 전체 목록은 이번 조사에서 공식 페이지로 확인 못 함.
- **왜 좋은가**: 도구가 화면에 흩어지지 않고 한 자리에 있다. 선택하지 않은 것의 옵션은 안 보여 화면이 조용하다. 문서 전체 설정(Document)과 선택 설정(Format)이 분리되어 "지금 무엇을 바꾸는가" 가 분명하다.

### 4.3 도구 막대 사용자화

- **무엇**: View > Customize Toolbar 에서 항목을 끌어 넣고 빼고 순서를 바꾼다.
- **어떻게**: 끌어서 추가 · 제거 · 재배열. 기본 세트는 아래 줄을 도구 막대로 끌어 복원. 아래 왼쪽 팝업에서 아이콘+글자(기본) · 아이콘만 · 글자만. Format 과 Document 버튼은 한 덩어리로 같이 움직인다. 설명서는 "안내에 나오는 버튼이 안 보이면 지웠을 수 있다" 고 따로 알린다.
- **왜 좋은가**: 자주 쓰는 것만 남겨 화면을 줄인다. 초보는 글자 포함으로 배우고 숙련자는 아이콘만으로 줄인다.

### 4.4 문서 보기 · 사이드바 · Screen View

- **무엇**: 왼쪽 사이드바는 **View** 버튼 하나에서 **쪽 썸네일 · 목차 · 댓글/변경 창** 중 하나를 고른다. 오른쪽은 Format/Document. 확대는 도구 막대의 Zoom 팝업(한 쪽 · 두 쪽 · 비율 · 너비 맞춤 · 쪽 맞춤), 전체 화면, 설정의 기본 확대 비율.
- **어떻게**: 왼쪽 자리는 한 번에 하나(썸네일 ↔ 목차 ↔ 댓글)가 번갈아 들어온다. **Screen View**(15.4, Mac): 쪽 구분 없이 화면에 맞춘 연속 흐름으로 읽기와 집중 쓰기를 돕는다. 끄면 전체 레이아웃이 돌아온다(Apple 의 iPad · iPhone 설명). Mac 의 정확한 메뉴 · 동작은 확인 못 함.
- **왜 좋은가**: 같은 문서를 "인쇄 모양" 과 "화면 모양" 두 가지로 보게 해 쪽 개념에 묶이지 않는다. 왼쪽 자리가 하나라 화면이 안 복잡하다.

### 4.5 스타일 (단락 · 문자)

- **무엇**: Format 사이드바 맨 위의 **단락 스타일** 팝업, 글꼴 영역의 **문자 스타일** 팝업. 둘 다 이름 있는 서식 묶음이다.
- **어떻게**: 스타일을 적용한 글을 손으로 고치면 스타일 이름 옆에 **별표(*)** 가 뜬다(덮어쓰기 표시). 별표만 있거나 별표와 **Update** 버튼이 나온다. Update 를 누르거나 **Redefine from Selection** 을 고르면 그 스타일을 쓰는 모든 글이 바뀐다. 되돌리려면 스타일 이름을 눌러 원래 스타일(회색 체크)을 다시 고른다. 이름 바꾸기 · 삭제는 이름 옆 화살표. 문자 스타일도 같은 규칙이다.
- **왜 좋은가**: "스타일에서 벗어났음" 이 보이고, 벗어난 것을 (a) 스타일을 고쳐 문서 전체에 퍼뜨리거나 (b) 되돌리는 두 길이 있다. 서식 일관성을 눈으로 지킨다.

### 4.6 보이지 않는 문자 보기

- **무엇**: View > **Show Invisibles**. 공백 · 탭 · 줄 바꿈(Return) · Shift-Return · 쪽 · 단 · 절 · 레이아웃 나눔 기호를 보인다.
- **어떻게**: 도구 막대 View 버튼이 아니라 **메뉴에만** 있다(설명서가 명시). 기호 색은 설정 > General 의 Invisibles 색 상자. 찾기 · 바꾸기는 코드(`\n` 단락 · `\t` 탭 · `\p` 쪽 · `\i` 줄 바꿈)로 이 문자들을 검색한다.
- **왜 좋은가**: 두 칸 공백 · 몰래 들어간 탭 같은 보이지 않는 오류를 찾는다. 자주 안 쓰므로 메뉴에 두어 도구 막대를 지킨다(해석).

### 4.7 변경 추적 · 주석

- **무엇**: Edit > Track Changes(또는 검토 도구 막대의 버튼). 추가 · 삭제가 색으로 남는다.
- **어떻게**: 검토 도구 막대의 **Change Tracking** 메뉴에서 보기를 고른다 — **Markup / Markup Without Deletions / Final**. 변경 하나에 마우스를 올리면 Accept/Reject, 범위 선택 후 일괄, 전체는 메뉴에서 Accept All/Reject All. 슬라이더로 **일시 중지**. 끄려면 먼저 전부 수락 · 거부해야 한다. 오른쪽이 아니라 **왼쪽 "댓글 · 변경 창"** 에 목록이 나오고 작성자 · 종류로 거른다. iCloud 로 공유한 문서를 Pages 앱 없이 열면 보기만 된다.
- **왜 좋은가**: 편집 흔적을 지우지 않고 "최종 모양" 으로 읽을 수 있다. 일시 중지로 오탈자 수정까지 기록되는 소음을 피한다.

### 4.8 자동 저장 · 버전 탐색

- **무엇**: 저장할 때마다 새 버전이 남는다. **File > Revert To > Browse All Versions**.
- **어떻게**: 오른쪽에 시간 눈금 타임라인과 썸네일 더미. 눈금이나 화살표로 넘기며 고른다. **Restore** 는 현재 버전을 바꾼다. **Option 을 누르면 Restore a Copy** 로 새 창에 복사본을 연다(원본 보존). 옛 버전에서 일부만 복사해(Edit > Copy) 현재 버전에 붙여 넣을 수도 있다. **Revert To > Last Opened / Last Saved** 는 연 시점 · 마지막 저장으로 간단히 되돌린다. 공유 문서는 공유한 뒤의 버전만, 보기 전용 사용자는 못 본다. iCloud Drive 를 쓰면 기기 사이 동기화되고 오프라인 편집은 다시 연결 때 올라간다. "자동 저장" 이라는 단어는 이번에 읽은 두 설명서 페이지에 없다 — 확인 못 함.
- **왜 좋은가**: 저장 · 되돌리기 불안이 없다. "복사본으로 복원" 이 안전한 탈출구라 과감히 되돌려 본다. 연 시점 되돌리기는 한 동작 실험을 쉽게 한다.

### 4.9 빈 상태 · 첫 사용 경험

- 앱을 열면 문서가 없을 때 템플릿 선택기(Mac) · 문서 관리자(iOS)가 빈 화면을 대신한다. 새 문서도 비어 있지 않고 템플릿의 자리 표시자 글이 있다(Pages 문서 기본 동작, 이번 조사에서 공식 페이지로 확인 못 함). 따로 둘러보기 투어는 확인 못 함.
- **왜 좋은가**: 빈 화면에서 멈추는 순간을 없앤다(해석).

### 4.10 2026 Liquid Glass 로 바뀐 점

- 15.1 설명서가 "Liquid Glass 로 새롭게 매끄러운 작업" 을 적었다. 구체적인 화면 변화(어느 막대가 어떻게 바뀌었는지)는 Pages 공식 페이지에서 확인 못 함. 앱이 macOS 26 이상에서만 돈다는 것은 확인.
- 시스템 차원(공식): 도구 막대 · 사이드바가 콘텐츠 위 별개의 층, 사이드바 굴절, 메뉴 막대 투명, 동심원 모서리. 콘텐츠 층에는 쓰지 않는다.
- **해석**: 텍스트 편집기 입장에서 중요한 것은 장식이 아니라 "문서 면은 건드리지 않고 컨트롤 층만 따로 두라" 는 층 분리 원칙이다.

## 5. JayDocs 에 가져올 만한 것

현재 JayDocs UI(HANDOFF 기준): 왼쪽 파일 트리 · 탭/분할 · 창 막대 버튼 · 팔레트(Ctrl+Shift+P) · 새 문서 창(Ctrl+Alt+N) · 훑어보기 패널(오른쪽, Ctrl+Alt+M) · 하이브리드 목차(왼쪽, Ctrl+Alt+T) · 보기 모드 4종 · TSV 그리드 · 시작 화면. **버전 기록 · 보이지 않는 문자 · 오른쪽 인스펙터 · 변경 표시는 없다.**

## 6. 맞지 않아 가져오지 않을 것과 이유

- **Liquid Glass 재질(반투명 · 굴절)**: HIG 가 글이 많은 구성요소에는 불투명도가 높은 변형을 쓰라고 하고, 콘텐츠 층에는 쓰지 말라고 한다. JayDocs 는 글 · 표가 전부라 가독성이 우선이다. 웹에서 `backdrop-filter` 는 Windows · 저사양에서 느리고, 굴절 효과는 흉내 낼 수 없다.
- **쪽 배치 / 워드 프로세싱 이중 문서 형식, 쪽 썸네일 · 머리말 꼬리말 · 여백**: JayDocs 는 쪽 나눔 · 인쇄 · PDF 를 하지 않는다(HANDOFF, Jay 결정).
- **스타일의 Update / Redefine from Selection**: md 는 스타일이 문법이라 "이름 붙인 서식 묶음" 이 없다.
- **진짜 변경 추적(작성자 · 수락/거부 · 댓글 창)**: 공동 작업이 없는 1인 로컬 도구에는 과하다. 저장본 비교 표시(5절 4번)만 취한다.
- **서식 인스펙터의 글꼴 · 도형 · 표 서식 세부**: 마크다운은 서식을 파일에 넣지 않는다(DESIGN 의 포맷 계약).
- **iCloud 동기화 · 공유 · 협업**: 서버 없음.
- **Intelligent Assistant · MCP(16.0) · Creator Studio 구독**: 범위 밖. 구독 모델은 참고 사실로만 적는다.
- **개체 인스펙터의 Arrange 탭, Content Hub, 이미지 편집**: 편집 대상이 아니다.
- **Mac 전용 관행 그대로 옮기기**(메뉴 막대 · 투명 메뉴 막대 · 트래픽 라이트 위치): 웹 PWA 에는 메뉴 막대가 없다. 팔레트가 그 역할이다.
