- 항목마다 **원칙 크로스 체크**(맞는 원칙 · 걸리는 원칙)와 **단축키 · 팔레트 명령 제안**을 붙였다. 단축키는 지금 표(`src/lib/shortcuts-table.mjs`)와 겹치지 않는지 확인했다. 정하면 표에 넣어 `npm run shortcuts` 로 SHORTCUTS.md 를 만든다.

- 크기는 대강이다: 작음(반나절 안) · 중간(하루 안팎) · 큼(여러 날).
- 코드에서 확인한 사실은 "확인" 으로, 확인하지 못한 것은 "확인 필요" 로 적었다.

## A. 위치와 상태

### A1. 경로 막대 — 중간
- **무엇**: 문서 창의 탭과 편집기 사이에 `@별칭 › 폴더 › 파일 › 제목` 한 줄. 각 단계를 누르면 같은 단계의 이웃 목록(같은 폴더의 파일, 같은 문서의 제목)이 뜨고, 글자를 치면 거른다. 표는 마지막 단계가 열 목록(`_Field` 는 블록 목록).
- **원칙**: 1 · 4 · 5 맞음 — 트리를 펼치지 않고 "지금 어디인가" 를 보고 이웃으로 간다. 2 주의 — 창마다 한 줄이라 가볍지만 제목 목록은 `lib/md/outline.ts` 를 재사용해 따로 계산하지 않는다.
- **근거**: Xcode 점프 바(07), Finder 경로 막대(08), HIG 경로 컨트롤 — 도구 막대가 아니라 본문에 둔다.
- **키**: `Ctrl+Shift+.` 경로 막대로 포커스(VS Code 와 같은 키). 막대 안: `← / →` 단계 이동, `Enter` · `↓` 목록 열기, 글자 입력 거르기, `Esc` 편집기로.
- **팔레트**: "경로 막대로 포커스".
- **주의**: 좁은 창에서는 앞 단계를 `…` 로 접는다. 목차를 대신하지 않는다. F6 순서에 넣을지 정한다(권고: 넣지 않는다 — 문서 창의 일부로 본다).

### A2. 문서 상태 줄 — 중간
- **무엇**: 문서 창 아래 한 줄.
  - 모든 형식: `UTF-8 · LF · BOM 없음 · 저장됨/수정됨`. 항목을 누르면 관련 명령(UTF-8 로 바꿔 저장 · 다른 인코딩으로 다시 열기).
  - TSV: 왼쪽에 활성 셀의 열 이름 · 타입 · Field 설명 · 검증 오류, 오른쪽에 선택 범위의 개수 · 합 · 평균 · 최소 · 최대(숫자 열만).
- **원칙**: 1 맞음 — 지금 호버 툴팁에만 있는 열 정보가 키보드 사용자에게도 보인다. 3 맞음 — 표 작업의 확인을 문서에 쓰지 않고 한다. 7 맞음 — 표시만 하고 파일에 쓰지 않는다. 2 주의 — 큰 표의 전체 열 선택 때 계산을 미루거나 상한을 둔다.
- **근거**: Numbers 의 아래쪽 빠른 계산 · Smart Cell View(02), TextEdit 의 인코딩(05). TSV 그리드에는 이미 EOL · BOM 표시가 있다(05 리포트) — 그것을 모든 형식으로 넓힌다.
- **키**: 없음(표시). 계산 함수 고르기는 팔레트.
- **팔레트**: "선택 요약에 보일 계산 고르기", "다른 인코딩으로 다시 열기"(→ C4).

### A3. 창 제목의 수정됨 표시 — 작음
- **무엇**: 저장 안 한 문서가 있으면 `● 파일명 — JayDocs`. 지금 `document.title` 은 폴더 이름만 쓴다(확인: `src/App.tsx:141`).
- **원칙**: 7 맞음 — 수동 저장 모델의 약점(다른 창으로 가면 저장 안 한 것을 잊음)을 줄인다.
- **근거**: TextEdit · macOS 의 닫기 버튼 점(05).
- **키 · 팔레트**: 없음. dirty 집합이 바뀔 때만 제목을 쓴다(글자마다 쓰지 않는다).

### A4. 마지막 저장 상태로 되돌리기 — 작음
- **무엇**: 저장 안 한 변경을 버리고 디스크의 내용으로 돌아간다. `Ctrl+Z` 한 번으로 다시 되돌릴 수 있게 한 트랜잭션으로.
- **원칙**: 7 맞음 — 앱 안 사본을 만들지 않고 파일이 기준점이다. HIG "실수에서 복구" 와 같다.
- **근거**: TextEdit · Pages 의 Revert To → Last Saved(05, 01).
- **키**: 주지 않는다(드문 동작). **팔레트**: "마지막 저장 상태로 되돌리기" — 저장 안 한 변경이 있을 때만 활성.
- **주의**: `Ctrl+Z` 로 되돌릴 수 있으면 확인창은 두지 않는다(HIG: 되돌릴 수 있는 동작은 묻지 않는다). 외부 변경 충돌 배너와 문구를 맞춘다.

### A5. 빈 폴더 · 빈 화면 안내 — 작음
- **무엇**: 폴더 격자가 비었을 때 "이 폴더는 비어 있어요" + **새 문서 (Ctrl+Alt+N)** 버튼. 읽기 전용이면 버튼 대신 이유. 문서가 없는 빈 창에도 다음에 할 일(새 문서 · 파일 검색 · 팔레트 · F1)을 키와 함께.
- **원칙**: 1 맞음 — 안내에 단축키를 보인다. 5 맞음 — 빈 곳에서 멈추지 않는다.
- **근거**: Finder 는 빈 창을 그냥 둔다 — 08 리포트는 "우리가 넣는 편이 낫다" 로 해석. HIG 온보딩: 한 번의 안내 흐름보다 상황별 안내.

### A6. 명령 노출 점검 + 버튼 툴팁 단축키 병기 — 중간
- **무엇**:
  1. 창 막대 · 그리드 막대 · 트리 문맥 메뉴의 모든 버튼이 팔레트 명령으로도 있는지 점검한다. 빠진 것으로 확인한 것: 그리드의 `＋위` · `＋끝` · `＋왼쪽`(HANDOFF 숙제), 마크다운 창 막대의 보기 모드 버튼 4개(팔레트에는 "순환" 하나뿐이라 원하는 모드로 바로 못 간다 — 확인: 등록된 명령 목록).
  2. 모든 버튼 툴팁을 `이름 (Ctrl+…)` 한 형식으로, 단축키 표에서 만든다.
  3. 맥락 메뉴(K1)에도 단축키를 적는다. HIG 는 문맥 메뉴에 적지 말라고 하지만, JayDocs 의 맥락 메뉴는 단축키를 가르치는 길이다(단축키 규칙 3). 지금 트리 메뉴도 이미 `F2` · `Del` · `Space` 를 적는다(확인: `FileTree.tsx`).
- **원칙**: 1 맞음(발견성), 6 맞음(Mac 에서는 표에서 ⌘ 표기로 바꿔 보일 수 있다).
- **근거**: HIG 메뉴 막대 · 툴바 · 문맥 메뉴(09), 여러 리포트가 공통으로 권함.
- **키**: `＋위` · `＋끝` · `＋왼쪽` 은 키를 주지 않고 팔레트 명령("위에 행 삽입", "끝에 행 추가", "왼쪽에 열 삽입")과 그리드 맥락 메뉴(K1)에 넣는다 — 흔한 경우는 `Ctrl+Alt+=` 가 맡는다(K2). 보기 모드도 팔레트 명령 4개("보기: 소스" · "보기: 하이브리드" · "보기: 분할" · "보기: 미리보기")만 더하고 키는 순환(`Ctrl+Shift+V`) 하나로 둔다.
- **테스트**: 막대 버튼마다 대응하는 명령이 있는지 검사하는 테스트를 하나 둔다(빠짐을 다시 막는다).

### A7. 접근성 설정 존중 · 대비 — 작음
- **무엇**: `styles.css` 에 `prefers-reduced-motion`, `prefers-contrast: more`, `forced-colors: active` 규칙을 둔다(지금 하나도 없다 — 확인). 라이트 테마 `--muted: #6e7781` 은 흰 바탕에서 4.5:1 경계라(09 리포트 계산) 조금 어둡게 한다.
- **원칙**: 6 맞음 — Windows 고대비 · Mac 대비 높이기 모두. 2 맞음 — 비용이 거의 없다.
- **근거**: HIG 재질 · 색 · 접근성(09).

### A8. 훑어보기 창의 "열기" · "오른쪽에 열기" 버튼 — 작음
- **무엇**: `QuickLook.tsx` 머리에 버튼 두 개. "열기" 는 지금의 `Enter` 와 같다. "오른쪽에 열기" 는 분할 창에 연다.
- **원칙**: 1 맞음 — 이미 있는 키를 버튼으로 드러낸다. 3 맞음 — 보던 문서를 옆 창에 바로 연다.

## K. 단축키 정리 · 맥락 메뉴

`PRINCIPLES.md` 의 단축키 규칙(2026-11-22, Jay)을 지금 표에 적용한다.

### K1. `Alt+Enter` 맥락 메뉴 — 중간~큼
- **무엇**: 어느 영역에서든 `Alt+Enter` 를 누르면 포커스가 있는 자리에 맞는 명령만 작은 목록으로 뜬다(Rider 의 Alt+Enter 와 같은 생각). 치면 거르고, 항목 옆에 단축키를 적고, `Enter` 실행 · `Esc` 닫기. 오른쪽 클릭 · `Shift+F10` 도 같은 메뉴를 연다.
- **영역별 항목(초안)**:

  | 자리 | 뜨는 명령 |
  |---|---|
  | 그리드 셀 · 열 머리 | 정렬 · 거르기 · 열 숨기기 · 폭 맞춤(E1), 위에 행 · 끝에 행 · 왼쪽에 열, 행 · 열 넣기 · 지우기 · 복제, 아래로 · 오른쪽으로 채우기, 계산식 적용, C# DTO 내보내기 |
  | 파일 트리 | 지금 `Shift+F10` 메뉴 전부 + 고정(B4) · 오른쪽 창에 열기(A8) |
  | 마크다운 제목 | 접기 · 펴기(C1), 절 위로 · 아래로, 단계 올리기 · 내리기(C2) |
  | 마크다운 표 | 행 · 열 넣기 · 지우기(K2) |
  | 링크 | 열기, 오른쪽 창에 열기 |
  | tsv-view | 그리드로 열기 |
  | Mermaid | 크게 보기 · 맞춤(A9) |
  | 탭 | 다른 탭 닫기, 탭 유지(D2), 아래로 분할(D4) |
  | 문서 어디서나(맨 아래) | 마지막 저장 상태로 되돌리기(A4), 다른 인코딩으로 다시 열기 · 보이지 않는 문자(C4), 경로 복사 |

- **원칙**: 1 맞음 — 마우스 없이 맥락 동작, 메뉴가 키를 가르친다. 2 맞음 — 외울 키가 준다. 메뉴 목록은 열 때만 계산한다. 6 맞음 — Windows · Mac 같은 키(Mac 은 Option+Return).
- **키가 비어 있는지**: 그리드는 셀 **편집 중** CSV 칸 줄바꿈에만 `Alt+Enter` 를 쓴다(Excel 관행, 확인: `Grid.tsx` 편집 분기) — 편집 중이 아닐 때 메뉴로 쓰면 겹치지 않는다. CodeMirror 기본 키맵에 `Alt-Enter` 가 없다(확인: `node_modules/@codemirror`). 하이브리드 표 칸 편집 중의 처리는 그 기능이 자리 잡은 뒤 맞춘다.
- **구현 메모**: 메뉴 틀은 팔레트의 거르기 목록을 재사용하고 커서 · 셀 옆에 띄운다. 영역마다 "지금 자리에서 쓸 수 있는 명령 id 목록" 을 돌려주는 함수를 하나씩 둔다. 명령은 이미 등록부에 있으니(`enabled()` 포함) 메뉴만을 위한 동작은 만들지 않는다 — **메뉴의 모든 항목은 팔레트에도 있다.**
- **순서**: 그리드 · 트리 먼저(메뉴에 넣을 명령이 이미 있다) → 마크다운 → 탭.
- **팔레트**: "맥락 메뉴" (F1 도움말 · 단축키 표에 `Alt+Enter` 한 줄).

### K2. 행 · 열 넣기 · 지우기를 선택에 따라 — 작음
- **무엇**: `Ctrl+Alt+=` · `Ctrl+Alt+-` 하나로, **열 전체를 고른 상태**(`Ctrl+Space`, 열 글자 클릭)면 열을, 아니면 행을 넣고 지운다. Excel 도 열 전체를 고르고 삽입하면 열이 들어간다.
- **없애는 키**: `Ctrl+Alt+Shift+=` · `Ctrl+Alt+Shift+-`(그리드, 마크다운 표). 마크다운 표에는 열 선택이 없으니 열은 맥락 메뉴(K1)와 팔레트 "마크다운 표: …" 로.
- **원칙**: 단축키 규칙 1(셋까지) · 4(같은 맥락 같은 키).
- **주의**: 마크다운 표 편집은 지금 진행 중인 작업이다(2026-11-22 작업 폴더에 커밋 전 변경 — `HybridTable.tsx` · `tableCommands.ts` · `shortcuts-table.mjs`). 그 작업이 들어간 뒤 맞춘다.

### K3. 새 폴더는 새 문서 창에서 — 작음
- **무엇**: 새 문서 창(`Ctrl+Alt+N`)에서 이름 끝에 `/` 를 치면 폴더를 만든다. 이미 "이름 끝에 `.txt` 를 치면 그 형식" 규칙이 있어 같은 문법이다. 트리 맥락 메뉴 · 팔레트 "새 폴더" 는 그대로.
- **없애는 키**: `Ctrl+Alt+Shift+N`.
- **원칙**: 단축키 규칙 1 · 2.

### K4. 가져오기를 하나로 — 작음
- **무엇**: `Ctrl+Shift+O` 가 가져오기 창을 열고, 창 안의 **폴더 고르기** · **파일 고르기…**(이미 있음) 중 고른다. 끌어다 놓기는 그대로.
- **없애는 키**: `Ctrl+Alt+I`. Mac 에서 ⌘⌥I 가 Chrome 개발자 도구와 겹칠 수 있는 문제(아래 "기존 단축키 점검")도 같이 사라진다.
- **원칙**: 단축키 규칙 4(같은 "가져오기" 는 같은 키), 6.

### K5. 옮기기 · 복제 가족 맞추기 — 중간
- **무엇**: 그리드에서 `Alt+↑ / Alt+↓` = 행 옮기기(새 기능), `Shift+Alt+↓` = 행 복제. 마크다운의 줄 옮기기 · 줄 복제, 목차의 절 옮기기(C2)와 같은 키가 된다.
- **없애는 키**: `Ctrl+Shift+D`(행 복제).
- **원칙**: 단축키 규칙 4. 7 주의 — 행 하나를 옮기면 그 행과 자리를 바꾼 행만 diff 에 나온다.

### K6. 마크다운에서도 `Ctrl+H` 로 바꾸기 — 작음
- **무엇**: 마크다운 편집기에서 `Ctrl+H` 를 누르면 찾기 패널을 바꾸기 칸에 포커스를 두고 연다. 그리드의 `Ctrl+H` 와 같은 뜻.
- **원칙**: 단축키 규칙 4. 지금 마크다운에서 `Ctrl+H` 가 무엇을 하는지(브라우저 방문 기록이 열리는지)는 **확인 필요**.

### K7. 단축키 안내 창 — 중간
- **무엇**: 화면 구석에 떠 있는 작은 창. 포커스가 있는 자리(마크다운 편집기 · 목차 · 그리드 · 트리 · 폴더 격자 · 훑어보기 창 …)에 맞는 **자주 쓰는 키 5~8개**와 동작을 보인다. 자리가 바뀌면 내용이 바뀐다. 맨 아래 줄은 늘 "`Alt+Enter` 이 자리의 모든 동작 · `F1` 전체 표". 옵션으로 켜고 끈다(Jay 요청 2026-11-22).
- **학습 사다리**: 안내 창(이 자리의 자주 쓰는 키, 늘 보임) → `Alt+Enter`(이 자리의 모든 동작, K1) → `F1`(전체 표). 세 곳 모두 같은 단축키 표에서 나온다.
- **원칙 크로스 체크**:
  - 1 맞음 — 이 기능의 목적이다. 마우스 대신 키를 익히게 한다.
  - 2 주의 — 글자를 칠 때마다가 아니라 **포커스가 다른 자리로 옮겨 갈 때만** 다시 그린다. 표를 읽어 보여 주기만 한다.
  - 3 주의 — 글과 표를 나란히 볼 때 내용을 가리면 안 된다. 작게, 접을 수 있게, 좁은 창에서는 숨긴다. 오른쪽 아래는 알림 줄 자리라 피한다(권고: 문서 창 영역의 왼쪽 아래, 파일 트리 바로 오른쪽).
  - 6 맞음 — Mac 에서는 `Ctrl` 을 ⌘ 로 바꿔 보인다(표기만, 키 처리는 이미 ⌘ 를 Ctrl 로 받는다 — `src/lib/keys.ts`).
  - 7 맞음 — 표시뿐, 파일을 건드리지 않는다. 켜짐 상태와 접힘은 화면 설정으로 브라우저에 남긴다.
  - 4 · 5 상관없음. **원칙 확인: 어긋남 없음.**
- **데이터**: `src/lib/shortcuts-table.mjs` 하나에서 읽는다(지금 영역 구분: 전역 · 대화상자 · 새 문서 창 · 탭/패널 · 파일 트리 · 마크다운 · TSV 그리드 · 팔레트). 표 항목에 두 가지를 더한다 — 어느 자리에서 보일지(`where`: 목차 · 폴더 격자 · 훑어보기 창 · tsv-view 셀처럼 영역보다 좁은 자리), 안내 창에 올릴지(`hint: true` 또는 순위). 지금 `keys` 칸의 "(목차)" 같은 괄호 표기는 이 칸으로 옮긴다. **자리 판단은 K1 맥락 메뉴와 같은 함수를 쓴다.**
- **더하면 좋은 것**: 마우스로 단축키가 있는 버튼을 누르면 안내 창에 그 동작의 키를 잠깐 강조한다("다음엔 `Ctrl+Alt+N`"). JetBrains 의 Key Promoter X 플러그인과 같은 생각이고, 메모의 "마우스 사용 최소화" 를 직접 돕는다.
- **보이지 않을 때**: 대화상자 · 팔레트 · 새 문서 창이 떠 있을 때(그 창 안에 이미 키 안내가 있다), 창 폭이 좁을 때. 스크린 리더가 자리 바뀔 때마다 읽지 않게 알림 영역으로 만들지 않는다.
- **키**: `Shift+F1` 안내 창 켜기 / 끄기 — `F1`(도움말) 가족이고 두 키다(지금 표에 없음 — 확인). **팔레트** "단축키 안내 창 켜기 / 끄기". F1 도움말 창 위쪽에도 같은 켜기 / 끄기.
- **기본값**: 처음에는 켜짐(익히는 것이 목적), 끄면 그 상태를 기억한다.

## B. 찾고 옮겨 다니기

### B1. 빠른 열기(Ctrl+P) 확장 — 중간
- **무엇**: 입력 규칙 세 가지. `이름:12` → 그 줄로, `#제목` → 지금 문서의 제목으로, `Ctrl+Enter` → 오른쪽 창에 열기(A8 과 같은 뜻). 빈 입력일 때는 고정(B4) → 최근 순.
  - **본문 검색 입구**(Jay 요청 2026-11-26 "Ctrl+P 에서 파일 내용 검색"): 글자를 치면 목록 맨 아래에 늘 **"본문에서 '…' 찾기 (Ctrl+Alt+F)"** 줄. 고르면 친 글자를 넘겨 전체 검색(B2)이 열린다. 본문 결과를 `Ctrl+P` 목록에 섞지 않는다 — 섞으면 이름 검색이 파일을 다 읽을 때까지 흔들린다(원칙 2 "열기 · 전환이 즉시"). VS Code 도 이름 찾기와 본문 찾기를 나눈다. B2 와 같이 넣는다.
- **원칙**: 1 · 2 · 5 맞음.
- **근거**: Xcode Open Quickly(07), 메모 · HIG 검색의 빈 입력 제안(04, 09).
- **키**: 입력칸 안의 규칙이라 새 전역 키 없음. 규칙은 입력칸의 안내 문구로 알린다.

### B2. 전체 검색 — 큼
- **무엇**: 연 폴더(가져온 폴더 포함)의 본문을 찾는다. 결과 목록에서 `Enter` 로 열고 그 자리로. 범위(전체 / 현재 폴더)를 칸 옆에 보인다.
- **원칙**: 4 · 5 맞음 — 흩어진 아이디어를 모으는 핵심 도구. 2 주의 — 큰 폴더는 읽기 비용이 크다. 읽기를 나누고 진행을 "n개 읽음" 으로 보인다(HIG 진행 표시).
- **근거**: 메모 · Finder · Xcode 의 검색(04, 08, 07). HANDOFF 에서 이미 권고한 후보.
- **키**: `Ctrl+Alt+F`(HANDOFF 에서 잡아 둔 키, 지금 표에 없음 — 확인). `Ctrl+P` 목록의 "본문에서 찾기" 줄로도 들어온다(B1).
- **나중에**: 조건을 칩으로 쌓아 이름 붙여 저장하는 "저장된 검색"(메모 · Finder 의 스마트 폴더). 검색이 자리 잡은 뒤.

### B3. 트리 필터 — 중간
- **무엇**: 트리 위 칸에 치면 트리 항목을 거르고, 맞는 항목의 상위 폴더는 펼쳐 둔다. "저장 안 한 것만" 토글.
- **원칙**: 1 · 4 맞음. `Ctrl+P` 와 달리 폴더 구조 속에서 보며 거른다.
- **근거**: Xcode 내비게이터 필터(07). HANDOFF 후보 "트리 이름 필터".
- **키**: 트리에 포커스가 있을 때 `Ctrl+F` — "지금 영역에서 찾기" 라는 뜻이 편집기 · 그리드의 `Ctrl+F` 와 같다. `Esc` 로 필터를 지우고 트리로. 트리의 키 처리가 `Ctrl+F` 를 받아 브라우저 찾기를 막아야 한다.

### B4. 고정 — 작음
- **무엇**: 문서 · 폴더를 트리 맨 위 "고정" 구역에 올린다. `Ctrl+P` 빈 입력의 맨 위에도.
- **원칙**: 4 맞음 — 흩어진 작업 단위의 자주 쓰는 곳을 한 줄로. 7 맞음 — 경로 목록은 화면 상태로 브라우저에 둔다(파일은 안 바뀜).
- **근거**: 메모의 고정, Freeform · Finder 의 즐겨찾기(04, 06, 08).
- **키**: 주지 않는다. **팔레트** "현재 문서 고정 / 해제", 트리 문맥 메뉴 "고정".
- **주의**: 이름 바꾸기 · 이동 때 경로를 갱신한다. `@별칭` 경로를 구분해 저장한다.

### B5. 뒤로 · 앞으로 — 중간
- **무엇**: 파일 열기 · 제목 점프(목차 · 경로 막대 · `#제목`)마다 위치를 기록하고 되짚어 간다.
- **원칙**: 3 · 5 맞음 — 표와 문서를 오가며 확인한 뒤 원래 자리로.
- **근거**: Xcode 이동 기록(07), Freeform 장면의 뒤로/앞으로(06).
- **키**: `Alt+,` 뒤로 · `Alt+.` 앞으로.
  - `Alt+← / →` 를 쓰지 않는 이유: Windows 브라우저의 뒤로 가기이고, Mac 에서는 Option+← / → 가 편집기의 단어 이동이다.
  - `Ctrl+[ / ]` 를 쓰지 않는 이유: Mac 에서 ⌘[ / ⌘] 가 브라우저 뒤로 가기다.
  - `Alt+,` · `Alt+.` 는 지금 표에 없고 탭 이동 `Alt+[ / ]` 와 같은 Alt 계열이다.

### B6. 폴더 격자 보기 전환 · 정렬 — 중간
- **무엇**: 폴더 훑어보기에서 격자 ↔ 목록(이름 · 수정 시각 · 크기). 정렬(이름 · 수정 시각), 수정 시각 정렬일 때 "오늘 · 어제 · 지난 7일 · 그 전" 묶음 머리글.
- **원칙**: 5 맞음 — 최근에 손댄 아이디어부터 모아 본다. 2 주의 — 수정 시각 읽기 비용, 이미 있는 "보이는 카드만 그리기" 와 맞춘다.
- **근거**: Finder 의 보기 네 가지, 메모의 목록/갤러리와 날짜 묶음, Freeform 보드 목록(08, 04, 06).
- **키**: 폴더 격자 안에서 `Ctrl+Shift+V` = 격자 ↔ 목록(마크다운의 `Ctrl+Shift+V` 보기 전환과 같은 뜻). 정렬은 팔레트. 전역 단축키는 `window` 에서 받으므로(`App.tsx`) 격자가 먼저 받아 전파를 멈춰야 한다 — 안 그러면 뒤의 마크다운 창 모드가 바뀐다.

## C. 생각을 구조로

### C1. 제목 접기 — 중간
- **무엇**: 마크다운 제목 아래 절을 접고 편다(화면 상태만, 파일은 그대로). 목차에서도 접는다.
- **원칙**: 5 맞음 — 긴 메모를 개요처럼 본다. 7 맞음 — 파일을 바꾸지 않는다.
- **근거**: 메모의 접는 제목(04). HANDOFF 후보 "절 접기".
- **키**: `Ctrl+Alt+[` 접기 · `Ctrl+Alt+]` 펴기. 목차에서는 `←` 접기 · `→` 펴기(트리와 같다). 모두 접기 · 모두 펴기는 팔레트.
  - CodeMirror 기본(`Ctrl+Shift+[`)을 쓰지 않는 이유: 표의 Ctrl 을 Mac 에서 ⌘ 로 읽으면 ⌘⇧[ 가 되는데, 이것은 Mac 브라우저의 이전 탭이다. `Ctrl+Alt+[` 는 Mac 에서 ⌘⌥[ 로 CodeMirror 의 Mac 기본과 같다.
- **주의**: 접힌 상태를 다시 열 때 복원할지 정한다(권고: 문서별로 복원 — 레이아웃 · 열 너비처럼 화면 상태로 남긴다).

### C2. 목차에서 절 옮기기 · 단계 바꾸기 — 큼
- **무엇**: 목차에서 제목을 골라 그 절 전체를 위 · 아래로 옮기고, `#` 단계를 올리고 내린다. 편집기 트랜잭션 한 번 — `Ctrl+Z` 한 번으로 되돌린다.
- **원칙**: 5 맞음 — 흩어진 생각을 문제정의 → 솔루션 → 결론 순서로 재배치하는 도구. 7 주의 — 절 범위 계산이 틀리면 내용이 상한다. 코드 펜스 · tsv-view 안의 `#` 을 제목으로 보지 않는 테스트를 먼저 쓴다. 옮긴 줄만 diff 에 나와야 한다.
- **근거**: Keynote 의 편집하는 개요(03).
- **키**: 목차에서 `Alt+↑ / Alt+↓` 절 옮기기(편집기의 줄 옮기기와 같은 키), `Tab` 단계 내리기(`#` 하나 더) · `Shift+Tab` 단계 올리기(Keynote 개요 · 편집기 들여쓰기와 같은 뜻). 목차에서 나가는 길은 `Esc` · `F6` · `Ctrl+Alt+T` 가 이미 있다. 편집기에서는 팔레트 "현재 절을 위로 / 아래로".
  - `Alt+Shift+← / →` 를 쓰지 않는 이유: Windows 에서 `Alt+Shift` 는 입력 언어 전환 기본 키다.

### C3. 결론 문서 템플릿 — 작음
- **무엇**: 새 문서 창의 예시에 "문제 정의 → 근거 → 솔루션 → 결론 · 다음 행동" 틀을 넣는다. 근거 칸에는 문서 링크 · tsv-view 인용의 예를 둔다.
- **원칙**: 5 맞음 — "결론 쓰기" 단계의 도구. 이 항목은 Apple 조사가 아니라 원칙에서 나왔다.
- **위치**: `src/lib/templates.ts`(형식을 늘리지 않으니 예시만 더한다). 사용자는 자기 틀을 `_templates/` 에 둘 수 있다(이미 있음).

### C4. 보이지 않는 문자 · 다른 인코딩으로 다시 열기 — 중간
- **무엇**: 
  1. 탭 · 줄 끝 · 앞뒤 공백을 기호로 보인다(기본 꺼짐). 그리드에서는 셀 안의 앞뒤 공백 · 칸 줄바꿈(CSV).
  2. 읽기 전용 배너 · 상태 줄에서 "다른 인코딩으로 다시 열기"(EUC-KR 등). 이미 읽은 바이트를 다시 해석해 화면만 바꾼다 — 디스크는 그대로.
- **원칙**: 7 맞음 — 탭 split · EOL 보존 계약의 문제(몰래 들어간 탭 · 공백)를 눈으로 본다. 인코딩 자동 판단이 틀렸을 때 고칠 길이 생긴다.
- **근거**: Pages 의 보이지 않는 문자(01), TextEdit 의 열기 옵션 인코딩(05).
- **키**: 주지 않는다(드문 동작). **팔레트** "보이지 않는 문자 보이기 / 숨기기", "다른 인코딩으로 다시 열기…".

### C5. 분할 보기 스크롤 맞추기 — 중간
- **무엇**: 마크다운 분할 모드에서 소스를 스크롤하면 미리보기가 같은 곳으로, 미리보기를 스크롤하면 소스가 같은 곳으로 따라온다(Jay 요청 2026-11-26). 기본 켜짐. 지금 분할 모드는 두 칸이 따로 스크롤된다(확인) — 03 조사에서 "분할 모드가 이미 있다" 로 넘긴 것은 이 점을 놓쳤다.
- **원칙**: 1 맞음 — 키 없이 동작, 켜고 끄기는 팔레트. 2 주의 — 대응 표는 내용 · 크기가 바뀔 때만 다시 재고, 스크롤에는 한 프레임에 한 번만 맞춘다. 3 맞음 — 한 문서 창 안의 두 칸만, 분할한 다른 창의 스크롤은 건드리지 않는다. 5 맞음 — 쓰면서 결과를 같은 자리에서 본다. 7 맞음 — 켜고 끄기만 브라우저에 남는다.
- **근거**: VS Code 마크다운 미리보기의 스크롤 동기화(기본 켜짐).
- **구현 메모**: 훑어보기 패널이 이미 쓰는 줄 ↔ 위치 대응(`lib/skim/lineMap.ts`, 미리보기의 `data-line` — `PreviewPane` 의 `lines`)을 분할 모드에서도 켜고 양쪽으로 쓴다. 기준은 각 칸 맨 위에 보이는 줄. 한쪽이 맞춘 스크롤이 다시 반대쪽을 움직이지 않게 막는다. Mermaid · 그림이 늦게 그려져 높이가 바뀌면 대응 표를 다시 잰다(ResizeObserver).
- **키**: 주지 않는다. **팔레트** "분할 보기: 스크롤 맞추기 켜기 / 끄기"(이름이 지금 상태를 따라간다).

## D. 창과 탭

### D1. 다른 창으로 포커스 — 작음
- **무엇**: 직전에 쓰던 문서 창으로 포커스를 옮긴다. 같은 키를 다시 누르면 돌아온다. 시트 창 ↔ 문서 창을 한 키로 오간다.
- **원칙**: 3 맞음 — 메모의 "시트 창과 문서 창 두 가지를 띄워 놓고 포커스를 바꿔 가면서" 를 그대로 옮긴 것이다. 이 항목은 Apple 조사가 아니라 원칙에서 나왔다.
- **왜 F6 으로 모자라나**: `F6` · `Shift+F6` 은 트리 → 탭 묶음들을 한 방향으로 돈다. 창이 둘일 때 오른쪽 창에서 `F6` 을 누르면 트리로 가므로, 방향을 생각해 `F6` 과 `Shift+F6` 을 골라야 한다. 이 명령은 방향 없이 "아까 그 창" 이다.
- **키**: `Ctrl+Alt+O`(지금 표에 없음). **팔레트** "다른 창으로 포커스(직전 창)".
- **주의**: 창마다 커서 · 선택 · 스크롤이 그대로인지(원칙 3) 이 명령으로 오갈 때 시험한다.

### D2. 임시 탭 — 중간
- **무엇**: 트리에서 한 번 눌러 연 문서는 임시 탭(이름 이탤릭)에 열리고, 다음 문서를 누르면 그 탭이 바뀐다. 편집하거나 탭을 두 번 누르면 고정된다. 끄는 설정을 둔다.
- **지금**: 트리에서 문서를 누르거나 `Enter` 를 칠 때마다 새 탭이 붙는다(이미 열린 문서면 그 탭으로 간다 — 확인: `Workbench.tsx` `openFile`). 흩어진 문서를 여러 개 훑으면 탭이 그만큼 쌓인다.
- **원칙**: 4 · 5 맞음 — 흩어진 문서를 훑는 동안 탭이 쌓이지 않는다. 1 주의 — 권고는 마우스 클릭과 `Enter` 를 같은 규칙으로(임시 탭). 고정은 편집 · 탭 두 번 누르기 · 팔레트로.
- **근거**: Xcode 의 이탤릭 탭(07).
- **키**: 주지 않는다. **팔레트** "탭 유지(임시 해제)".
- **주의**: "훑기는 Space(훑어보기 창), 열기는 임시 탭" 으로 역할을 나눈다. 레이아웃 복원 때 임시 상태를 남길지 정한다. 파일 검색(`Ctrl+P`)으로 연 문서는 찾아서 연 것이라 고정 탭으로 연다.

### D3. 집중 모드 — 중간
- **무엇**: 파일 트리 · 탭 막대 · 목차 · 패널을 한 번에 숨기고 본문을 읽기 좋은 폭으로 가운데에. 같은 키로 이전 레이아웃으로 돌아온다.
- **원칙**: 5 맞음 — 결론을 쓸 때 집중. 3 주의 — 분할 중이면 포커스가 있는 창만 남길지 정한다(권고: 포커스 창만).
- **근거**: Pages Screen View(01), Xcode "편집기만 보기"(07), HIG 의 방해 없는 보기 — 복구 방법을 확실히.
- **키**: `Ctrl+Alt+Enter`(지금 표에 없음).

### D4. 아래로 분할 — 작음
- **무엇**: 지금 문서를 아래 창에도 연다. 표 두 개를 위아래로 비교할 때.
- **원칙**: 3 맞음.
- **근거**: Xcode 의 Option 분할(07).
- **키**: 주지 않는다(드문 동작 — 단축키 규칙 2). 탭 맥락 메뉴(K1)와 팔레트 "아래에 분할".

## E. 그리드

### E1. 열 머리 메뉴 — 보기 전용 정렬 · 필터 · 숨기기 · 폭 맞춤 — 큼
- **무엇**: 열 글자에 마우스를 올리거나 키로 열면 메뉴 — 오름차순 · 내림차순 정렬, 값 목록에서 체크해 거르기, 열 숨기기, 폭을 내용에 맞추기. 열 경계를 두 번 누르면 폭 맞춤.
- **원칙**: 3 · 5 맞음 — 표에서 필요한 행만 보며 문서를 쓴다. **7 걸림 → 보기 전용으로 해결**: 정렬해도 파일의 행 순서는 바꾸지 않는다(바꾼 셀의 행만 diff 에 나와야 한다). 정렬 · 필터 중임을 머리와 상태 줄에 표시한다.
- **근거**: Numbers 의 열 메뉴 · 빠른 필터(02).
- **키**: 별도 키를 주지 않고 그리드 맥락 메뉴(`Alt+Enter`, K1)에 넣는다. 열 글자 위의 ▾ 는 마우스용으로 같은 메뉴를 연다. (처음 제안한 `Alt+↓` 는 K5 의 행 옮기기 `Alt+↑/↓` 와 겹쳐 뺐다.)
- **먼저 정할 것**: 정렬 · 필터 중의 행 삽입 · 채우기 · 붙여넣기 규칙. 권고는 정렬 · 필터 중에는 행 삽입과 채우기를 막고 알림으로 이유를 보이는 것. Key 중복 검사는 숨긴 행도 포함한다.

## 기존 단축키 점검 — Mac (원칙 6)

새로 넣는 키는 아니지만, 원칙 6 으로 지금 표를 보니 Mac 에서 시스템 · 브라우저와 겹칠 수 있는 키가 있다. 표의 `Ctrl` 은 Mac 에서 ⌘ 로 읽힌다(`src/lib/keys.ts` — 확인). 아래는 알려진 Mac 동작에 기댄 판단이라 **Mac 에서 실제로 확인이 필요하다**.

| 지금 키 | Mac 에서 | 겹칠 수 있는 것 |
|---|---|---|
| `Ctrl+Alt+D` 다크/라이트 | ⌘⌥D | macOS 의 Dock 자동 숨기기 |
| `Ctrl+Alt+M` 훑어보기 패널 | ⌘⌥M | 앱의 모든 창 최소화 |
| `Ctrl+Alt+I` 파일 가져오기 | ⌘⌥I | Chrome 개발자 도구 — K4 에서 키를 없애므로 해결 |

권고: Mac 에서 `Ctrl+Alt+D` · `Ctrl+Alt+M` 을 눌러 앱이 받는지 먼저 본다. 받지 못하면 그 키만 Mac 에서 다른 조합을 보여 주도록 표에 Mac 대체 키 칸을 둔다(Windows 키는 그대로).

## 확인할 것 (구현 전에)

- 설치한 Edge 앱에서 `Alt+Enter` · `Shift+F1` · `Ctrl+Shift+.` · `Alt+,` · `Alt+.` · `Ctrl+Alt+O` · `Ctrl+Alt+Enter` 가 앱에 오는지(K1, A1, B5, D1, D3).
- 마크다운 편집기에서 지금 `Ctrl+H` 가 무엇을 하는지(K6).
