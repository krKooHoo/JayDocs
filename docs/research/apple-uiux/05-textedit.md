# 05. Apple TextEdit (macOS) — UI/UX 조사

조사일: 2026-11-22. 기준: Apple 지원 사이트의 TextEdit 사용 설명서(현재 macOS 27판으로 표시됨)와 Mac 사용 설명서. Apple 개발자 문서(HIG · AppKit)는 본문을 못 읽은 곳이 많아 해당 항목에 '확인 못 함' 을 적었다. 단축키 목록은 조사하지 않았다.

## 1. 한 줄 요약

TextEdit 은 "열면 바로 쓰고, 저장은 시스템이 책임지는" 표준 macOS 문서 앱의 기본기(자동 저장 · 버전 · 제목 표시줄 · 인코딩 선택)를 가장 작게 보여 주는 견본이다. JayDocs 가 가져올 핵심은 기능이 아니라 **'수동 저장의 불안을 줄이는 장치'**(마지막 저장으로 되돌리기 · 닫을 때 묻는 방식 · 창 제목의 수정됨 표시)와 **'인코딩 · 줄 끝을 숨기지 않고 보여 주기'** 다.

## 2. 개요

- **무엇**: macOS 에 기본으로 깔린 문서 편집기. 서식 있는 텍스트(RTF/RTFD), 일반 텍스트(.txt), HTML, Word · OpenDocument · Web Archive 를 만들고 연다. 안내서는 HTML 을 코드로 편집하는 용도도 든다.
- **누구를 위한 것**: 메모 수준의 글을 빠르게 쓰는 일반 사용자와, 설정 파일 · HTML 을 가끔 고치는 개발자. 기능이 더 필요하면 Pages 로 가라고 안내서가 직접 적는다(아래 3절).
- **구조**: AppKit 의 문서 기반 앱(NSDocument). 자동 저장 · 버전 · 열기/저장 패널 · 최근 항목 · 창 탭 · 제목 표시줄의 파일 메뉴는 TextEdit 이 만든 것이 아니라 **시스템이 문서 앱에 공통으로 주는 것**이다. 그래서 이 조사는 TextEdit 고유 기능보다 "macOS 문서 앱의 공통 문법" 을 본다.

## 3. 디자인 철학

### Apple 이 직접 말한 것

- 자동 저장이 기본이다. TextEdit 안내서: "TextEdit automatically saves your documents as you work on them." (create-open-and-convert-documents) Mac 사용 설명서도 많은 앱이 작업 중 자동 저장하고 "언제든 저장할 수 있다" 고 쓴다. (create-and-work-with-documents)
- 버전은 시스템이 만든다. "A version is saved automatically every hour" 이고, 변경이 많으면 더 자주, 그리고 문서를 열 때 · 저장 · 복제 · 잠금 · 이름 바꾸기 · 되돌리기 때도 만든다. (view-and-restore-past-versions-of-documents) — **저장 · 잠금 · 이름 바꾸기 같은 '사용자의 확정 동작' 이 곧 버전 경계**라는 설계다.
- 개발자용 문서: NSDocument 가 `autosavesInPlace` 를 켜면 별도 사본이 아니라 **문서 파일 자체를 안전 저장(새 파일에 쓰고 바꿔치기)** 으로 덮어쓰고, 버전 탐색이 같이 켜지며, File 메뉴에서 '다른 이름으로 저장' 이 숨고 '복제' 가 들어온다. 오래 편집하지 않은 문서는 읽기용으로 잠긴다. (autosavesInPlace 참조 쪽 · 옛 Document-Based App Programming Guide. 새 참조 쪽은 한 줄뿐이라 세부는 보관 문서에서 읽었다 — 현행 동작과 다를 수 있음)
- 범위 선언: 추가 기능이 필요하면 Pages 를 보라고 안내서가 적는다. 즉 **TextEdit 은 의도적으로 작게 둔다**. (create-open-and-convert-documents)
- 시스템 설정의 '문서를 닫을 때 변경 사항 유지 여부 묻기' 는 기본이 꺼짐(= 닫을 때 묻지 않고 저장)이다. (Desktop & Dock 설정 안내서, 검색 요약으로만 확인 — 본문 직접 확인 못 함)

### 해석 (Apple 문구 아님)

- **해석 1 — 저장을 '동작' 에서 '상태' 로 옮겼다.** 사용자는 저장 버튼을 누르지 않고, 되돌릴 방법(버전)이 보장되는 한 닫아도 잃지 않는다. 위험의 중심이 "저장 안 하고 닫음" 에서 "잘못 고치고 모름" 으로 이동했고, 그 해결이 버전 탐색이다.
- **해석 2 — 파일 이름 · 위치도 문서 창 안에서 다룬다.** 제목을 누르면 이름 · 이동 · 잠금이 열려 Finder 로 나가지 않는다. 파일 시스템이 '문서 안의 속성' 처럼 보인다.
- **해석 3 — 서식 전환은 되돌릴 수 없는 일이므로 경고를 붙인다.** 일반 텍스트로 바꾸면 서식이 사라진다고 미리 알린다. (아래 4.1)
- **해석 4 — 깨진 글자는 사용자가 인코딩을 고르는 '열기 옵션' 으로 푼다.** 자동 판단을 기본으로 두되 실패를 열 때 고칠 수 있게 하고, 저장 때 다시 묻지 않는다.

## 4. 핵심 UI/UX 요소

### 4.1 일반 텍스트 ↔ 서식 있는 텍스트

- **무엇**: 문서마다 형식이 있고 서식 메뉴에서 '일반 텍스트로 만들기' / '서식 있는 텍스트로 만들기' 로 바꾼다. 새 문서의 기본 형식은 설정(새로운 문서 → 형식)에서 고른다. 안내서는 일반 텍스트로 바꾸면 스타일이 모두 사라지고 .txt 로 저장된다고 경고하고, 서식 있는 텍스트는 .rtf 라고 적는다. (같은 안내서의 환영 쪽은 .rtfd 라고 적어 두 페이지가 어긋남 — 확인 못 함)
- **동작**: 일반 텍스트에서는 서식 도구가 없다. 저장 패널의 파일 포맷 팝업에서도 형식을 고른다.
- **왜 좋은가**: 한 앱 안에서 '메모' 와 '설정 파일' 을 둘 다 다룬다. 단점도 분명하다 — 기본값이 서식 있는 텍스트라서 .txt 를 만들 때 매번 바꿔야 한다는 불만이 흔하다(공식 자료 아님, 일반 지식). 파괴적 전환에 경고를 붙이는 것만 배울 만하다.

### 4.2 인코딩 선택과 줄 끝

- **무엇**: 설정의 '열기 및 저장' 에 '일반 텍스트 파일 인코딩' 팝업이 열기용 · 저장용으로 있다. 기본은 자동이다. 한 파일만 다르게 열려면 파일 → 열기에서 파일을 고르고(열지 않고) 왼쪽 아래 '옵션 보기' 로 인코딩 팝업을 골라 연다. 목록에 없으면 '인코딩 목록 사용자화' 가 있다. 글자가 깨졌을 때의 안내는 "다른 인코딩으로 열어 보라" 한 줄이다. 저장 옵션으로 '.txt 확장자 붙이기' 도 있다.
- **줄 끝**: 안내서 일곱 페이지에서 CR · LF · CRLF 언급은 **확인 못 함**. 줄 끝 선택 UI 가 문서화되어 있지 않다(실제 앱에도 없는 것으로 알려져 있으나 공식 근거는 못 찾았다).
- **저장 시 인코딩 선택 패널**: 설정 쪽 문구는 "열기 또는 저장" 에 쓰는 인코딩이라 하지만, 저장 패널의 인코딩 컨트롤은 안내서에 설명이 없어 **확인 못 함**.
- **왜 좋은가**: 인코딩을 숨기지 않고 '열 때의 옵션' 이라는 한 자리에 모았다. 반대로 줄 끝은 아예 사용자에게 안 보인다 — JayDocs 는 이 점에서 오히려 앞선다(TSV 그리드 상태 줄에 CRLF/LF · BOM 을 보인다).

### 4.3 자동 저장 · 버전 · '되돌리기'

- **무엇**: 파일 → 되돌리기에 '마지막으로 연 상태' · '마지막으로 저장된 상태' · 모든 버전 탐색이 있다. 버전 탐색은 화면이 시간 눈금(타임라인) 화면으로 바뀌고 눈금을 눌러 버전을 오간다.
- **동작**: '복원' 은 현재 문서를 그 버전으로 교체한다. Option 을 누르면 '사본 복원' 으로 새 문서를 만든다. 버전 삭제 항목도 있다. (view-and-restore-past-versions) TextEdit 안내서 자체에는 버전 설명이 **확인 못 함** — 시스템 공통 기능으로만 문서화되어 있다.
- **왜 좋은가**: '실수한 뒤의 탈출구' 가 항상 있어서 저장 확인 대화상자를 줄일 수 있다. '마지막으로 연 상태 / 마지막 저장 상태' 라는 **두 기준점** 이 이해하기 쉽다.

### 4.4 잠금 · 편집 방지

- **무엇**: 제목 오른쪽의 화살표 메뉴에서 '잠금'. 잠긴 문서는 편집 · 삭제가 안 되고(Trash 로 옮길 때 경고, 비우면 지워짐) 소유자가 다시 눌러 풀 수 있다. 별도로 서식 → '편집 방지' / '편집 허용' 이 있다. (lock-a-document, create-open-and-convert-documents)
- **왜 좋은가**: 실수 방지용 가벼운 읽기 전용 상태를 문서 안에서 켜고 끈다. 잠글 때 버전이 하나 저장되므로 '확정 지점' 의 의미도 겸한다.

### 4.5 창 제목 표시줄: 프록시 아이콘 · 제목 메뉴

- **무엇**: 제목 표시줄에 문서 이름이 있고, 제목에 마우스를 올리면 화살표가 나와 메뉴가 열린다. 공식 페이지에서 직접 확인한 메뉴 항목은 **잠금** 하나뿐이다. 이름 바꾸기 · 이동 · 복제 · 내보내기 · 되돌리기가 같은 메뉴에 있다는 점은 **공식 페이지에서 확인 못 함**(사용 경험상 알려진 구성).
- **프록시 아이콘**: WWDC22 세션에서 문서 앱은 창 제목에 문서 이름을 보이고, 접근성의 '창 제목 아이콘 보기' 가 켜져 있을 때만 파일 프록시 아이콘이 함께 보인다고 말한다. (WWDC22 10076) 즉 요즘은 **기본 꺼짐** 이다. 아이콘을 끌어 다른 곳에 놓으면 파일이 따라간다는 동작은 개발자 문서 본문을 못 읽어 확인 못 함. 관련 API: `NSWindow.representedURL`(본문 확인 못 함).
- **왜 좋은가(해석)**: 파일 이름 · 위치 · 상태가 제목 한 줄에 모인다. 다만 웹에서는 '끌어서 파일을 옮기는 프록시' 가 성립하지 않는다(6절).

### 4.6 수정됨 표시 (닫기 버튼의 점)

- **무엇**: 창 닫기 버튼 안의 점이 '저장 안 된 변경' 을 뜻하는 것이 AppKit 관례이고, `NSWindow.isDocumentEdited` 가 그 상태를 구동한다. API 이름은 확인했지만 본문(HIG 의 표시 규칙)은 **확인 못 함**.
- **자동 저장 앱에서의 의미(해석)**: 자동 저장 문서에서는 점이 '파일이 위험하다' 가 아니라 '아직 확정되지 않았다' 에 가깝다. 사용자가 점을 지우려고 저장하지 않아도 되도록 설계된 상태 표시다.
- **JayDocs 현황**: 탭 이름 뒤에 `●` (Workbench.tsx 의 `dirty-dot`), 트리에도 `●`. 창(브라우저 탭) 제목 · 닫기 동작과는 연결되어 있지 않고 `beforeunload` 경고만 있다.

### 4.7 윈도우 탭

- **무엇**: 문서가 새 창 대신 탭으로 열린다. 시스템 설정 → 데스크탑 및 Dock → 윈도우의 '문서를 열 때 탭 선호' 가 '전체 화면에서만 / 항상 / 안 함'. 탭 막대 + 버튼 · 파일 → 새로운 탭, '윈도우 → 모든 윈도우 병합', 탭을 끌어 새 창으로. 탭 이름은 저장된 문서 이름이다. (use-tabs-in-windows)
- **왜 좋은가**: 문서 창이 늘어도 Mission Control 이 어지럽지 않고, 병합 · 분리가 되돌릴 수 있는 동작이다.
- **JayDocs 현황**: flexlayout-react 탭 · 분할이 이미 훨씬 강하다 — 해당 없음에 가깝다.

### 4.8 찾기 · 바꾸기

- **무엇**: 편집 → 찾기에서 창 위쪽에 찾기 막대(검색 칸 · 이전/다음 · 지우기 · 완료 버튼)가 열린다. 선택 영역으로 찾기, 검색 옵션 팝업은 문서화된 것이 '대소문자 무시' 뿐(그 밖의 옵션 · 정규식 · 되감기는 확인 못 함), '패턴 삽입' 팝업이 특수 문자(탭 · 줄바꿈 등)를 넣어 준다. 바꾸기 체크박스를 켜면 바꿀 칸이 나타나고 '전체' 는 길게 누르면 '선택 영역 안 전체 바꾸기' 가 된다. (find-and-replace-text)
- **왜 좋은가**: 한 칸으로 시작하고 바꾸기는 필요할 때만 펼친다. **'선택 영역 안에서만 바꾸기'** 가 한 번의 누름 안에 있다.

### 4.9 맞춤법 · 대체(스마트 따옴표 등)

- **무엇**: 설정 '새로운 문서 → 옵션' 에 입력하면서 맞춤법/문법 검사, 데이터 감지, 스마트 복사/붙여넣기, 스마트 따옴표 · 대시 · 링크, 텍스트 대체가 있고 일부는 '서식 있는 문서에서만' 이다. '모든 기본값 복원' 이 시스템 키보드 설정과 일치시킨다. 문서별로는 편집 → 대체 → 대체 보기. (change-textedit-settings, check-spelling-and-grammar)
- **왜 좋은가(해석)**: 일반 텍스트에서는 스마트 따옴표가 코드를 깬다는 걸 알고 '서식 있는 문서에서만' 이라는 분리 옵션을 둔 것으로 보인다. JayDocs 의 md · TSV · CSV 편집에는 이런 치환을 **기본으로 넣으면 안 된다**(포맷 계약 위반).

### 4.10 창 크기 · 줄바꿈

- **무엇**: 서식 → '윈도우에 맞춰 줄바꿈' / '페이지에 맞춰 줄바꿈'(페이지 설정의 용지 크기 기준). 안내서에 'Fit to window' 라는 문구는 **확인 못 함** — 실제 메뉴 이름은 'Wrap to Window / Wrap to Page'. 인쇄 때는 '인쇄 크기에 맞춰 다시 줄바꿈' 을 끌 수 있다. (change-how-text-wraps)
- **왜 좋은가**: 화면용 줄바꿈과 인쇄 폭이 다른 개념임을 분리한다.
- **JayDocs 현황(코드 확인)**: 마크다운 편집기는 항상 줄바꿈(`EditorView.lineWrapping`), 그 밖의 텍스트 형식에는 줄바꿈 켜기/끄기 UI 가 없다.

### 4.11 문서 열기 패널 · 최근 항목

- **무엇**: 파일 → 열기(시스템 패널), 파일 → 최근 사용 열기, Apple 메뉴의 최근 항목, Finder 의 최근 항목. 열기 패널의 '옵션' 이 인코딩 · 파일 형식 선택을 연다. (open-documents) 열기 패널 자체의 세부는 해당 페이지가 얇아 확인 못 함.
- **왜 좋은가**: 최근 목록이 앱 바깥(시스템)에도 있어 어느 앱에서든 같은 방식으로 다시 연다.
- **JayDocs 현황**: Ctrl+P 가 이미 '최근' 표시와 최근 순을 준다(DESIGN X6) — 같은 문제를 푼 상태.

## 5. JayDocs 에 가져올 만한 것

JayDocs 의 지금 구조(HANDOFF · SHORTCUTS 기준): 수동 저장(Ctrl+S, Ctrl+Shift+S 모두 저장), 탭 이름 뒤 `●`, 닫을 때 저장 확인, 팔레트 · 파일 검색 · F1, UTF-8 이 아닌 파일은 읽기 전용 배너 + 'UTF-8 로 바꿔 저장' 확인, 마크다운 찾기 패널(CM6, 위쪽 · 한글), 그리드 찾기 막대, 앱 안 버전 기록은 없음(git 은 앱 밖).

| 요소 | 우선순위 | JayDocs 화면 | 웹 PWA 구현 | 주의 |
|---|---|---|---|---|
| **마지막 저장 상태로 되돌리기**(Revert To → Last Saved) | 높음 | 팔레트 명령 + 창 막대 메뉴. 저장 안 한 변경이 있을 때만 활성 | 스토어에 디스크에서 읽은 원본이 이미 있으면 그것으로 문서를 교체하고 `Ctrl+Z` 로 되돌릴 수 있게 하나의 트랜잭션으로. 없으면 디스크에서 다시 읽기 | 파괴적 동작이라 `askConfirm`(취소 기본). 외부에서 파일이 바뀐 충돌 배너와 용어를 맞출 것 |
| **수정됨 표시를 문서 창 제목까지 확장** (`document.title` 앞 `● ` + 설치형 앱의 창 제목) | 높음 | 앱 창(브라우저 탭) 제목 · 설치된 PWA 창 제목 | `document.title = (dirty ? '● ' : '') + 파일명 + ' — JayDocs'`, 스토어의 dirty 집합 구독 | 지금은 탭 이름 `●` 만 있어 다른 창으로 전환하면 저장 안 한 상태가 안 보인다. 글자 하나마다 제목을 쓰지 말고 dirty 가 바뀔 때만 |
| **저장 안 한 상태를 '확정 전' 으로 설명하는 문구 통일** (닫기 · 종료 확인 문구) | 중간 | 저장 안 한 탭 닫기 확인, `beforeunload` | 문구만: '저장하지 않은 변경 N개' 처럼 개수 + 파일 목록(`askConfirm` 의 `items`) | `beforeunload` 는 브라우저 기본 창이라 문구를 못 바꾼다(DESIGN N7) |
| **인코딩 · 줄 끝 · BOM 을 항상 보이는 상태 줄로** | 중간 | 모든 형식의 문서 창 아래 줄(지금은 TSV 그리드 상태 줄에만 있음) | 상태 표시 `UTF-8 · LF · BOM`, 누르면 팔레트의 관련 명령(UTF-8 로 바꿔 저장) | TextEdit 은 줄 끝을 못 보여 준다 — JayDocs 가 앞서 있다. 새 UI 는 포맷 계약(EOL 보존)을 건드리지 않는 '표시' 만 |
| **'다른 인코딩으로 다시 열기'** (열기 옵션) | 중간 | 읽기 전용 배너(`ReadOnlyBanner`) · 팔레트 | 이미 읽은 바이트를 `TextDecoder('euc-kr')` 등으로 다시 해석해 화면만 갱신(디스크는 그대로) | 지금 구조는 자동 판단 한 번뿐. 자동 판단이 틀리면(CP949 를 UTF-8 로 오판 등) 고칠 길이 없다. 덮어쓰기 금지 규칙은 그대로 |
| **선택 영역 안에서만 바꾸기** | 중간 | 마크다운 찾기 패널 · 그리드 찾기 막대 | CM6 `SearchQuery` 에 범위 제한(선택 범위만 순회), 그리드는 선택 범위 안만 | TextEdit 은 '전체' 길게 누르기라 발견이 어렵다 — 버튼 옆에 따로 두는 쪽이 낫다 |
| **찾기 '패턴 삽입'**(탭 · 줄바꿈 입력 도우미) | 낮음 | 그리드 · 마크다운 찾기 막대 | 작은 메뉴가 `\t` · `\n` 을 삽입 | 정규식 모드가 있는 도구면 이스케이프 문법 설명 필요. TSV 에서 탭 검색은 쓸모가 클 수 있다 |
| **줄바꿈 켜기/끄기** (txt · json · md 소스) | 낮음 | 창 막대 · 팔레트 '줄 바꿈 전환' | CM6 `lineWrapping` 컴파트먼트로 켜고 끄기, 형식별 저장 | 코드 확인상 md 만 항상 줄바꿈. 글자 키 단독 단축키 금지 규칙에 맞게 `Alt+Z` 류 조합은 Jay 가 정할 것 |
| **저장 안 한 변경을 임시로 보관(복구)** | 낮음 | 앱 시작 시 '복구할 변경' 알림 | 편집 중 내용을 IndexedDB 에 주기적으로 쓰고 비정상 종료 뒤 복원 제안 | 자동 저장이 아니다 — 디스크를 건드리지 않는다. 원본이 바뀌었으면 충돌 처리. 범위가 커서 별도 결정 필요 |
| **최근 항목 메뉴**(파일 → 최근 사용 열기)의 눈에 띄는 진입점 | 낮음 | 빈 화면 · 시작 화면 | Ctrl+P 의 '최근' 을 시작 화면에도 나열 | 이미 있는 기능의 노출 문제 |

### 가져올 때 우선 순서 (권고 하나)

1. 마지막 저장 상태로 되돌리기 + 2. 창 제목의 수정됨 표시 — 둘 다 구현이 작고, '수동 저장' 모델의 가장 큰 약점(저장 안 한 것을 놓침 · 고친 것을 못 무름)을 직접 줄인다. 3. 인코딩 · 줄 끝 상태 줄과 다른 인코딩으로 다시 열기를 함께 묶는다.

## 6. 맞지 않아 가져오지 않을 것과 이유

- **자동 저장(기본값)** — JayDocs 는 `main` 에 push 되는 공개 리포의 로컬 파일을 직접 쓴다. 파일이 곧 SagaDocs 같은 git 작업 트리여서 '저장 = 확정 지점' 이 diff · 커밋과 맞물린다(CLAUDE.md 포맷 계약: 바뀐 셀의 행만 diff). 타이핑 중 디스크를 계속 덮으면 외부 변경 감지 · 충돌 배너와 부딪힌다. 대신 위의 '복구용 임시 보관' 정도까지가 한계다. (해석)
- **시스템 버전 저장소(타임라인 UI)** — 버전은 macOS 의 파일 시스템 기능이다. 웹에는 없고, 앱이 직접 사본을 쌓으면 저장 용량 · 개인정보 · 동기화 문제가 생긴다. git 이 이미 그 역할이다(HANDOFF: git 은 앱 밖에서). 기준점 둘(마지막 열림 · 마지막 저장)만 흉내 낸다.
- **프록시 아이콘으로 파일 끌어 옮기기** — 브라우저는 파일 경로를 모르고 File System Access 로는 앱 밖으로 파일을 끌어 줄 수 없다. 전체 경로조차 사용자가 한 번 입력해야 한다(DESIGN §30).
- **제목 메뉴에서 이름 바꾸기 · 이동 · 잠금** — 이름 바꾸기(F2) · 읽기 전용은 이미 트리에 있고, 저장 안 한 문서의 이름 바꾸기는 의도적으로 거부한다. '이동' 은 가져온 폴더(`@별칭`)와 FSA 권한 때문에 앞의 두 기능보다 비용이 크다. 잠금은 '읽기 전용으로 열기' 가 이미 있어 이름만 다른 중복이다.
- **서식 있는 텍스트(RTF) · 일반 텍스트 전환** — JayDocs 는 형식이 확장자로 정해지고(`filetypes.mjs`) 마크다운이 '서식' 을 맡는다. 전환의 파괴성 경고는 배우되 기능은 없다.
- **스마트 따옴표 · 대시 · 텍스트 대체 · 맞춤법 기본 켜기** — 코드 · TSV · 마크다운 원문을 바꾸므로 포맷 계약과 충돌한다. 브라우저 자체 맞춤법 밑줄은 이미 있다(별도 처리 안 함).
- **윈도우 탭 / 문서 열기 방식 설정(탭 선호)** — flexlayout 탭 · 분할이 이미 같은 목적을 더 잘 한다.
- **열기 패널의 인코딩 옵션 자체** — 웹에서는 파일 선택 창(시스템)을 앱이 바꿀 수 없다. 앱 안의 '다시 열기' 로 대체(5절).
