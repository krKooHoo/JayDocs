# 06. Apple Freeform — UI/UX 조사

조사일 2026-11-22. 대상: Mac 앱 중심, iPad 참고. 출처는 7절. 확인 못 한 것은 "확인 못 함" 으로 적었다.

## 1. 한 줄 요약

Freeform 은 "끝없는 빈 캔버스 + 최소 툴바 + 고르면 뜨는 문맥 도구" 로 모든 종류의 자료를 한 판에 모으는 앱이다. JayDocs 가 가져올 것은 캔버스 자체가 아니라 **큰 판을 다루는 방법**(맞춤 보기 · 저장된 시점 · 뒤로/앞으로)과 **파일을 카드로 보여 주는 방식**이다.

## 2. 개요

- **무엇**: 아이디어 · 자료를 늘어놓는 협업 화이트보드 앱. 2022-12-13 iOS 16.2 · iPadOS 16.2 · macOS 13.1 에 무료로 들어왔다 [S1].
- **누구를 위한 것**: 브레인스토밍 · 기획 · 여행 계획처럼 "정해진 형식이 없는 모음" 을 다루는 사람. 문서를 쓰는 도구가 아니라 **배치하는 도구**다. 글 구조가 있는 JayDocs 와 성격이 다르다(해석).
- **구성 요소**: 무한 캔버스, 스티커 메모 · 텍스트 · 도형(700개 이상) · 표 · 다이어그램 · 그림 · 링크 · 파일, Apple Pencil, 최대 100명 협업, FaceTime 내장, iCloud 동기화 [S1].
- **2026 기준 변화**
  - 2026-01 Apple Creator Studio(구독 묶음) 발표. Apple 은 Freeform 포함 일부 앱의 새 지능형 기능 · 프리미엄 콘텐츠가 구독자 전용이라고 했다고 MacRumors 가 전한다 [S9]. Freeform 자체는 계속 무료다 [S9]. Freeform 의 구독 전용 기능이 정확히 무엇인지는 **확인 못 함**.
  - Wikipedia 는 2026-03 에 Freeform 이 Creator Studio 에 들어왔고 새 앱 아이콘이 붙었다고 적는다(2차 출처, 원문 The Apple Post) [S8].
  - **2026-09-29 Apple 발표** [S2]: 보드가 다크 모드에 자동으로 맞춰진다. **폴더**로 보드를 묶고 협업자를 초대한다. 공유 파일에 접근 요청을 보낼 수 있다. 손글씨에 쓰기 도구(고쳐 쓰기 · 교정 · 요약)와 단축어 자동화. visionOS 27 에서 보드의 여러 항목을 내 공간으로 꺼내기.
  - 위 다크 모드 · 폴더가 어느 OS 버전부터인지, 구독이 필요한지는 Apple 글에 **없다**. Engadget 은 iOS 27 이라고 하고 [S6], 독자 댓글은 구독이 필요 없다고 하지만 근거가 약하다(확인 못 함).
  - 지금 Mac 사용 설명서(5.0 / macOS 27 판)에 "보드 모양 바꾸기" 로 어두운 배경 보기, 점 격자, 정렬 안내선 5종이 있다 [S4].
- **한계(리뷰)**: 웹/Android 앱이 없다. 협업자는 모두 Apple 계정이 필요하다. 큰 보드는 다루기 어렵다는 평이 있다 [S6].

## 3. 디자인 철학

**Apple 이 공식적으로 말한 것**
- 한곳에서 보고 · 나누고 · 함께 만드는 공유 공간. "see, share, and collaborate all in one place" [S1].
- 캔버스는 내용이 늘면 따라 커져서 쪽 한계가 없다 [S1]. 판 크기를 미리 정하지 않는다.
- Apple 임원 인용(Bob Borchers)은 "끝없는 가능성", "어디든 가져갈 수 있는 공유 공간" 쪽이다 [S1]. UI 원칙에 대한 별도 설명은 **확인 못 함**(HIG 에 Freeform 전용 지침은 찾지 못했다).
- 장면(Scenes)은 "보드 안의 저장된 시점" 이고 보는 사람 누구나 이동에 쓸 수 있다 [S4].

**해석 (Apple 이 말한 것이 아님)**
- **구조를 강요하지 않는다.** 보드를 열면 빈 판이고 툴바는 삽입 버튼 몇 개뿐이다. 쓰는 사람이 구조를 만든다.
- **도구가 대상 곁에 온다.** 도형 · 선 · 텍스트는 고르는 순간 거기에 맞는 서식 도구가 뜬다(채우기 · 선 · 화살표 끝 · 연결선 종류). 전역 툴바가 길어지지 않는다.
- **큰 판의 길 찾기는 "저장된 위치" 로 푼다.** 미니맵 대신 장면 목록 + 뒤로/앞으로 버튼을 둔다. 미니맵은 어느 문서에서도 **찾지 못했다**.
- **내용물을 열지 않고 보게 한다.** 파일은 판 위에서 카드로 놓이고 Space 로 Quick Look 을 연다.
- **협업은 "누가 어디에" 를 보여 주는 데서 끝난다.** 커서 색, 이름 옆 색 막대, 이름을 눌러 그 자리로 이동, 따라가기(Follow).

## 4. 핵심 UI/UX 요소

각 항목은 무엇 / 동작 / 왜 좋은가 순이다.

### 4.1 보드 목록
- **무엇**: 시작 화면이 곧 보드 갤러리. 보드가 아이콘(썸네일) 격자로 뜨고, 목록 보기로 바꿀 수 있다. 왼쪽 사이드바 범주는 모든 보드 · 즐겨찾기 · 공유됨, 그 아래 폴더 [S4].
- **동작**: 아이콘 보기 `⌘1` / 목록 보기 `⌘2` / 검색 `⌘F` [S4]. 보기 > 정렬 기준, 보기 > 그룹 사용(공유됨 범주는 사람별 그룹). 보드를 더블클릭해 연다. 이름은 열린 보드의 왼쪽 위 "Untitled" 를 눌러 바꾼다. 즐겨찾기는 파일 메뉴 또는 보드 왼쪽 버튼. 복제는 `⇧⌘D`(공유 보드의 복제본은 공유가 풀린다). 새 폴더는 파일 메뉴 · 사이드바 버튼 · "선택 항목으로 새 폴더", 끌어 넣기 또는 `Control+클릭 > 이동`, 하위 폴더 가능 [S4]. 삭제 · 복구 절이 따로 있다(상세 확인 못 함).
- **왜 좋은가**: 파일 이름이 아니라 **모습**으로 고른다. 보드가 많아져도 폴더 + 즐겨찾기 + 검색 세 갈래로 줄인다. 최근 범주는 이 안내서에서 **확인 못 함**.

### 4.2 이동 · 확대
- **무엇**: 캔버스 왼쪽 아래의 확대 · 축소 버튼, 보기 > 확대/축소 > 선택에 맞추기 · **내용 전체에 맞추기** [S4].
- **동작**: 트랙패드 핀치와 두 손가락 이동, `Space+드래그` 로 이동, `⌘+` `⌘−`, `⌥⌘+스크롤` 로 확대 [S4]. 배율 숫자 표시와 "100% 로 되돌리기" 는 이 안내서에서 **확인 못 함**.
- **왜 좋은가**: 길을 잃어도 "전체에 맞추기" 한 번으로 돌아온다. 선택한 것에 맞추기는 "지금 만지는 것을 크게" 를 한 동작으로 해 준다.

### 4.3 장면(Scenes)
- **무엇**: 보드 안의 저장된 시점(위치 + 배율). iOS 18 · macOS 15 에서 들어왔다 [S4, S7].
- **동작**: 확대 · 이동으로 구도를 잡고 왼쪽 아래 장면 탐색기 버튼 → 장면 보기 → 장면 추가. 목록에서 고르거나 뒤로/앞으로 버튼으로 넘긴다. 이름 바꾸기 · **현재 구도로 바꾸기(Replace)** · 삭제, 끌어서 순서 바꾸기. 장면을 PDF 로 인쇄 · 내보내기. 협업자 모두가 장면을 쓴다 [S4]. 출시 전 루머 기사에는 다음/이전 장면 단축키가 있었으나 [S10] 확정 여부는 **확인 못 함**.
- **왜 좋은가**: 큰 판을 "목차" 로 쪼갠다. 발표(슬라이드처럼 순서대로) 와 길 찾기에 같은 기능을 쓴다. 장면은 **내용을 복제하지 않고 시점만 저장**해서 가볍다.

### 4.4 최소 툴바와 문맥 도구
- **무엇**: 툴바에는 삽입 도구만 둔다 — 그리기, 텍스트 상자, 도형, 스티커 메모, 표/그래프, 미디어(링크 · 파일 · 사진 · 스케치) [S4].
- **동작**: 항목을 고르면 그 종류에 맞는 서식 버튼이 뜬다. 도형은 채우기 · 선 · 텍스트 · 선 끝 검사기, 연결선이 둘을 이을 때만 "연결선" 검사기가 나온다(직선 · 꺾인 선 · 곡선) [S4]. 링크는 편집 · 열기 · 새로 고침, 파일은 교체 · 미리보기 [S4]. 더 많은 서식은 More 와 컨트롤 클릭 메뉴에 둔다.
- **왜 좋은가**: 화면 대부분이 내용이다. 지금 가능한 것만 보이니 배울 것이 적다.

### 4.5 도형 · 커넥터
- **무엇**: 도형 삽입 버튼이 추천 도형과 "콘텐츠 허브 둘러보기"(검색 칸이 있는 큰 목록), 펜으로 그리기를 연다. 선 · 화살표도 도형 안에 있다 [S4].
- **동작**: 연결선은 항목 한 곳이 아니라 여러 지점에 붙는다 [S11]. 연결선이 항목을 따라 다시 이어지는 세부 동작은 안내서에 **없다**(확인 못 함). 도형 합치기(합집합 · 교집합 · 빼기 · 제외) 와 나누기가 있다 [S4]. 손으로 그린 선을 도형으로 펴 주는 "Snap to Shapes" 가 있다 [S4].
- **왜 좋은가**: 도형 수가 많아도 검색 칸 하나로 고른다. 흐름도를 마우스 몇 번에 만든다.

### 4.6 정렬 안내선 · 격자
- **무엇**: 보기 > 안내선 [S4]: 중앙 · 가장자리 · 상대 크기 · 상대 간격 안내선, 햅틱 피드백. 점 격자 보이기, "격자에 맞추기".
- **동작**: 끌 때 다른 항목과 맞는 순간 선이 뜨고 달라붙는다. 맞추기 설정은 iOS 에서는 보드마다 정할 수 있다고 하지만 [S11], Mac 안내서는 열린 모든 보드에 적용된다고 적는다 [S4] — 둘이 어긋나며 **어느 쪽이 맞는지 확인 못 함**.
- **왜 좋은가**: 눈대중 배치를 도구가 받쳐 줘서 대충 놓아도 정돈된 판이 된다.

### 4.7 파일 · 링크 카드
- **무엇**: 파일을 Finder 에서 끌어다 놓거나 "미디어 > 파일 선택" 으로 넣으면 판 위의 **카드**가 된다. 링크는 주소를 붙이거나 Safari 에서 끌어다 놓는다 [S4].
- **동작**: 고른 파일에서 `Space` 를 누르면 Quick Look 창이 뜨고, 여러 개를 고르면 화살표로 넘기며 전체 화면 슬라이드쇼도 된다 [S4]. 링크 카드의 미리보기 크기 선택(카드 · 썸네일 · 큰 미리보기) 같은 옵션은 안내서에서 **찾지 못했다**.
- **왜 좋은가**: "자료를 가리키는 것" 과 "자료를 보는 것" 을 같은 자리에서 한다. 열지 않고 훑는 이 흐름은 JayDocs 의 트리 `Space` 훑어보기와 같은 계열이다.

### 4.8 협업 표시
- **무엇**: 툴바의 협업 버튼 → 참가자 목록(이름 옆에 색 막대), 참가자 커서 표시 켜기 [S4].
- **동작**: 이름을 누르면 그 사람이 있는 곳으로 이동. 따라가기를 켜면 그 사람의 화면을 따라가고, 내가 확대 · 이동하면 멈춘다. 오른쪽 위에 재개 · 중지 버튼. 메시지와 FaceTime 도 같은 패널에 있다 [S4]. 변경은 iCloud 에 저장된다.
- **왜 좋은가**: 서로의 위치를 알면 같은 판에서 충돌이 줄어든다.

### 4.9 빈 보드의 첫 경험
- **무엇**: 새 보드는 빈 판이고 툴바의 삽입 도구가 전부다. 이름은 "Untitled" 이고 자동 저장이라 저장 버튼이 없다 [S4].
- **확인 못 함**: 빈 보드에 안내 문구 · 예시가 뜨는지. 사용 설명서에는 없고 화면으로 직접 보지는 못했다.
- **해석**: 설명 없이 비워 두는 쪽을 택한 것으로 보인다. 도구가 곁에 오니 설명이 필요 없다는 설계다.

### 4.10 보드 모양과 다크 모드
- 보기 > "어두운 배경으로 보기"(다크 모드일 때), 점 격자 켜기/끄기 [S4]. 2026-09 에 보드가 다크 모드에 자동으로 맞춰진다고 발표됐다 [S2].
- **왜 좋은가**: 판 위의 색 · 그림이 어두운 배경에서도 읽히도록 앱이 책임진다. (해석) 내용 쪽 색을 앱 테마에 맞춰 뒤집는 접근이다.

### 4.11 내보내기
- PDF 내보내기, 복사본 보내기(받는 쪽이 자기 사본을 얻는다) [S4, S11]. 장면별 PDF 가 있다.

## 5. JayDocs 에 가져올 만한 것

JayDocs 현재 상태 근거: `HANDOFF.md` — 폴더 훑어보기 격자(트리 `Space`, `Tab`), 훑어보기 창 배율 · 크기, 끌어다 놓아 가져오기, 하이브리드 목차, 마크다운 모드 4종, 팔레트 · 단축키 도움말. Mermaid 는 `PreviewPane.tsx` 가 SVG 를 그냥 박아 넣을 뿐이고, 확대 · 이동은 없다(코드 확인).

| 요소 | 우선순위 | 해당 화면 | 웹 PWA 구현 | 주의 |
|---|---|---|---|---|
| **Mermaid 다이어그램 확대 · 이동 · 맞춤 보기** (4.2) | 높음 | 마크다운 미리보기 · 하이브리드의 Mermaid 블록, 훑어보기 창 | 블록 위에 휠 + `Ctrl` 로 확대, `Space` 또는 가운데 버튼 드래그로 이동, "맞춤" 버튼. SVG 에 CSS `transform` 이나 `viewBox` 조절. 라이브러리 없이 가능 | `Ctrl+휠` 은 훑어보기 창에서 이미 배율에 쓴다 — 포커스가 있는 블록만 가로채게 한다. 키는 `Ctrl+Alt+…` 조합으로 하고 글자 키 단독은 금지(CLAUDE.md). 큰 다이어그램은 지금 문서 폭에 잘리거나 작아진다(확인 필요) |
| **파일 · 링크 카드** (4.7) — 문서 링크 위에 마우스를 올리거나 고르면 `DocThumb` 카드가 뜬다 | 높음 | 미리보기 · 하이브리드의 `[링크](문서.md)` , 가져오기 창, 파일 검색(`Ctrl+P`) 옆 | 이미 있는 `DocThumb` / `DocView` 재사용. 호버 카드는 작은 팝오버, `Space` 는 트리의 훑어보기 창과 같은 창을 연다 | 호버 렌더 비용 — 큰 문서는 앞부분만. 읽기 전용이어도 카드를 연다. 파일 검색 옆 미리보기는 HANDOFF 후보에 이미 있다 |
| **저장된 시점 + 뒤로/앞으로** (4.3) — "저장된 위치" | 중간 | 긴 마크다운(목차와 합침), TSV 그리드(필터 · 열 선택 · 스크롤 위치) | 문서마다 "이름 + 위치(커서/스크롤/보기 모드/필터)" 를 `localStorage` 에 저장. 팔레트 명령 + 창 막대의 작은 목록. 뒤로/앞으로는 커서 위치 이력 | 어디까지 저장할지 정해야 한다(커서만? 필터까지?). 장면 방식처럼 **내용이 아닌 위치만** 저장해 파일은 안 바뀐다(포맷 계약 영향 없음). 문서가 바뀌면 위치가 어긋난다 — 제목 기준으로 저장하면 안전 |
| **폴더 격자의 보기 전환 (격자 ↔ 목록) + 정렬/그룹** (4.1) | 중간 | 폴더 훑어보기 격자(트리 `Space`/`Tab`) | 격자 위에 보기 버튼 · 정렬 목록(이름 · 수정 날짜). 팔레트 명령. 이미 있는 카드 배율과 같은 방식으로 저장 | 단축키는 `Cmd+1/2` 대신 `Ctrl+Alt+…` 조합. 정렬은 파일 시스템 날짜를 읽어야 하므로 `Backend.stat` 비용 확인 |
| **즐겨찾기 (보드 → 문서/폴더)** (4.1) | 중간 | 파일 트리 위, 팔레트 · 파일 검색(최근 목록 옆) | `localStorage` 에 경로 목록(작업 공간별). 트리 메뉴 "즐겨찾기에 추가", 팔레트에 상단 고정 | 이름을 바꾸거나 지우면 목록과 어긋난다(`rename` 때 갱신). 별(★) 이모지만 쓰지 말고 글자 병기(HANDOFF 의 이모지 버튼 통일 숙제) |
| **고르면 뜨는 문맥 도구** (4.4) | 중간 | TSV 그리드(열을 고르면 열 도구), 하이브리드의 표 · 이미지 · 코드 블록 | 선택 위에 작은 떠 있는 막대. 그리드는 이미 `＋위/＋끝/＋왼쪽` 에 키가 없다는 숙제가 있어 거기에 맞물린다 | 키보드가 우선(CLAUDE.md). 마우스 전용 막대로 만들지 않는다. 한글 조합 중 선택이 바뀌면 막대가 깜박이지 않게 |
| **맞춤 보기 / 선택에 맞추기** (4.2) | 중간 | 훑어보기 창(폭에 맞추기 · 100%), 폴더 격자, 큰 이미지 미리보기 | 훑어보기 창 머리에 "맞춤" 버튼. 지금은 숫자 클릭이 100% 로 가는 것까지 있다 | 문서는 글자 크기 배율이고 캔버스 줌이 아니다 — 맞춤의 뜻을 "폭 맞춤" 으로 한정 |
| **다크 모드에서 내용도 맞추기** (4.10) | 낮음 | Mermaid · 코드 블록 · 이미지 | Mermaid 는 이미 앱 테마를 따른다(`PreviewPane.tsx` 의 `theme`). 남은 것은 이미지 배경이 흰 PNG 일 때 | 이미지를 색 반전하지 않는다 — 원본 보존 |
| **빈 문서/빈 폴더의 첫 경험** (4.9) | 낮음 | 문서 없을 때 빈 화면 안내 | 이미 있다(HANDOFF §24.7). 문구에 단축키(`Ctrl+Alt+N`, `Ctrl+Shift+P`)를 보여 주는 정도 | Freeform 도 안내를 줄이는 쪽이라 새로 넣을 것은 거의 없다 |
| **단축키 발견 방식** | 낮음 | 팔레트 · F1 | Freeform 은 메뉴바 항목 옆에 키를 적는 macOS 관례에 기댄다(웹 PWA 에는 메뉴바가 없다). JayDocs 는 팔레트 항목 옆에 키를 보이는지 이미 확인 필요 | 이 부분은 다른 Apple 앱 조사와 겹친다 |

**상위 3개 권고**: ① Mermaid 확대 · 이동 · 맞춤, ② 문서 링크 호버 카드 / `Space` 훑어보기(`DocThumb` 재사용), ③ 저장된 시점(목차 + 뒤로/앞으로와 묶기). 근거: ①은 지금 완전히 비어 있고 구현이 작다. ②는 이미 있는 부품 재사용이다. ③은 Freeform 만의 아이디어이고 긴 문서와 큰 표의 길 찾기에 효과가 크다.

## 6. 맞지 않아 가져오지 않을 것

- **무한 캔버스 · 자유 배치**: JayDocs 는 파일 하나 = 순서 있는 문서/표다. 자유 배치는 Markdown/TSV 포맷 계약(DESIGN §2)과 맞지 않는다.
- **도형 라이브러리 · 커넥터 · 도형 합치기 · 정렬 안내선 · 점 격자**: 다이어그램은 Mermaid 텍스트가 맡는다. 손으로 도형을 놓는 편집기는 만들지 않는다. 정렬 안내선은 Mermaid 가 자동 배치하니 필요 없다.
- **Apple Pencil · 손글씨 · 스케치**: 웹 PWA(Windows 사용자 다수)와 맞지 않고 JayDocs 의 대상(텍스트 · 표)도 아니다.
- **협업 표시(커서 · 따라가기 · FaceTime)**: JayDocs 는 서버가 없다(CLAUDE.md). 동시 편집을 하지 않는다. 대신 이미 있는 외부 변경 감지 · 충돌 배너가 같은 문제를 푼다.
- **iCloud 공유 · 링크 초대 · 복사본 보내기**: 서버 없음. 보내기는 파일 자체를 공유하면 된다.
- **Apple Intelligence 쓰기 도구 · 이미지 생성**: 서버 · 외부 호출을 넣지 않는다(DESIGN §20 B9 취지).
- **미니맵**: Freeform 에도 없다. JayDocs 는 이미 훑어보기 패널이 그 역할을 한다.
- **구독(Creator Studio) 모델**: 해당 없음.
