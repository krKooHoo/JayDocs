# 07. Xcode — 문서 · 코드 편집기로서의 UI/UX

조사일 2026-11-22. 빌드 · 디버거 · 시뮬레이터 · 코딩 에이전트 같은 개발 기능은 다루지 않는다. 단축키 목록은 조사 범위가 아니다(발견하게 하는 방식만 본다).

표기: **[공식]** Apple 문서 · WWDC 세션에서 확인. **[2차]** 제3자 정리(Apple 원문 확인 못 함). **[해석]** 내 해석. **확인 못 함** = 찾지 못했다.

---

## 1. 한 줄 요약

Xcode 는 "왼쪽 목록 · 가운데 편집기 · 오른쪽 · 아래 보조 영역" 틀 위에 **모든 목록에서 글자를 치면 거르고(필터), 경로 막대 · 빠른 열기 · 임시 탭으로 '찾아가는 비용'을 줄이는** 편집기다. JayDocs 에는 **경로 막대(폴더 > 파일 > 제목) + 임시(이탤릭) 탭 + 빠른 열기 확장**이 가장 잘 맞는다.

## 2. 개요

- **무엇 / 누구를 위한 것**: Apple 플랫폼 앱 개발용 통합 개발 환경(IDE). 사용자는 Swift · Objective-C 개발자. 문서 편집기가 아니라 코드 편집기이므로 "많은 파일 사이를 빨리 오가며 한 파일의 구조를 빨리 훑는" 쪽에 설계가 몰려 있다. [해석]
- **창 구조** [공식, help.apple.com "About the main window" · "Configure the editor area"]:
  - 위: 툴바(작업 진행 · 창 구성 버튼). 오른쪽 끝의 버튼 3개가 **왼쪽 내비게이터 · 아래 디버그 영역 · 오른쪽 인스펙터**를 각각 켜고 끈다.
  - 왼쪽: 내비게이터 영역 — 위 막대로 종류(프로젝트 · 검색 · 이슈 · 변경 등)를 바꾸고, **맨 아래 필터 막대**로 거른다.
  - 가운데: 탭 막대 → 점프 바(경로 막대) → 편집기.
  - 편집기 오른쪽 위 "편집기 옵션" 메뉴: 미니맵 · 작성자 · 코드 커버리지 · 보이지 않는 글자 · "편집기만 보기".
- **최근 변화**:
  - Xcode 26(2025-06) [공식]: 탭을 원하는 만큼 열 수 있고 **파일에 고정(pin)** 할 수 있다. 탭 동작을 "더 직관적으로" 고쳤고 Safari 처럼 새 탭에 **시작 페이지**가 뜬다(WWDC25 247). 찾기 탐색기에 "여러 단어" 검색 추가.
  - Xcode 27(2026-06 공개, 업데이트 문서에 2026-09 항목도 있어 정식 시점은 확인 못 함) [공식]: **툴바 · 테마 개편**(점프 바에 있던 이동 기록 · 편집기 컨트롤이 툴바로 이동, 툴바는 항목을 더하고 빼고 순서를 바꿀 수 있음, 워크스페이스마다 테마), **Markdown 시각 편집기**(업데이트 문서에 한 줄, WWDC26 258/8013).
  - Markdown 시각 편집기의 동작은 WWDC26 8013(Q&A 패널)에서 다음처럼 나온다: 렌더된 보기가 기본, "Open As → source" 로 원문, **둘 다 편집 가능**, 캔버스 미리보기 버튼으로 나란히 보기. 이 요약은 세션 전사에서 읽은 것이고, 세부(전환 단축키 · 표 편집 여부)는 Apple 문서에서 확인 못 함. 베타 단계라 바뀔 수 있다.

## 3. 디자인 철학

**Apple 이 말한 것**

- WWDC24 "Xcode essentials"(10181) 첫머리: 목표는 개발 주기를 "speed, clarity, and joy" 로 지나가는 것, 코드를 찾는 일이 "문제의 절반"이 되지 않게 돕는 것. [공식]
- WWDC19 "What's New in Xcode 11"(401): 어시스턴트 · 작성자 모드를 툴바에서 **각 편집기 창 안으로** 옮겼다. 파일 종류마다 작업 흐름이 아주 다르기 때문이라고 설명한다. 편집기는 언제든 가로 · 세로로 나눌 수 있고 나눈 편집기마다 상태가 따로 있다. [공식]
- WWDC26 "What's new in Xcode 27"(258): 입력 중에 뜨는 예측 이슈는 theme 에 섞이는 은은한 모양으로, 빌드 뒤에야 정식 경고 · 오류 강도로 보인다. 이유는 "minimize distractions while typing" 취지. [공식, 전사 요약]
- WWDC24: Xcode 의 많은 메뉴가 글자를 치면 거른다(점프 바 · 내비게이터 필터 · 팝업). [공식]

**해석** (Apple 이 직접 한 말이 아니다)

1. **"찾기 → 이동"을 한 동작으로**: 경로 막대의 각 단계가 메뉴이고, 그 메뉴는 치면 걸러진다. 빠른 열기는 파일과 심볼을 한 입력창에서 찾는다. 계층을 따라 내려가는 길(경로 막대)과 이름으로 바로 가는 길(빠른 열기)을 둘 다 준다.
2. **관심의 정도를 탭이 반영**: 지나가기만 한 파일은 임시 탭, 만지면 영구 탭. 사용자가 "열겠다"고 선언하지 않아도 정리된다.
3. **보조 영역은 항상 접을 수 있다**: 툴바 버튼 3개로 켜고 끄고 "편집기만 보기"까지 있다. 본문에 집중하는 방향.
4. **한 창 안의 기능은 창마다 설정**(편집기 옵션 메뉴): JayDocs 가 창 막대에 둔 목차 · 보기 모드 버튼과 같은 발상이다.

## 4. 핵심 UI/UX 요소

### 4.1 편집기 탭과 임시(이탤릭) 탭

- **무엇**: 탭 두 종류. 이탤릭 제목은 임시(implicit/view) 탭, 보통 글씨는 영구 탭. [공식, WWDC24 5:47]
- **어떻게**: 내비게이터에서 파일을 한 번 누르면 이탤릭 탭에 열리고, 다른 파일을 누르면 **그 탭의 내용이 바뀐다**. 탭을 더블클릭하거나 "Keep Open" 을 고르면 영구가 된다(WWDC24). 내비게이터에서 더블클릭하면 영구 탭으로 열린다(개발자 포럼 스레드 732699, Xcode 15 기준 — 포럼 글이라 Apple 문서는 아님). 편집을 시작해도 영구가 된다는 설명은 블로그 수준이라 확인 못 함.
- **설정**: 설정 > Navigation 에 "Double-click Navigation" 드롭다운(탭 / 클릭과 같게 / 별도 창 / 별도 창의 탭) [포럼, Xcode 15 기준, 최신 판 확인 못 함].
- **탭 막대 부속**: 앞으로 · 뒤로 버튼(길게 누르면 기록 목록), 왼쪽 "관련 파일" 메뉴(최근 파일 · 서브클래스 · 호출자 같은 관계), 탭의 닫기 버튼을 Option 으로 누르면 다른 탭 모두 닫기(WWDC24). 탭 막대는 View > Show/Hide Tab Bar 로 숨긴다. 탭을 끌어 다른 탭 막대나 바탕화면으로 빼면 별도 창이 된다(help "About the main window").
- **Xcode 26**: 고정(pin)과 시작 페이지. 닫기 · 재배열 세부는 WWDC25 전사에 없다.
- **왜 좋은가**: 파일을 훑는 동안 탭이 쌓이지 않고, 만진 것만 남는다.

### 4.2 점프 바(경로 막대)

- **무엇**: 탭 막대 바로 아래, 현재 파일의 경로(폴더 > 파일 > 심볼)를 보이는 줄. [공식, WWDC24 7:41]
- **어떻게**: 각 단계가 눌리는 메뉴이며 같은 단계의 이웃(같은 폴더의 파일 · 같은 파일의 심볼)을 목록으로 보인다. 열린 메뉴에서 글자를 치면 위쪽에 필터 칸이 생겨 거른다. 맨 오른쪽 단계가 파일의 심볼 목록이고, `MARK` 주석은 이 목록에서 구역 제목이 된다. 점프 바에서 프로젝트 내비게이터의 같은 항목으로 가는 명령도 있다(WWDC24). WWDC26 패널은 "점프 바 메뉴 필터 + 빠른 열기 + 내비게이터에서 보기" 조합을 즐겨 쓴다고 말한다.
- **Xcode 27**: 점프 바에 있던 이동 기록 · 편집기 컨트롤이 툴바로 올라갔다(WWDC26 258). 경로 단계 자체의 변화는 확인 못 함.
- **왜 좋은가**: "지금 어디인가"를 늘 보여 주면서, 같은 자리에서 이웃으로 옮겨 가게 한다. 길 안내와 이동이 한 요소다.

### 4.3 편집기 분할과 보조 편집기

- **무엇**: 한 창 안에서 편집기를 여럿 두는 것. [공식, help "Configure the editor area", WWDC19]
- **어떻게**: 편집기 오른쪽 위의 "편집기 추가" 버튼 — 그냥 누르면 오른쪽에, Option 을 누르면 아래에 더해진다. 닫기는 왼쪽 위 X, 한 편집기를 잠시 창 전체로 키우는 이중 화살표 버튼이 있다(WWDC19 "Focus"). 파일을 어느 편집기에 열지는 Option+Shift 클릭으로 고르는 칸을 쓰거나, 빠른 열기에서 Option+Return 으로 새 분할에 연다(WWDC24 11:22). 보조 편집기(Assistant)는 현재 파일과 관련된 파일(헤더 ↔ 구현 등)을 옆에 연다.
- **Xcode 27**: 툴바 오른쪽 위 컨트롤로 탭 · 편집기 창을 더하고, 3가지 모드(캔버스 미리보기 · 관련 내용 보조 편집기 · 변경 검토)를 고른다. 에이전트 대화도 편집기 창이라 탭 · 분할에 섞인다(WWDC26 258).
- **왜 좋은가**: 분할이 "탭 안의 상태"가 아니라 편집기 하나하나의 독립 상태라 확대 · 옵션을 편집기별로 둘 수 있다.

### 4.4 미니맵

- **무엇**: 소스 편집기 오른쪽의 축소 보기. 편집기 옵션 메뉴 > Minimap 으로 켠다. [공식, help.apple.com · WWDC19 401]
- **어떻게**: 코드 윤곽과 구문 색을 축소해 보이고, 같은 줄에 변경 표시 · 중단점이 얹힌다. 위에 마우스를 올리면 무엇인지 미리 보인다. `MARK` 는 편집기와 같은 모양으로(구분선 포함) 미니맵에 나온다. 찾기를 쓰면 일치 위치 전부가 보이고 나머지는 흐려진다(WWDC19). Xcode 14 릴리스 노트의 "스크롤 중 코드 구조 표시"는 검색 결과 요약으로만 확인했다.
- **Xcode 26 · 27 변화**: 확인 못 함(26 / 27 소개 문서 · 세션에 미니맵 언급 없음).
- **왜 좋은가**: 스크롤하지 않고 긴 문서에서 "지금 위치 · 구역 · 찾은 곳"을 한눈에 본다.

### 4.5 빠른 열기(Open Quickly)

- **무엇**: 파일 · 심볼 이름으로 어디서든 바로 이동하는 입력창. [공식, WWDC24 11:22]
- **어떻게**: 이름 일부를 치면 코드 자동완성식 규칙으로 맞춘다(고유한 낱말 하나만 쳐도 됨). 쿼리에 `/` 가 있으면 경로로 맞추고, 끝에 `:줄번호` 를 붙이면 그 줄로 간다. Option+Return 은 새 분할에 열고, 연 뒤 "내비게이터에서 보기"를 이어 쓰는 흐름을 WWDC26 패널이 추천한다.
- **왜 좋은가**: 목록 · 경로를 몰라도 되고, 파일 · 심볼 · 줄까지 한 입력창에 모인다.

### 4.6 내비게이터의 필터 칸

- **무엇**: 내비게이터 맨 아래 필터 막대. [공식, WWDC24 1:45 · 3:05, help "About the navigator area"]
- **어떻게**: 치면 목록이 걸러지고, 입력과 맞는 추가 필터(예: 타깃 이름)가 있으면 입력창 위에 메뉴가 뜬다. 오른쪽 끝 아이콘은 **깃 상태(바뀐 파일)만** 보기. 찾기 탐색기는 범위 메뉴 · 결과 선택 뒤 Delete 로 "이번 검색에서만 숨기기" · 필터 칸으로 추가로 좁히기를 준다. 화살표를 Cmd 로 누르면 형제 항목을 모두 접는다(모든 개요 목록에서).
- **왜 좋은가**: 큰 폴더에서 "트리를 펼쳐 찾기"가 필요 없다. "바뀐 것만" 같은 상태 필터가 같은 자리에 있다.

### 4.7 문서 항목(MARK) 기반 구조 탐색

- **무엇**: 코드 안의 `MARK:` 주석이 구역 제목이 되어 점프 바 심볼 목록과 미니맵에 나온다. [공식, WWDC24 10:56, WWDC19]
- **왜 좋은가**: 작성자가 구조를 직접 선언하면 도구가 알아서 구조 탐색에 쓴다. [해석] JayDocs 의 마크다운은 제목 자체가 이 역할을 한다(이미 목차에 쓴다).

### 4.8 코드 접기

- Apple 문서에서 현재 버전의 접기 UI(리본 · 메뉴 위치)를 **확인 못 함**. 오래된 포럼 글은 설정이 버전마다 옮겨 다녔다고 한다. WWDC26 패널 요약([2차])은 접기보다 심볼 메뉴(Control+6)로 탐색하라고 권하고, 자주 접어야 하면 파일을 나누라고 한다. 이 항목은 Xcode 에서 가져올 근거가 약하다.

### 4.9 영역 숨기기 · 집중

- 툴바 오른쪽 버튼 3개가 내비게이터 · 디버그 · 인스펙터를 토글한다(help). 편집기 옵션 메뉴의 "Show Editor Only" 가 편집기 옵션 줄까지 숨긴다. 어느 영역이든 자동으로 열렸다 닫히기보다 "사용자가 켠 상태"가 유지된다. [해석] 단축키를 어떻게 알리는지: 메뉴 항목 옆에 키가 같이 표시되고(메뉴 중심 발견), 점프 바 · 팝업 메뉴는 치면 거른다. 키보드 설정은 검색 가능한 표다(WWDC26 패널 요약, 2차).

## 5. JayDocs 에 가져올 만한 것

JayDocs 지금 UI(HANDOFF · SHORTCUTS 기준): 왼쪽 파일 트리(트리에서 `Space` 훑어보기), flexlayout 탭 · 분할(`Ctrl+\` 오른쪽만), `Ctrl+P` 파일 이름 검색, 마크다운 보기 모드 4종, 하이브리드 모드의 목차(`Ctrl+Alt+T`, 제목은 `lib/md/outline.ts`), 훑어보기 패널(`Ctrl+Alt+M`), 창 막대. **경로 막대 · 임시 탭 · 이동 기록 · 트리 필터는 없다**(소스에서 관련 코드를 찾지 못함. 트리 이름 필터는 HANDOFF 에 후보로만 적혀 있음).

| 요소 | 우선순위 | JayDocs 에서 | 웹 PWA 구현 | 주의 |
|---|---|---|---|---|
| **경로 막대** (폴더 › 파일 › 제목, 각 단계 메뉴 + 치면 거름) | 높음 | 문서 창(편집기 · 그리드) 위 한 줄 — 탭과 편집기 사이 | 창마다 `div` 한 줄. 폴더 · 파일 단계는 스토어의 트리 데이터로 형제 목록, 제목 단계는 `outline.ts` 가 만든 목록. 메뉴는 기존 팔레트의 걸러 고르기 컴포넌트를 재사용. TSV 는 마지막 단계를 "열" 목록(또는 `_Field` 블록)으로 | 좁은 창에서는 앞 단계를 `…` 로 접는다. `@별칭` 폴더의 맨 앞 단계는 별칭 이름. 키보드로 열 명령 필요(팔레트 + 겹치지 않는 키, 단축키 표 먼저 확인). 훑어보기 · 목차와 역할이 겹치므로 목차를 대체하지 않는다 |
| **임시(이탤릭) 탭** | 높음 | 파일 트리 클릭 · 탭 막대 | flexlayout 은 탭 이름 · 클래스를 지정할 수 있다. 임시 탭 하나만 유지: 트리에서 열면 그 탭을 교체, 편집 · 더블클릭 · 팔레트 "탭 유지" 로 영구화, CSS 로 이탤릭 | 수강생 제출물 폴더를 훑을 때 효과가 가장 큼. 트리 클릭이 현재 항상 새 탭을 여는지 코드에서 확인하지 못했다 — 먼저 확인. `Space` 훑어보기와 목적이 겹치므로 "훑기는 Space, 열기는 임시 탭"으로 선을 긋는다. 레이아웃 복원 때 임시 상태 저장 여부 결정 필요. 끄는 설정 하나 필요(Xcode 도 설정이 있다) |
| **빠른 열기 확장** (`Ctrl+P`): `:줄`, 경로 `/` 맞춤, 제목(심볼) 검색, 분할로 열기 키 | 높음 | 파일 검색(`Ctrl+P`) | 기존 입력창에 접두 규칙 추가: `이름:12` → 그 줄, `#` 뒤는 열린 문서의 제목 목록(`outline.ts`), `Shift+Enter`(또는 Alt+Enter)는 오른쪽 분할로 열기 | 접두 규칙은 입력창 안내 문구로 알린다(발견성). 글자 키 단독 단축키 금지 규칙은 입력창 안이라 해당 없음 |
| **이동 기록 앞으로 · 뒤로** (탭 막대의 ◀ ▶, 길게 누르면 기록) | 중간 | 창 막대 · 팔레트 | 창별(또는 전역) 방문 스택. 제목으로 점프 · 다른 파일 열기마다 push | 브라우저의 Alt+←/→ 와 겹친다 — Edge 설치 앱에서 가로챌 수 있는지 확인하고 안 되면 Ctrl+Alt+←/→ 같은 다른 조합. 제목 점프(목차 · 경로 막대)까지 기록에 넣어야 가치가 있다 |
| **트리 필터 칸** (+ "수정한 파일만" 같은 상태 필터) | 중간 | 파일 트리 위쪽 🔍 줄 옆 또는 맨 아래 | 입력에 따라 트리 항목을 거르고 일치 항목의 상위 폴더는 펼쳐 둔다. 상태 필터는 저장 안 한 문서(dirty 집합 구독이 이미 있다) | HANDOFF 후보 "트리 이름 필터"와 같다. `Ctrl+P` 와 역할이 겹치니 "폴더 구조 속에서 보며 거르기"로 차별화. 트리 단독 글자 키 단축키는 쓰지 않는다 |
| **관련 파일** (현재 표의 `_Field` · `_Calc`, 마크다운이 `tsv-view` 로 가리키는 표) | 중간 | 창 막대 메뉴 또는 경로 막대 옆 | 같은 폴더의 `X_Field.tsv` · `X_Calc.tsv` 를 이름 규칙으로 찾고, md 는 `tsv-view` 의 `file:` 값을 읽어 목록. 선택하면 오른쪽 분할로 연다 | [해석] Xcode 의 보조 편집기 · 관련 파일에서 얻은 발상. JayDocs 의 포맷 계약(DESIGN §2)과 Calc 규칙이 이미 있어 재료는 있다 |
| **편집기 임시 확대 · 편집기만 보기** | 중간 | 창 막대 · 팔레트 | flexlayout 의 탭 묶음 최대화 사용(있으면), 트리 · 목차 · 훑어보기 패널을 한 번에 숨기는 명령 하나 | 기존 `Ctrl+B`(트리), 목차, 패널 토글을 하나로 묶는 것이지 새 기능이 아니다. 복귀 시 이전 상태 복원 필요 |
| **분할 아래쪽** (Option 으로 아래) | 중간 | 분할 명령 | flexlayout 은 행 · 열 분할을 지원. 기존 `Ctrl+\` 옆에 "아래에 분할" 명령 추가 | 분할을 되돌리는 쉬운 길(탭 닫기)이 있어야 한다. 표 비교(위 · 아래)에 쓸모가 있다 |
| **전체 검색**(찾기 탐색기식: 범위 · 결과 숨기기 · 추가 좁히기) | 중간 | 트리 옆 새 패널 — HANDOFF 후보 `Ctrl+Alt+F` | 열려 있는 폴더 파일을 읽어 검색. 결과 목록에서 항목을 지워 "이번 검색에서만 숨기기" | 큰 폴더는 읽는 비용이 크다. 스토어 캐시 · 청크 읽기 필요. 이 항목은 Xcode 가 아니어도 이미 후보였다 |
| **검색 결과 표시가 있는 훑어보기 패널** (미니맵의 찾기 일치 · 제목 표시) | 낮음 | 훑어보기 패널(`Ctrl+Alt+M`) | `Ctrl+F` 일치 위치와 제목 위치를 패널 위에 가는 선으로 얹는다 | 패널이 이미 축소 렌더 방식이라 선 하나 얹는 정도. 큰 문서의 자동 갱신 멈춤 정책과 충돌 안 하는지 확인 |
| **탭 고정 · 다른 탭 모두 닫기** | 낮음 | 탭 메뉴 | 고정 탭은 닫기 · 교체 대상에서 제외하고 앞쪽에 몰기. "다른 탭 닫기"는 저장 확인 흐름(`confirmCloseTab`) 재사용 | 임시 탭을 넣은 뒤에 필요가 드러나면 한다 |
| **여러 영역 켜기 · 끄기의 한 곳 묶음** (툴바 버튼 3개) | 낮음 | 상단 막대 | 트리 · 목차 · 훑어보기 패널 토글을 같은 자리에 모아 켜짐 상태 표시 | 지금은 `Ctrl+B` · 창 막대 · 팔레트에 흩어져 있다. 접근성 · 상태 표시만 개선 |
| **워크스페이스별 테마 색**(폴더마다 강조색) | 낮음 | 상단 · 시작 화면 | 작업 공간 id 별 localStorage 에 강조색 하나 | 설치한 앱 창이 여러 개일 때만 쓸모. Xcode 27 의 방식은 가져올 수 있는 것은 "구분용 색" 정도 |
| **섹션 접기**(제목 기준) | 낮음 | 편집기(소스 · 하이브리드) | CM6 `foldGutter` + 마크다운 제목 접기 | Xcode 가 근거는 아니다(접기 UI 확인 못 함, 패널은 심볼 메뉴를 권함). 이미 HANDOFF 후보 "절 접기" |

**발견성(단축키를 보여 주는 방식) 참고** [해석]: Xcode 는 메뉴 항목 옆에 키를 같이 쓰고, 팝업 · 점프 바는 치면 거르게 한다. JayDocs 는 이미 F1 도움말(검색) · 팔레트가 있어 같은 목적을 한다. 새로 만드는 경로 막대 메뉴 · 트리 필터에 "여기서 치면 거른다"를 칸 안 안내 문구로 보이는 정도면 된다.

**먼저 하나만 고른다면**: 경로 막대(높음 1번). 목차 · 훑어보기 · 빠른 열기가 이미 "위치 알기 · 이동"을 나눠 갖고 있어, 경로 막대는 그것들을 한 줄로 묶는 접착제 역할을 한다. 임시 탭은 트리 클릭 동작 확인 뒤에.

## 6. 맞지 않아 가져오지 않을 것과 이유

| 항목 | 이유 |
|---|---|
| 디버그 영역 · 인스펙터 · 시뮬레이터 · 빌드 활동 표시 | 개발 기능이다. JayDocs 에는 해당 개념이 없다 |
| 코딩 에이전트 · 대화 · 아티팩트 창, 코딩 도구 팝오버 | 서버 없는 로컬 편집기라는 전제와 맞지 않는다 |
| 작성자 · 코드 커버리지 · 변경 막대 · 변경 검토 모드 | git 기능은 2026-10-31 전환에서 뺐다(HANDOFF) |
| SwiftUI 캔버스 · 플레이그라운드 | Swift 전용 |
| 툴바 항목 사용자 지정 · 테마 슬라이더(배경 그라데이션 포함) | 1인용 도구에 설정 면이 늘고, 다크/라이트 전환 하나로 충분하다 |
| 설정의 "더블클릭하면 별도 창 / 별도 창의 탭" | 설치한 PWA 의 창 여러 개는 상태(레이아웃 · 저장 충돌)를 나누기 어렵다. 임시 탭 on/off 하나만 가져온다 |
| Vim · Emacs 키 모드 | 대상 사용자(문서 작성)와 맞지 않고 단축키 유지 비용이 크다 |
| 내비게이터 종류 여러 개(심볼 · 이슈 · 테스트 · 보고서) | 문서 편집기에는 프로젝트 · 검색(+ 목차)이면 충분하다 |
| 코드 접기를 Xcode 따라 하기 | Apple 쪽 근거가 약하다(확인 못 함). 접기는 HANDOFF 의 "절 접기" 후보로 따로 판단 |
| 예측형 이슈를 은은하게 보이는 방식(Xcode 27) | 원칙 자체("입력 중 방해 줄이기")는 좋지만 JayDocs 의 검증(키 중복 등)은 즉시 보여 주는 것이 계약에 가깝다. 바꿀 필요가 있는지는 확인 못 함 |
